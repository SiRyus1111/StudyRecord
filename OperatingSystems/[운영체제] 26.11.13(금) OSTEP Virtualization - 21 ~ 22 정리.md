## 0. 서론

지금까지 이 정도를 했지?

- 가상 메모리가 뭔지
  - 각 프로세스에서 가상 주소를 가지고 물리 메모리를 독점하고 있다는 환상을 심어주는 것
- Base / Bound를 이용한 가상 메모리가 뭔지
  - `Base + virtual_address` / `virtual_address < Bound` 검사
- 세그먼테이션이 뭔지
  - 세그먼트라는 프로세스의 소단위로 Base / Bound를 적용한 것
- 페이징이 뭔지
  - 외부 단편화를 막기 위해 가상 페이지와 물리 프레임의 크기를 같게 맞추고
  페이지를 프레임에 할당하는 가상 메모리 기법
- 페이지 테이블이 뭔지
  - 각 페이지의 정보(프레임 번호 / 상태 비트 등)를 담고있는 테이블
    - 가상 메모리 주소 -> 가상 페이지 번호 + 오프셋
    - 가상 페이지 번호 -> 물리 프레임 번호
    - 물리 프레임 번호 -> 중간 물리 주소
    - 중간 물리 주소 + 오프셋 -> 최종 물리 주소
- TLB가 뭔지
  - 페이지 테이블의 캐시(히트 / 미스 있음)
- 페이지 테이블의 크기를 줄이기 위한 기법
  - 페이지 크기 키우기
  - 페이징에 세그먼테이션 결합하기
  - 다단계 페이지 테이블 사용하기
  
와.. 많이 하긴 했네..

이번에 할 것은
쉽게 말해 스와핑,
즉 메모리의 페이지를 디스크로 빼놨다가 필요할 때 다시 메모리에 적재하는 그런 동작에 대해 배울거야.

페이지 테이블의 존재 비트 기억나?
그거야 그거.
해당 페이지가 메모리에 존재하나를 나타내는 비트였지.
메모리에 존재하면 1, 디스크에 있으면 0.

이제 본격적으로 스와핑을 배워보자.

## 1. 스와핑

일단 앞에서 스와핑에 대해 좀 설명했지?

한번 더 정리하자.

스와핑이란,

> 프로세스에게 충분히 큰 메모리 공간을 사용하고 있다는 환상을 주기 위해
> 일부 페이지를 더 낮은 메모리 게층이 하드 디스크에 저장하고
> 필요할 때 다시 메모리에 적재하는 것

이라고 할 수 있어.

왜 충분히 큰 메모리 공간을 사용하고 있다는 환상을 줘야하냐면,
최근의 프로그램들은 전부 메모리에 올라와있으면
메모리 공간이 부족한 경우가 왕왕 나오거든.
그래서 '충분히 큰 메모리 공간을 사용하고 있다는 환상'이라는 키워드를 쓴거야.

스와핑에 대한 키워드 몇 개만 뽑아보자면

- 큰 메모리 공간이 필요
- 일부 페이지를 하드 디스크에 저장
- 필요할 때 다시 메모리에 적재

라고 할 수 있어.

눈치챘겠지만,
이렇게 하면
물리 메모리의 크기를 초과하는 프로그램을 가상 메모리에서 실행할 수 있어.

OS는 디스크에 페이지들을 저장할 수 있는 공간,
즉 스왑 공간(swap space)를 확보해.

그리고 스왑 공간에는 페이지 단위로 입 / 출력이 일어나지.

OS는 스왑 공간에 있는 모든 페이지들의 디스크 주소를 기억해야하고.
많은 시스템에서 해당 페이지의 디스크 상에서의 위치를
페이지 테이블에 저장해.

### 1-1. 페이지 폴트와 페이지 폴트의 처리

그리고 페이지 테이블 엔트리의 존재 비트를 사용해서
메모리에 해당 페이지가 존재하는지 확인할 수 있어.

그리고 사용하려는 페이지가 물리 메모리에 존재하지 않은 것을
즉 사용하려는 페이지의 페이지 테이블 엔트리의 존재 비트가 0인 것을
페이지 폴트라고 해.

그리고 페이지 폴트가 발생하면
말그대로 폴트, 예외이기 때문에
OS의 페이지 폴트 핸들러가 호출돼.

페이지 폴트 핸들러는
페이지 테이블 엔트리를 보고
해당 페이지를 디스크에서 메모리로 스왑해와.

그리고 해당 페이지 테이블 엔트리의 PFN를 할당된 프레임으로 갱신하지.

이 작업까지 하면 페이지 폴트를 발생시킨 명령어가 재실행돼.
(폴트니까.)

그리고 이런 디스크 I/O 작업 중에는 해당 프로세스가 블로킹돼.

만약 이미 해당 프로세스에 할당된 프레임이 다 차있다면,
(메모리에 더이상 페이지를 적재할 프레임이 없다면)
기존에 있던 페이지를 쫓아내고 해당 페이지가 들어가는 페이지 교체가 발생해.

(물론 실제로는 더이상 페이지를 적재할 프레임이 없을 때 교체가 발생하지 않고
따로 지정된 빈 프레임 수의 최솟값이면 페이지를 교체함)
(여기서는 그냥 쉽게 빈 프레임이 없다고 설명할게.)

결국,
페이지에 접근하는건 이렇게 네 가지 경우로 나눌 수 있겠어.
(TLB 히트 / 미스는 제외. 어쨌든 페이지 테이블 엔트리에 접근한 시점부터 시작이야.)

1. 페이지가 존재하며 유효한 경우
    - 그냥 바로 해당 페이지에 접근
2. 페이지가 유효하지만 존재하지 않고 빈 프레임이 남아있는 경우
    - 페이지 폴트 -> 해당 페이지를 빈 프레임으로 스왑
3. 페이지가 유효하지만 존재하지 않고 빈 프레임이 없는 경우
    - 페이지 폴트 -> 해당 페이지와 이미 메모리에 올라와있는 페이지 중 하나를 교체
4. 페이지가 유효하지 않은 경우
    - 세그폴트
    
이렇게 볼 수 있어.

### 요약

1. OS는 프로세스에 충분히 큰 메모리 공간을 제공하기 위해
특정 페이지를 디스크에 스왑하고
필요할 때 해당 페이지를 메모리로 스왑하는
스와핑을 한다.
   - OS는 이를 위해 사전에 디스크에 스왑 공간을 만들어놓는다.
   - 스왑 공간에는 페이지 단위로 입 / 출력이 일어난다.
   - OS는 디스크에 있는 페이지의 주소를 페이지 테이블의 PFN 필드에 임시로 저장해놓는다.
2. 만약 필요한 페이지의 존재 비트가 0일 경우(해당 페이지가 메모리에 존재하지 않을 경우)
OS는 페이지 폴트를 발생시키고
페이지 폴트 핸들러를 호출해서
디스크에 있을 해당 페이지를 메모리에 다시 올려놓는다.
   - 폴트이기 때문에 해당 폴트를 처리하면 현재 명령어부터 다시 실행한다.
3. 페이지 폴트가 발생했는데 이미 해당 프로세스에 할당된 프레임이 전부 사용중일경우,
해당 페이지와 기존의 특정 페이지를 교체하는
페이지 교체가 일어난다.

## 2. 페이지 교체 정책

일단 편하게 페이지 교체 정책을 보기 위한 관점을 한번 살펴보자.

OS는 딱 특정 페이지들만 메모리에 올려놓고
나머지 페이지는 디스크에 스왑해놓지?

그래서 메모리는 페이지를 가져다놓기 위한 캐시 역할을 해.

이게 중요한 관점이야.

결국 효율적으로 페이지 교체를 하려면
메인 메모리의 캐시 미스(비유적 표현)가 최대한 적게 발생해야한다는거야.

즉, 디스크로부터 페이지를 가져오는 횟수를 최소로 만드는거지.

### 2-1. 페이지 교체 정책들

#### 2-1-1. 가장 좋지만 구현하기 매우 어려운 정책 - 최적 교체 정책

최적 교체 정책은
가장 나중에 접근될(미래 관점) 페이지를 교체하는 정책이야.

이게 솔직히 효율은 제일 쩔지.

가장 나중에 접근될 페이지를 교체하는 정책이니,
먼저 접근될 페이지들에는 캐시 미스가 발생하지 않아서
최대한 메인 메모리의 캐시 미스를 막을 수 있어.

하지만 이걸 완벽히 하려면
사실상 미래를 예측해야해.

어떻게 가장 나중에 교체될 페이지를 알 수 있는지가 문제지.
그래서 사실상 범용 OS에서는 이 정책은 구현 불가능해.

#### 2-1-2. 가장 간단한 정책 - FIFO(선입선출) 정책

FIFO 정책은
이름처럼 큐마냥 가장 먼저 메모리에 올라온 페이지를 먼저 교체하는 방식이야.

장점은 매우 구현이 간단하다는 점이고,
단점은 다른 페이지 교체 정책에 비해서는 효율이 그닥이라는 점이야.

다음 정책을 이어서 보자.

#### 2-1-3. 간단한 정책 - 무작위 선택 정책

무작위 선택 정책은
이름처럼 내보낼 페이지를 완전히 무작위로 선택하는 정책이야.
소위말해 운빨 정책.

운이 매우 좋으면 최적 교체 정책만큼의 효율을 내지만,
운이 더럽게 없으면 최대의 캐시 미스를 발생시키지.

근데 이게 FIFO보다는 아주 조금 더 좋긴 해.
그래도 운빨이라는건 변하지 않지만.

#### 2-1-4. 제일 보편적인 정책 - LRU(Least Recently Used) 정책

이건 최적 교체 정책의 반대 시점의 정책이라고 보면 돼.

최적 교체 정책은
가장 나중에 접근**될**(미래) 페이지를 내보내는 정책이고,

LRU 정책은
가장 이전에 접근**된**(과거) 페이지를 내보내는 정책이야.

논리는 딱 이래.
'가장 이전에 접근된 페이지는 앞으로도 접근될 가능성이 낮지 않을까?'

장점은 시간 지역성을 잘 활용해서 높은 성능을 보인다는 점이라고 할 수 있고,
단점은 모든 페이지의 접근 시점을 기록해야하기 때문에 하드웨어 오버헤드가 크다는 점이라고 할 수 있어.

사실상 보통은 이 정책을 사용하지.

근데 이 정책은 앞서 말했듯이 하드웨어 오버헤드가 커서,
보통 이 정책을 근사한 알고리즘을 사용해.

#### 2-1-5. 번외 - LFU(Least Frequently Used) 정책

이것도 LRU랑 비슷하게 과거의 데이터를 기반으로 결정을 내리는 정책이라고 보면 돼.

다른 점은, 과거에 가장 적은 **빈도**로 사용됐던 페이지를 내보내는 정책이라는 점이지.

이것도 나름 유용한 정책이야.
하지만 LRU에는 밀리지.

장점으로는 오랜 시간 인기가 많았던 페이지를 잘 보존한다는 점이라고 할 수 있고,
단점으로는 과거에 많이 쓰였지만 현재에는 쓰이지 않는 페이지가 메모리를 계속 점유할 수 있다는 점이야.

그리고 추가적인 단점으로도 이것도 모든 페이지의 사용 빈도를 기록해야한다는 점이 있겠네.

### 요약

1. 스와핑에서의 메모리는
사실상 일부의 페이지만 올라오고,
페이지 교체 때문에 페이지가 디스크로 밀려나는 특성이 있기 때문에
사실상 디스크의 캐시로 볼 수 있다.
그 점에서 착안하여, 페이지 교체 알고리즘의 효율성은 캐시 히트율로 비유할 수 있다.
즉, 더 적은 스와핑이 발생하게 하는 것이 좋다.
2. 페이지 교체 정책으로는,
    - 최적 교체 정책 : 가장 마지막으로 접근될 페이지를 먼저 교체
      - 장점 : 제일 효율적이다.
      - 단점 : 미래를 예측해야 하기 때문에 구현이 극도로 어렵다.
    - FIFO 정책 : 가장 먼저 메모리에 스왑된 페이지를 먼저 교체
      - 장점 : 구현이 간단하다.
      - 단점 : 그다지 효율적이지 않다.
    - 무작위 선택 정책 : 아무 페이지나 먼저 교체
      - 장점 : 구현이 간단하다.
      - 단점 : 그다지 효율적이지 않다.
    - LRU 정책 : 가장 이전에 접근된 페이지를 먼저 교체(제일 보편적으로 사용)
      - 장점 : 나름 효율적이다.(시간적 지역성 활용)
      - 단점 : 구현이 어려운 편이다.
        - 그래서 보통 LRU를 근사한 알고리즘을 사용한다.(Clock 등)
    - LFU 정책 : 가장 적은 빈도로 접근됐던 페이지를 먼저 교체
      - 장점 : 나름 효율적이다.(오랜 시간 인기가 많았던 페이지를 잘 보존함)
      - 단점 : 구현이 어렵고, 현재는 인기가 없는 페이지가 과거에 인기가 많았다면 계속 메모리를 점유할 수 있다.
    이 정도가 있다.

## 3. 스와핑 여담

솔직히 이 내용들은 생각보다 중요하지 않을 수 있어.
요즘에는 메모리 접근 시간과 디스크 접근 시간의 차이가 점차 증가하고 있기 때문에,
디스크에 페이징하는 비용이 점점 비싸지고 있어.

디스크에 페이징하는 비용이 점점 비싸지고 있기 때문에,
빈번한 스와핑을 감당할 수가 없어.

솔직히 스와핑 때문에 컴퓨터가 느려진다면
그냥 메모리를 더 사는게 낫지 않을까..
(요즘 메모리 가격이 무섭긴 하지만ㅋㅋ)

## 4. 메모리 가상화 요약

1. 가상 메모리
    - 투명성 / 효율성 / 보호를 목적으로
    프로세스가 물리 주소를 쓰지 않고 연속된 메모리에 접근하는 것 마냥 가상 주소를 쓰는 것.
2. Base / Bound
    - 제일 기본적인 가상 메모리 기법.
    - `virtual_address < Bound` -> `physical_address = Base + virtual_address`
    - 프로세스 하나를 통짜로 Base / Bound로 관리하기 때문에
    사용하지 않는 메모리 영역을 메모리에 올려놓게 됨.
3. 세그먼테이션
    - 기본적인 가상 메모리 기법.
    - 세그먼트 단위로 프로세스를 분할해서 각각의 Base / Bound를 두는 가상 메모리 기법.
    - 세그먼트의 판별은 상위 N비트로.
    - 빈 메모리가 파편화되는 외부 단편화 문제가 발생함.
4. 페이징
    - 가장 일반적으로 사용하는 가상 메모리 기법.
    - 프로세스를 같은 크기의 페이지들로 분할한 후,
    각 페이지를 페이지와 같은 크기인 물리 메모리의 프레임에 할당함으로써
    외부 단편화를 없애는 가상 메모리 기법.
    - 페이지 테이블을 매개로
      - 가상 주소 -> 페이지 번호 + 오프셋
      - 페이지 번호 -> 프레임 번호
      - 프레임 번호 -> 중간 물리 주소
      - 중간 물리 주소 + 오프셋 -> 최종 물리 주소
      를 수행한다.
    - 단일 페이지 테이블은 크기가 너무 커질 수 있어서,
    일반적으로는 
    필요하지 않은 페이지들에 대한 테이블을 할당하지 않는
    다단계 페이지 테이블을 사용한다.
5. TLB
    - 페이지 테이블이 메모리에 저장되어있기 때문에,
    메모리 접근 시 시간을 줄이기 위한
    페이지 테이블의 캐시.
    - TLB 히트시 그대로 페이지 테이블 엔트리를 사용하고,
    미스시 사양에 따라 
    하드웨어(CPU) / 소프트웨어(예외)적으로 메모리에서 페이지 테이블 엔트리를 가져온다.
6. 스와핑
    - 더 큰 메모리 공간이 필요함에 따라
    일부 페이지를 디스크에 스왑하고,
    필요할 때 다시 물리 메모리에 스왑하는 기법.
    - 페이지가 물리 메모리에 존재하지 않으면
    페이지 폴트를 발생시켜 디스크에서 해당 페이지를 찾아서 프레임에 할당한다.
    - 만약 해당 프로세스의 프레임이 꽉 찼다면,
    페이지 교체 정책에 따라 디스크의 해당 페이지와 메모리의 특정 페이지를 교체한다.
