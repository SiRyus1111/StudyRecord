## 1. 큐의 기본 구조

큐는 FIFO(선입선출) 구조이기 때문에,
맨 앞의 데이터를 내보내고
맨 뒤에 데이터가 들어가.

그래서 스택과 달리 위치 두 개를 저장해야해.

```text
          [ Front ][ element ][ element ][ element ][ Rear ]
              ^                                        ^
              |                                        |
              |                                        |
    가장 처음 큐에 들어온 원소                 가장 마지막에 큐에 들어온 원소
    이 방향으로 원소가 나감                      이 방향으로 원소가 들어옴
```

원소가 나가는 큐의 맨 앞을 `front`
원소가 들어오는 큐의 맨 뒤를 `rear`라고 해.

그리고 큐에는 여러가지 동작이 필요한데,

- Push : 큐의 `rear`에 새로운 데이터를 넣는 연산
- Pop : 큐의 `front`에 있는 데이터를 삭제하는 연산
- Front : 큐의 `front`에, 맨 앞에 있는 데이터를 삭제하지 않고 확인만 하는 연산
- IsEmpty : 큐가 비어있는지 확인하는 연산
- (배열 구현 한정) IsFull : 큐가 가득찼는지 확인하는 연산

여기서 중요한 연산 세 개만 꼽아보자면,
Push / Pop / Front정도야.

이번 구현에는 가장 간단한 연결 리스트로 먼저 큐를 구현해보고,
그 다음에 단순 선형 구조로 구현하면 문제가 생기는 배열로 큐를 구현해볼거야.

## 2. 큐의 구현 - 연결 리스트

연결 리스트는 사실상 사용가능한 노드의 갯수가 무한이고,
`head` 포인터와 `tail` 포인터로 맨 앞과 맨 뒤에 $O(1)$의 시간복잡도로
자유로운 삽입 / 삭제가 가능하기 때문에,
큐를 구현하기 매우 적합해.

```cpp
template <typename T>
class SLLQueue {
private:
    struct Node {
        T data;
        Node* next;
        
        Node(const T& element) : data(element), next(nullptr) {
        
        }
    };
    
    Node* front_node; // 맨 앞 노드(head)
    Node* rear_node; // 맨 뒤 노드(tail)
public:
    SLLQueue() : front_node(nullptr), rear_node(nullptr) {
    
    }
    ~SLLQueue() { // 소멸자에서 모든 노드 메모리 해제
        Node* current = front_node;
        while (current != nullptr) {
            Node* next_node = current->next;
            delete current;
            current = next_node;
        }
        
        front_node = nullptr;
        rear_node = nullptr;
    }
    
    bool IsEmpty() const;
    
    bool push(const T& value);
    bool pop();
    
    T front();
};
```

`IsEmpty()` 함수부터 보자면,
해당 큐가 비어있다는건 `front_node` / `rear_node`가 모두 `nullptr`이라는 뜻이겠지?

그래서 이렇게 구현할 수 있어.

```cpp
bool SLLQueue::IsEmpty() const {
    return (front_node == nullptr) && (rear_node == nullptr);
}
```

연결 리스트는 크기 제한이 없기 때문에 `IsFull()` 함수는 필요가 없어.

`push()` 함수를 보자면,
사실상 기존 단일 연결 리스트에서 맨 뒤에 삽입하는 것과 다르지 않아.

```cpp
bool SLLQueue::push(const T& value) {
    Node* new_node = new Node(value);
    
    if (rear_node == nullptr) { // 큐가 비어있을 경우
        front_node = new_node;
        rear_node = new_node;
    }
    else {
        rear_node->next = new_node;
        rear_node = new_node;
    }
    
    return true;
}
```

`pop()` 함수도 보자면,
이것도 기존 단일 연결 리스트에서 맨 앞의 노드를 삭제하는 것과 다르지 않고.
하지만 비어있다면 `pop()`을 할 수 없어.

```cpp
bool SLLQueue::pop() {
    if (IsEmpty()) {
        return false;
    }
    
    Node* target = front_node;
    front_node = target->next;
    
    if (front_node == nullptr) {
        rear_node = nullptr;
    }
    
    delete target;
    
    return true;
}
```

`front()` 함수도 보자면,
이것도 기존의 단일 연결 리스트에서 맨 앞 노드의 `data`를 반환하는 것과 다를바가 없어.
물론 비어있는 경우 `front()`을 할 수 없으므로 예외를 던져줘야해.

```cpp
T SLLQueue::front() {
    if (IsEmpty()) {
        throw std::out_of_range("Queue is empty.");
    }
    
    return front_node->data;
}
```

### 2-1. 연결 리스트로 구현한 큐의 시간복잡도

- 삽입(`push()`) : 연결 리스트의 `tail`을 이용한 맨 뒤 삽입과 같으므로 $O(1)$
- 삭제(`pop()`) : 연결 리스트의 맨 앞 삭제와 같으므로 $O(1)$
- 데이터 조회(`front()`) : 연결 리스트의 `head` 조회와 같으므로 $O(1)$
- 비어있는지 확인(`IsEmpty()`) : `front`와 `rear`만 확인하면 되므로 $O(1)$

## 3. 큐의 구현 - 배열(선형)

스택처럼, 큐도 배열로 구현할 수 있어.
하지만, 스택과 다르게 인덱스를 두 개 저장해야한다는 점이 차이점이지.

```cpp
template <typename T, size_t N>
class LinearArrayQueue {
private:
    T data[N];
    int front_index;
    int rear_index;
public:
    LinearArrayQueue() : front_index(-1), rear_index(-1) {
    
    }
    
    bool IsEmpty() const;
    bool IsFull() const;
    
    bool push(const T& value);
    bool pop();
    
    T front();
};
```

### 3-1. `front`와 `rear`의 의미

`front`의 의미는 '가장 마지막으로 삭제된 위치'야.
즉, 첫 번째 데이터의 바로 앞 인덱스지.

`rear`의 의미는 '가장 마지막으로 데이터가 삽입된 위치'야.

그래서 데이터는 항상 `front + 1` 위치부터 존재하고,
`rear` 위치까지 저장되어있지.

굳이 `front`를 첫 번째 데이터가 아닌
첫 번째 데이터의 바로 앞 인덱스로 정하는 이유는,
쉽게 해당 큐가 비어있는걸 나타내기 위해서야.

만약 `front`를 첫 번째 데이터로 놓는다면
해당 큐가 비어있다는건 `front`가 `rear`보다 1 커야해.
데이터 하나 남아있던게 첫 번째 데이터(`front`)와 마지막 데이터(`rear`)가 일치할 때니까.
데이터가 하나도 없다면 첫 번째 데이터가 마지막 데이터와 교차할 때겠지..

하지만, 만약 배열의 끝까지 전부 데이터가 채워져서 `rear`가 마지막 인덱스라면 어떻게 될까?
`front`가 1이 더 크면 마지막 인덱스를 초과해버리겠지?

그래서 그걸 해결하겠답시고 별도의 로직을 넣을 바에
그냥 `front`를 첫 번째 데이터의 바로 앞 인덱스로 정하면
`front == rear`로 해당 큐가 비어있는지 알 수 있는거지.

물론 다른 이유도 있긴 한데,
그건 4번(환형 큐) 파트에서 보자.
(스포 : 환형 큐 구조에서 비어있는 것과 가득차있는 것을 구분하기 위해)

### 3-2. 삭제와 삽입에서의 `front`와 `rear`의 동작

그리고 처음에는 이렇게 둘 다 `-1`(아예 비어있는 상태)로 시작해.

`-1`을 쓰는 이유는 인덱스를 단순 산술 연산으로 관리하는데,
아무것도 없는 상태는 `0`번 인덱스보다 `1`칸 적으므로 `-1`이 어울리기 때문이야.

- `front` : `-1`
- `rear` : `-1`

```text
[ X ] [ X ] [ X ] [ X ] [ X ]
```

그리고 원소가 Push되면,
`rear`을 한 칸 뒤로 미루고 그 인덱스에 새 원소를 넣어.

- `front` : `-1` -> `-1`
- `rear` : `-1` -> `0`

```text
[ 1 ] [ X ] [ X ] [ X ] [ X ]
  ^
  |
  |
 rear
```

그리고 원소가 Pop되는 경우,
`front`를 한 칸 뒤로 미뤄.
(굳이 삭제하지 않아도 그냥 해당 인덱스를 안 쓰면 됨)

- `front` : `1` -> `2`
- `rear` : `4` -> `4`

```text
[ X ] [ X ] [ X ] [ 4 ] [ 5 ]
              ^           ^
              |           |
              |           |
            front        rear        
```

### 3-3. 본격적인 구현

이제 `IsEmpty()`를 보자.

만약 해당 큐가 비어있다면,
앞에서 말했듯이 `front`와 `rear`이 같은 인덱스를 가리키고 있겠지?

```cpp
bool LinearArrayQueue::IsEmpty() const {
    return front_index == rear_index;
}
```

`IsFull()`을 보자면,
해당 큐가 가득차있다는 것은 결국 `rear` 인덱스를 더이상 뒤로 미룰 수 없다는 이야기잖아?

```cpp
bool LinearArrayQueue::IsFull() const {
    return rear_index == N - 1;
}
```

`push()`를 보자면,
결국 `IsFull()` 검사를 한 후 `rear`를 1 증가시키고, 해당 위치에 데이터를 넣는거야.

```cpp
bool LinearArrayQueue::push(const T& value) {
    if (IsFull()) {
        return false;
    }
    data[++rear_index] = value;
    
    return true;
}
```

`pop()`을 보자면,
`IsEmpty()` 검사를 한 다음에 `front`를 1 증가시키면 돼.
(기존의 인덱스는 어차피 더 이상 쓰지 않으면 되니까)

```cpp
bool LinearArrayQueue::pop() {
    if (IsEmpty()) {
        return false;
    }
    
    ++front_index;
    
    return true;
}
```

마지막으로 `front()` 함수의 구현도 보자면,
이것도 `IsEmpty()` 검사를 한 후에 
`front`의 의미가 첫 번째 데이터의 바로 앞 인덱스니까
큐의 첫 번째 데이터인 `front + 1` 인덱스의 값을 반환하면 그만이야.

```cpp
T LinearArrayQueue::front() {
    if (IsEmpty()) {
        throw std::out_of_range("Queue is empty.");
    }
    
    return data[front_index + 1];
}
```

### 3-4. 배열로 구현한 선형 큐의 시간복잡도

- 삽입(`push()`) : 인덱스로 바로 접근하고 일정 횟수의 연산만 수행하므로 $O(1)$
- 삭제(`pop()`) : 인덱스로 바로 접근하고 일정 횟수의 연산만 수행하므로 $O(1)$
- 데이터 조회(`front()`) : 인덱스로 바로 접근하고 일정 횟수의 연산만 수행하므로 $O(1)$
- 비어있는지 / 꽉차있는지 확인(`IsEmpty()` / `IsFull()`) : 변수 두 개만 확인하면 되므로 $O(1)$

### 3-5. 배열로 구현한 선형 큐의 문제점

일단, 앞서 눈치챘을 수도 있는데,
배열로 선형 큐를 구현하면
연결 리스트와 다르게 맨 앞 삭제가 자연스럽지 않다보니까
무조건 큐에 더 원소가 들어오고 빠져나갈수록
맨 앞의 메모리 공간이 낭비돼.

```text
          이 앞의 비어있는 인덱스들은 어캄?
                    ↓
[ X ] [ X ] [ X ] [ X ] [ 5 ]
                    ^     ^
                    |     |
                    |     |
                  front  rear         
```

결국 `front`든 `rear`든 뒤로밖에 안 가다보니까
삽입 / 삭제가 많이 일어나면 맨 앞에 비어있는 인덱스들이 낭비돼.

그래서,
삭제(맨 앞 삭제)가 일어날 때마다 모든 인덱스의 원소들을 하나씩 땡기면 될 것 같긴 한데,
그러면 그 비용이랑 `front` / `rear`을 잘 맞춰줘야 하는 수고가 더 들겠지..

그래서, 배열로 구현한 큐는 보통 뒤의 환형 큐 구조를 사용해.

## 4. 큐의 구현 - 배열(환형)

환형 큐란, 환형 연결 리스트마냥
맨 뒤의 인덱스를 넘어가면 다시 맨 앞의 인덱스로 돌아오도록 구현해놓은 큐를 말해.

앞서 설명한 배열의 공간 낭비 문제 때문에
이 구조가 나왔어.

결국 맨 뒤 인덱스를 맨 앞 인덱스와 이어버리는게 이 환형 큐의 핵심적인 아이디어야.
나머지 연산(`%`)을 이용해 구현될 수 있지.

현재 인덱스를 배열의 크기로 나눈다면, 
나눈 나머지가 결국 해당 배열 내에서 표현될 수 있는 범위 안에 들어갈테니까.

`현재 인덱스 % 배열의 크기`.. 
이 식은 결국 반환되는 값이 배열의 크기를 넘어설 수 없어.

만약

```text
[ X ] [ X ] [ X ] [ X ] [ X ]
                          ^
                          |
                       4번 인덱스
                     (현재 인덱스)
```

여기에서 인덱스를 `+ 1`하면,
배열의 크기가 `5`이므로 `(4 + 1) % 5` = `0`로 다시 맨 앞 인덱스(`0`번)로 복귀하게 돼.

### 4-1. 환형 큐의 핵심 : 배열 한 칸 비워두기

이게 처음 환형 큐를 접할 때 가장 헷갈리는건데,
실제 환형 큐를 구현할 때 모든 인덱스를 다 채우도록 구현하지 않는다는 점이야.

이게 왜 이렇게 하냐면,
만약 크기가 4인 배열에 4개 데이터를 꽉 채워버린다고 하자.

- `front` : 첫 번째 데이터의 전 인덱스
- `rear` : 마지막 데이터의 인덱스

라고 하고.

그러면 텅 빈 상태나 가득 찬 상태나 같은 인덱스 표현을 가져.

- 텅 빔 : 첫 번째 데이터의 인덱스와 마지막 데이터의 인덱스가 교차함 
  - 즉, 첫 번째 데이터의 전 인덱스와 마지막 데이터의 인덱스가 일치함
  - 즉, `front == rear`
- 가득 참 : 마지막 데이터의 인덱스가 한 바퀴를 돌아 첫 번째 데이터의 인덱스 바로 전까지 옴
  - 즉, 첫 번째 데이터의 전 인덱스와 마지막 데이터의 인덱스가 일치함
  - 즉, `front == rear`
  
이렇게 말이야.

```text
(비어있는 경우)

     (마지막 인덱스) (첫 인덱스)
              |     |
              ↓     ↓
[ X ] [ X ] [ X ] [ X ] [ X ]
              ^
              |
              |
         front, rear
```

```text
(가득 차 있는 경우)

(마지막 인덱스) (첫 인덱스)
        |     |
        ↓     ↓
[ 1 ] [ 2 ] [ 3 ] [ 4 ] [ 5 ]
        ^
        |
        |
    rear, front
```

그래서, 실제 환형 큐 구현에서는 `front`가 가리키는 인덱스 한 칸은 일부러 비워두고,
실제 데이터는 `N - 1`개만 저장하는 방식을 많이 써.

이렇게 하면,

- 텅 빔 : 첫 번째 데이터의 인덱스와 마지막 데이터의 인덱스가 교차함
  - 즉, 첫 번째 데이터의 전 인덱스와 마지막 데이터의 인덱스가 일치함
  - 즉, `front == rear`
- 가득 참 : 마지막 데이터의 인덱스가 한 바퀴를 돌아 첫 번째 데이터의 전 인덱스 바로 전까지 옴
  - (첫 번째 데이터의 바로 전 인덱스(`front`)는 일부러 비워두기 때문에
  가득찬 경우가 첫 번째 데이터의 전 인덱스의 전 인덱스(`front - 1`)인거..)
  - 즉, `rear`를 `1` 늘린 후 `front`와 비교하면 됨.
  - 하지만, `rear`이 `1` 늘어나서 정해진 배열의 크기 `N`에서 벗어날 수 있기 때문에
  `1`을 더한 `rear`에는 나머지 연산을 해줌.
  - 즉, `front == (rear + 1) % N`
  - (`front`는 이미 나머지 연산(`%`)으로 저장되어 `N` 안에 들어오는 상태)
  - (`rear`은 `+ 1`로 `N`에서 벗어날 수 있는 상태라 나머지 연산(`%`))
  
이렇게 텅 빈 경우와 가득 찬 경우를 나눠서 볼 수 있어.

```text
(비어있는 경우)

     (마지막 인덱스) (첫 인덱스)
              |     |
              ↓     ↓
[ X ] [ X ] [ X ] [ X ] [ X ]
              ^
              |
              |
         front, rear
```

```text
(가득 차 있는 경우)

   (첫 데이터 전의 인덱스(front)는 비워둠)
        |
        ↓
[ 1 ] [ X ] [ 3 ] [ 4 ] [ 5 ]
  ^     ^
  |     |
  |     |
rear  front
```

### 4-2. 환형 큐의 본격적인 구현

```cpp
template <typename T, size_t N>
class CircularArrayQueue {
private:
    T data[N];
    int front_index;
    int rear_index;
public:
    CircularArrayQueue() : front_index(0), rear_index(0) {
        // 환형 큐는 0번 인덱스부터 시작해도 순환되므로 0으로 초기화
    }
    
    bool IsEmpty() const;
    bool IsFull() const;
    
    bool push(const T& value);
    bool pop();
    
    T front();
};
```

`IsEmpty()` / `IsFull()`은 방금 설명한대로 구현하면 돼.

```cpp
bool CircularArrayQueue::IsEmpty() const {
     return front == rear;
}
```

```cpp
bool CircularArrayQueue::IsFull() const {
    return (rear + 1) % N == front;
}
```

`push()` / `pop()` / `front()`는 앞서 말한대로 인덱스를 초과하지 않게 
나머지 연산(`%`)을 사용해서 `rear_index` / `front_index`를 관리해줘야해.

```cpp
bool CircularArrayQueue::push(const T& value) {
    if (IsFull()) {
        return false;
    }
    
    rear_index = (rear_index + 1) % N;
    data[rear_index] = value;
    return true;
}
```

```cpp
bool CircularArrayQueue::pop() {
    if (IsEmpty()) {
        return false;
    }
    
    front_index = (front_index + 1) % N;
    return true;
}
```

```cpp
T CircularArrayQueue::front() {
    if (IsEmpty()) {
        throw std::out_of_range("Queue is empty.");
    }
    
    return data[(front_index + 1) % N];
}
```

### 4-3. 배열로 구현한 환형 큐의 시간복잡도

- 삽입(`push()`) : 인덱스로 바로 접근하고 일정 횟수의 연산만 수행하므로 $O(1)$
- 삭제(`pop()`) : 인덱스로 바로 접근하고 일정 횟수의 연산만 수행하므로 $O(1)$
- 데이터 조회(`front()`) : 인덱스로 바로 접근하고 일정 횟수의 연산만 수행하므로 $O(1)$
- 비어있는지 / 꽉차있는지 확인(`IsEmpty()` / `IsFull()`) : 변수 두 개만 확인하면 되므로 $O(1)$
