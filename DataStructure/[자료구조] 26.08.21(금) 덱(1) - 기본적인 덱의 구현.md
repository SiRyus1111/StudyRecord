## 0. 서론

지금까지 LIFO(후입선출) 자료구조인 스택과 FIFO(선입선출) 자료구조인 큐를
연결 리스트와 배열로 구현해봤었는데,
이번에는 최종 보스라고 할 수 있는
덱(Deque)이야.

이번에는 덱이 대체 뭔지,
그리고 배열과 연결 리스트를 이용한 구현 각각에 대해 공부해볼 생각이야.

대략,

- 덱의 기본 구조
- 덱의 구현 - 배열(환형)
  - 삽입
  - 조회
  - 삭제
  - 시간복잡도
- 덱의 구현 - 이중 연결 리스트
  - 삽입
  - 조회
  - 삭제
  - 시간복잡도
  
이 정도로 해볼 생각이야.

## 1. 덱의 기본 구조

덱은 쉽게 말하면,
양쪽 끝에서 삽입 / 삭제가 가능한 자료구조라고 보면 돼.

스택과 큐를 합친거라고 보면 돼.

- 스택 : 한쪽 끝에서 삽입 / 삭제
- 큐 : 한쪽 끝에서 삽입, 반대쪽 끝에서 삭제
- 덱 : 한쪽 끝에서 삽입 / 삭제, 반대쪽 끝에서도 삽입 / 삭제

```text
[ Front ][ element ][ element ][ element ][ Rear ]
```

이렇게 있다고 치면,
`front`로도, `rear`로도 삽입 / 삭제가 가능한 자료구조라는거야.

그래서

- 스택이나 큐 중 하나의 용도로 쓸 수도 있고,
- **양방향 삽입 / 삭제가 필요한 경우에 쓸 수도 있고**

이런 식이야.

그리고 덱에는 여러가지 동작이 필요해.

- Push(front / back) : 덱의 `front` / `rear`에 새로운 데이터를 넣는 연산
- Pop(front / back) : 덱의 `front` / `rear`에 있는 데이터를 삭제하는 연산
- Front : 덱의 `front`의 데이터를 삭제하지 않고 확인만 하는 연산
- Back : 덱의 `rear`의 데이터를 삭제하지 않고 확인만 하는 연산
- IsEmpty : 덱이 비어있는지 확인하는 연산
- IsFull : 덱이 가득찼는지 확인하는 연산

이 정도가 있어.

이번 구현에서는 지난번 환형 큐처럼
`front` / `rear` 인덱스 기반으로 구현하지 않고,
따로 해당 덱에 들어있는 원소 갯수인 `size` 변수를 만들어서 들고있는 식으로 구현해볼게.
(이게 덱에서는 훨씬 편리함)

그리고, 연결 리스트는 단일 연결 리스트를 쓰면
맨 뒤 삭제가 $O(n)$ 걸려서 덱의 장점을 살릴 수 없기 때문에,
이중 연결 리스트를 쓰도록 할게.

## 2. 덱의 구현 - 배열(환형)

이것도 기존의 환형 큐 생각하면 나름 쉬워.
하지만 기존의 환형 큐와 다르게,
첫 번째 데이터 전 인덱스를 한 칸 비워놓지 않고,
따로 `size` 변수로 `IsEmpty()` / `IsFull()` 판별을 할 생각이야.

그래서, `size == 0`이면 비어있는거고,
`size = N`이면 꽉 차 있는걸로 판별하는거지.

앞 / 뒤에 삽입하고 삭제하는 연산은 그저 `front` / `rear` 인덱스를
`- 1` / `+ 1` 해주고 삽입 / 삭제하는거야.

그리고 여기서 중요한게 `- 1`하다가 `0`번 인덱스를 지나치는건데,
이건 해결하는 방법이 있어.
바로 `N`을 한 번 더한 상태로 나누는거야.

일반적인 경우에는 그 `N`은 `(front - 1 + N) % N`으로 사라질테지만,
`front`가 `0`인 경우에는 `(-1 + N) % N`이 되어서 `N - 1`이 돼.
그렇게 `front`에서 더 앞으로 `push()`되는 경우에는 다시 최상위 인덱스로 순환하는거지.

그리고 `front`와 `rear`의 의미도 중요해.
안 그러면 `front` / `rear`가 가리키는 위치의 정의가 어긋나게 되거든.

만약 초기값으로 `front = 0` / `rear = 0`으로 놓고
`front` = 현재 맨 앞 위치
`rear` = 현재 맨 뒤 위치

이렇게 하면 어떻게 될까?

이게 문제가, 비어있는 상태는 `front` / `rear`가 교차해 있어야해.
그래서 초기 인덱스를 `(0, N - 1)`로 해놓아야하지.

그래서, 비어있을 때 `front`와 `rear`가 교차해있지 않도록

`front` = 현재 맨 앞 위치
`rear` = 다음에 맨 뒤 삽입할 위치

이렇게 의미를 명확하게 반개방 구간으로 해놓는게 좋아.

마치 STL 이터레이터의 `begin()` / `end()`처럼,
`begin()`은 첫 원소를,
`end()`는 마지막 원소의 다음(빈 공간)을 가리키는 것 처럼
인덱스를 설정해놔야해.

안 그러면, 한 인덱스를 건너뛰게 되는 문제가 발생할 수 있어.

### 2-1. 본격적인 구현

```cpp
template <typename T, size_t N>
class CircularArrayDeque {
private:
    T data[N];
    int size;
    int front_index; // 현재 맨 앞 위치
    int rear_index; // 다음에 맨 뒤 삽입 할 위치
public:
    CircularArrayDeque() : front_index(0), rear_index(0), size(0) {
    
    }
    
    bool IsEmpty() const;
    bool IsFull() const;
    
    bool push_front(const T& value);
    bool push_back(const T& value);
    
    bool pop_front();
    bool pop_back();
    
    T front();
    T back();
    
};
```

`IsEmpty()`와 `IsFull()`은 앞에서 말한대로 `size` 기반으로 동작해.

- `size == 0` : 비어있음
- `size == N` : 꽉차있음

```cpp
bool CircularArrayDeque::IsEmpty() const {
    return size == 0;
}
```

```cpp
bool CircularArrayDeque::IsFull() const {
    return size == N;
}
```

`push_front()` / `push_back()`은 앞서 설명한 `%`를 이용해서 돌아가.
물론 `size`를 증가시키는 것도 잊으면 안되고.

```cpp
bool CircularArrayDeque::push_front(const T& value) {
    if (IsFull()) {
        return false;
    }
    
    front_index = (front_index - 1 + N) % N;
    ++size;
    data[front_index] = value;
    
    return true;
}
```

```cpp
bool CircularArrayDeque::push_back(const T& value) {
    if (IsFull()) {
        return false;
    }
    
    data[rear_index] = value; // rear_index가 맨 뒤 삽입할 위치이므로 일단 먼저 저장
    rear_index = (rear_index + 1) % N; // 그 후 rear_index를 증가
    ++size;
    
    return true;
}
```

`pop_front()` / `pop_back()` / `front()` / `back()`도 앞서 설명한 `%`를 이용해서 돌아가.
여기서도 `size`를 감소시키는 것을 잊으면 안돼.
(물론 `front()` / `back()`은 단순 데이터 조회 함수니 `size`를 변경하면 안되고.)

```cpp
bool CircularArrayDeque::pop_front() {
    if (IsEmpty()) {
        return false;
    }
    
    front_index = (front_index + 1) % N;
    --size;
    
    return true;
}
```

```cpp
bool CircularArrayDeque::pop_back() {
    if (IsEmpty()) {
        return false;
    }
    
    rear_index = (rear_index - 1 + N) % N;
    --size;
    
    return true;
}
```

```cpp
T CircularArrayDeque::front() {
    if (IsEmpty()) {
        throw std::out_of_range("Deque is empty.");
    }
    
    return data[front_index];
}
```

```cpp
T CircularArrayDeque::back() {
    if (IsEmpty()) {
        throw std::out_of_range("Deque is empty.");
    }
    
    return data[(rear_index - 1 + N) % N]; // rear_index가 다음에 맨 뒤 삽입할 위치이므로 - 1 해야함
}
```

### 2-2. 배열로 구현한 환형 덱의 시간복잡도

- 삽입 : 인덱스로 바로 접근하고 일정 횟수의 연산만 수행하므로 $O(1)$
- 삭제 : 인덱스로 바로 접근하고 일정 횟수의 연산만 수행하므로 $O(1)$
- 데이터 조회 : 인덱스로 바로 접근하고 일정 횟수의 연산만 수행하므로 $O(1)$
- 상태 확인 : 변수 하나만 확인하면 되므로 $O(1)$

## 3. 덱의 구현 - 이중 연결 리스트

물론 단일 연결 리스트도 덱을 구현하는데 사용은 할 수 있지만,
삭제할 때 이전 노드도 알아야 하기 때문에(이전 노드를 `tail`로 붙여야함)
역방향 탐색이 불가능한 단일 연결 리스트는 맨 뒤 삭제가 $O(n)$만큼 걸려서,
결국 이중 연결 리스트를 사용해야
맨 앞 / 맨 뒤 삽입 / 삭제가 자유로운 덱을 제대로 구현할 수 있어.

### 3-1. 본격적인 덱의 구현

```cpp
template <typename T>
class DLLDeque {
private:
    struct Node {
        T data;
        Node* prev;
        Node* next;
        
        Node(const T& value) : data(value), prev(nullptr), next(nullptr){
        
        }
    }
    
    Node* front_node;
    Node* rear_node;
public:
    DLLDeque() : front_node(nullptr), rear_node(nullptr) {
        
    }
    ~DLLDeque() { // 소멸자에서 모든 노드 메모리 해제
        Node* current = front_node;
        while (current != nullptr) {
            Node* next_node = current->next;
            delete current;
            current = next_node;
        };
        
        front_node = nullptr;
        rear_node = nullptr;
    }
    
    bool IsEmpty() const;
    
    bool push_front(const T& value);
    bool push_back(const T& value);
    
    bool pop_front();
    bool pop_back();
    
    T front();
    T back();
};
```

해당 연결 리스트에 노드가 없는지 확인하려면 `front_node` / `rear_node`가 `nullptr`인지 확인하면 돼.

```cpp
bool DLLDeque::IsEmpty() const {
    return (front_node == nullptr) && (rear_node == nullptr);
}
```

그리고 해당 노드에 맨 앞 / 맨 뒤로 `push()`하는
`push_front()` / `push_back()`은 사실상 이중 연결 리스트의 맨 앞 삽입 / 삭제와 다를 바가 없어.

```cpp
bool DLLDeque::push_front(const T& value) {
    Node* new_node = new Node(value);
    
    if (front_node == nullptr) { // 노드가 하나도 없을 때 처리
        front_node = new_node;
        rear_node = new_node;
    }
    else {
        front_node->prev = new_node;
        new_node->next = front_node;
        front_node = new_node;
    }
    
    return true;
}
```

```cpp
bool DLLDeque::push_back(const T& value) {
    Node* new_node = new Node(value);
    
    if (rear_node == nullptr) {
        front_node = new_node;
        rear_node = new_node;
    }
    else {
        rear_node->next = new_node;
        new_node->prev = rear_node;
        rear_node = new_node;
    }
    
    return true;
}
```

해당 노드의 맨 앞 / 맨 뒤로 `pop()` 하는
`pop_front()` / `pop_back()`은 사실상 이중 연결 리스트의 맨 앞 / 맨 뒤 삭제와 다를 바가 없어.

```cpp
bool DLLDeque::pop_front() {
    if (IsEmpty()) {
        return false;
    }
    
    Node* target = front_node;
    if (front_node == rear_node) {
        front_node = nullptr;
        rear_node = nullptr;
    }
    else {
        front_node = target->next;
        target->next->prev = nullptr;
    }
    
    delete target;
    
    return true;
}
```

```cpp
bool DLLDeque::pop_back() {
    if (IsEmpty()) {
        return false;
    }
    
    Node* target = rear_node;
    if (front_node == rear_node) {
        front_node = nullptr;
        rear_node = nullptr;
    }
    else {
        rear_node = target->prev;
        target->prev->next = nullptr;
    }
    
    delete target;
    
    return true;
}
```

마지막으로 `front()` / `back()`은 그냥 `front` / `rear`의 `data`를 반환하면 되지.

```cpp
T DLLDeque::front() {
    if (IsEmpty()) {
        throw std::out_of_range("Deque is empty.");
    }
    
    return front_node->data;
}
```

```cpp
T DLLDeque::back() {
    if (IsEmpty()) {
        throw std::out_of_range("Deque is empty.");
    }
    
    return rear_node->data;
}
```

### 3-2. 이중 연결 리스트로 구현한 덱의 시간복잡도

- 삽입 : 이중 연결 리스트의 맨 앞 / 맨 뒤 삽입과 같이 고정된 횟수의 연산만 수행하므로 $O(1)$
- 삭제 : 이중 연결 리스트의 맨 앞 / 맨 뒤 삭제와 같이 고정된 횟수의 연산만 수행하므로 $O(1)$
- 데이터 조회 : 포인터 하나만 조회하면 되므로 $O(1)$
- 상태 확인 : 고정된 갯수의 포인터만 조회하면 되므로 $O(1)$
