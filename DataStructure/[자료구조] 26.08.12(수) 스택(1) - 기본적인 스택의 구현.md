## 1. 스택의 필요성

솔직히 이거 의문이 들 수 있어.
왜 굳이 스택이 필요한걸까?

솔직히 우리가 상식적으로,
스택처럼 LIFO(Last In First Out, 후입선출) 자료구조보단
큐같은 FIFO(First In First Out, 선입선출) 자료구조가 훨씬 많이 필요할텐데..

스택의 필요성은 바로 그 후입선출이라는 점으로부터 시작해.

이게, 뭔가 사람이 쓰기에는 선입선출 자료구조인 큐가 훨씬 더 직관적이고 많이 쓰일 것 같지만,
실제 알고리즘 등등에서는 후입선출 자료구조인 스택도 많이 사용돼.

왜 그렇냐면,
스택은 특유의 후입선출 특성 때문에 
'가장 최근에 넣은 것을 가장 먼저 처리하고 싶을 때 쓰는 자료구조'의 능력이 있어.

여기서 중요한건, 단순히 역순으로 저장한다는 느낌보다는
가장 최근에 삽입된 원소만 계속 상대한다는거야.

그래서

```text
함수 호출 -> 가장 최근에 호출한 함수부터 return
DFS -> 가장 최근에 발견한 경로부터 탐색
괄호 검사 -> 가장 최근에 열린 괄후부터 닫혀야 함
Undo -> 가장 최근에 한 작업부터 취소
```

이런 경우에 주로 쓰이지.

그런데 여기서 눈여겨봐야할 점이,
가장 최근에 삽입된 원소를 다루지만,
이전에 삽입된 원소들도 계속 들고있어서,
스택에 저장된 원소들은 지금까지의 발자취를 나타낸다고 할 수 있어.

그래서, 가장 최근에 삽입된 원소부터 하나씩 삭제해나간다면,
계속 과거의 원소를 구할 수 있게 되는거지.

이게 스택이 필요한 이유야.

> 가장 최근에 삽입한 원소를 가장 먼저 처리하고,
> 과거의 기록을 따라가기 위해서

라고 할 수 있겠네.

## 2. 스택의 기본 구조

스택은 LIFO(후입선출) 구조 때문에,
데이터가 들어가고 나오는 입구가 단 하나뿐인 원통형 구조야.

```text
|---------------|
|      top      | <---- 가장 마지막으로 스택에 들어온 원소, 이 방향으로 새로운 원소가 들어옴
|---------------|
|    element    |
|---------------|
|    element    |
|---------------|
|     bottom    | <---- 가장 처음으로 스택에 들어온 원소
|---------------|
```

이 유일한 입구를 `top`이라고 해.

그리고, 스택은 사실상 이 `top`을 포인터같은걸로 구해놓고 구현되지.
(물론 구현마다 다를 수 있음)

그리고 가장 처음 들어온 원소는 `bottom`이라고 하고,
이건 솔직히 배열로 구현할 때는 그냥 무시해도 돼.

그리고 스택에는 여러가지 동작이 필요해.

- Push : 스택의 `top`에 새로운 데이터를 밀어넣는 연산
- Pop : 스택의 `top`에 있는 데이터를 삭제하는 연산
- Top : 스택의 맨 위에 있는 데이터를 삭제하지 않고 확인만 하는 연산
- IsEmpty : 스택이 비어있는지 확인하는 연산
- IsFull : 스택이 가득찼는지 확인하는 연산

그리고 여기서 가장 중요한 연산 두 개를 꼽아보자면,
원소를 삽입하는 Push와 삭제하는 Pop이라고 할 수 있겠지.

구현 파트에서는 거기에다 스택의 `top`에 있는 데이터를 삭제하지 않고 확인만 하는
Top이라는 연산도 다뤄볼거야.

그리고 이번에는 가장 단순한 구현 중 하나인
고정 크기 배열을 이용한 스택을 구현해볼거야.

그래서 고정 크기 배열의 크기를 넘어서 원소가 들어가면
스택 오버플로우가 발생해서,
큰 문제가 생길 수 있어.

## 3. 스택의 구현

스택은 단순히 한 가지 방식으로 구현할 수 있는 자료구조라기보단,
여러가지 방식으로 구현할 수 있는 자료구조야.

이 글에서는

- 고정 크기 배열로 구현(기본적인 스택의 구현)
- 연결 리스트로 구현

이 두 가지의 구현을 살펴볼거야.

### 3-1. 스택의 구현 - 배열

일단 고정 크기 배열을 이용한 기본적인 구현은,

```cpp
template <typename T, size_t N>
class ArrayStack {
private:    
    T data[N];
    int top_index;
public:
    ArrayStack() : top_index(-1) {
    
    }
    
    bool IsEmpty() const;
    bool IsFull() const;
    int size() const;
    int capacity() const;
    
    bool push(const T& value);
    bool pop();
    
    std::optional<T> top(); // 스택이 비어있는 경우를 처리하기 위해 optional 사용
}
```

이 정도라고 할 수 있어.

- 스택에 들어있는 데이터들을 나타내는 `data` 고정 크기 배열
- 스택의 `top` 인덱스를 나타내는 `top_index`

이렇게 두 가지를 멤버로 가지고있지.
그리고, 스택이 비어있을 때는 `top_index`는 `-1`로 둬.

왜 그렇냐면, 스택이 비어있다는건 `top` 인덱스가 `0`보다 `1` 작다는 뜻이니까.
그리고 결국 이게 `push()`와 `pop()`을 할 때 `top`을 `1`씩 늘였다 줄였다 해야하는데,
`top` 인덱스가 `0`일때(스택에 원소가 하나뿐일 때) `pop()`을 한다면 
`top`이 `-1`이 되는게 자연스러우니까..

일단 `IsEmpty()` 함수의 구현부터 보자.
앞의 스택이 비어있을 때 `top_index`가 `-1`이라는 것을 이용하면 돼.

```cpp
bool ArrayStack::IsEmpty() const {
    return top == -1; // top이 -1이라면 해당 스택은 비어있음
}
```

그리고 `IsFull()` 함수의 구현도 봐보자면,
결국 정해진 크기의 마지막 인덱스는 입력받은 크기 `N`에서 `1`을 뺀 값이라는 점을 이용하면 돼.
`top_index`가 `N - 1`이면, 해당 스택의 마지막 인덱스까지 원소가 들어가있는거지.

```cpp
bool ArrayStack::IsFull() const {
    return top_index == N - 1;
}
```

`size()` 함수의 구현도 봐보자면,
결국 `size`, 즉 해당 스택에 있는 원소의 갯수는 `top`을 보고 알 수 있어.
하지만 인덱스 지정 방식에 따라 
`top_index`는 `실제 원소 개수 - 1`이니까,
`top_index + 1`을 해주면 `size`가 나오지.

```cpp
size_t ArrayStack::size() const {
    return top_index + 1;
}
```

`capacity()` 함수의 구현도 봐보자면,
`capacity`, 즉 해당 스택에 저장할 수 있는 원소의 최대는 
해당 스택 객체를 만들 때 입력받는 `N`을 보고 알 수 있어.

```cpp
size_t ArrayStack::capacity() const {
    return N;
}
```

이제 `push()` 함수의 구현도 보자.
`push()` 함수는 스택에 새 원소를 삽입하는 연산인데,
이미 스택이 가득차있으면 새 원소를 삽입하면 안돼.

그리고 스택에 새 원소를 삽입하는 위치는,
`top_index`의 다음 인덱스겠지.
현재의 `top_index`는 현재 스택의 마지막 인덱스일테니, 그 다음 인덱스에 새 원소를 넣어야할테니까.

```cpp
bool ArrayStack::push(const T& value) {
    if (IsFull()) {
        return false;
    }
    
    data[++top_index] = value;
    
    return true;
}
```

그 다음에는 `pop()` 함수의 구현도 보자.
`pop()` 함수는 스택의 가장 최근에 넣은 원소를 삭제하는 연산인데,
스택이 비어있으면 원소가 없기 때문에 삭제하면 안돼.

그리고 스택의 기존 원소를 삭제하는 위치는,
`top` 인덱스겠지.
그리고 `top` 인덱스의 값이 삭제되니 `top_index`도 `1` 내려야할테고.

```cpp
bool ArrayStack::pop() {
    if (IsEmpty()) {
        return false;
    }
    
    --top_index; // 왜 이것만으로 되냐면, 스택의 범위만 줄여서 새로 원소가 들어올 때 남아있는 원소를 덮어쓰기 하려고..
    
    return true;
}
```

마지막으로 `top()` 함수의 구현도 보자.
`top()` 함수는 스택의 가장 최근에 넣은 원소를 삭제하지 않고 확인하는, 
즉 가장 최근에 넣은 원소를 반환하는 연산이야.
스택이 비어있으면 원소가 없다는 뜻이므로 반환할 값도 없겠지.

결국 `top_index`가 나타내는 인덱스의 원소를 반환하는거야.

```cpp
std::optional<T> ArrayStack::top() {
    if (IsEmpty()) {
        return std::nullopt; // 값이 없음을 반환
    }
    
    return data[top_index];
}
```

### 3-1-1. 배열로 구현한 스택의 시간복잡도

- 삽입(`push()`) : 인덱스로 바로 접근하고 일정 횟수의 연산만 수행하므로 $O(1)$
- 삭제(`pop()`) : 인덱스로 바로 접근하고 일정 횟수의 연산만 수행하므로 $O(1)$
- 데이터 조회(`top()`) : 인덱스로 바로 접근하고 일정 횟수의 연산만 수행하므로 $O(1)$
- 비어있는지 / 꽉차있는지 확인(`IsEmpty()` / `IsFull()`) : 인덱스 변수 하나만 확인하므로 $O(1)$

### 3-2. 스택의 구현 - 연결 리스트

스택은 고정 크기 배열 뿐만 아니라,
연결 리스트로도 구현할 수 있어.

연결 리스트에서 `head` 포인터 기억나지?

- `head` 포인터 = `top_index`

로 보고 구현하면 편해.

`tail` 포인터는 일부러 안 썼어. 
굳이 `bottom` 포인터가 필요한가 해서..

그리고 `size()` 함수는 일부러 안 구현했어.
`size`라는 별도의 변수를 증감하느라 코드만 더 복잡해질 것 같아서..

그리고 연결 리스트는 고정 크기 배열과 다른 점이
**고정된 최대 용량이 없다는 점**이라,
정해진 `capacity` 때문에 발생하는 스택 오버플로우 걱정은 없어.

연결 리스트로 구현한 스택은 대략

```cpp
template <typename T>
class SLLStack {
private:
    struct Node {
        T data;
        Node* next;
        
        Node(const T& element) : data(element), next(nullptr) {
        
        }
    }
    
    Node* top_node;
    
public:
    SLLStack() : top_node(nullptr) { // 생성자에서 top을 초기화
    
    }
    ~SLLStack() { // 소멸자에서 해당 연결 리스트로 구현된 스택의 모든 데이터를 메모리 해제
        Node* current = top_node;
        while (current != nullptr) {
            Node* next_node = current->next;
            delete current;
            current = next_node;
        }
        
        top_node = nullptr;
    }
    
    bool IsEmpty() const;
    
    bool push(const T& value);
    bool pop();
    
    std::optional<T> top(); // 스택이 비어있는 경우를 처리하기 위해 사용
}
```

`IsEmpty()` 함수부터 보자면,
일단 해당 스택이 비어있다는건 `top_node`가 `nullptr`이란거잖아?

그래서 이렇게 구현할 수 있어.

```cpp
bool SLLStack::IsEmpty() const {
    return top_node == nullptr;
}
```

스택의 크기 제한은 앞서 설명한 연결 리스트의 특성 때문에 없으니
`IsFull()` 함수는 필요가 없겠고,

`push()` 함수를 보자면,
어차피 스택 오버플로우 신경을 쓸 필요가 없기 때문에
크게 별도의 예외처리는 하지 않아도 돼.

그리고 이건 사실상, 
기존 단일 연결 리스트에서 맨 앞에 삽입하는 것과 다를바가 없어.

```cpp
bool push(const T& value) {
    Node* new_node = new Node(value);
    
    new_node->next = top_node;
    top_node = new_node;
    
    return true;
}
```

`pop()` 함수도 보자면,
이건 노드가 하나도 없을 때에 대한 처리를 해야해.

그리고 이것도 사실상
기존 단일 연결 리스트에서 맨 앞의 노드를 삭제하는 것과 다를바가 없지.

```cpp
bool pop() {
    if (IsEmpty()) { // 스택이 비어있을 경우 처리
        return false;
    }
    
    Node* target = top_node;
    top_node = target->next; // 노드가 하나뿐일 때도 top이 nullptr로 정상적으로 변경됨
    
    delete target;
    
    return true;
}
```

`top()` 함수도 보자면,
이건 기존의 고정 크기 배열 기반 스택과 상당히 비슷해서,
간단해.

```cpp
std::optional<T> top() {
    if (IsEmpty()) {
        return std::nullopt;
    }
    
    return top_node->data;
}
```

### 3-2-1. 연결 리스트로 구현한 스택의 시간복잡도

- 삽입(`push()`) : 연결 리스트의 맨 앞 삽입과 같으므로 $O(1)$
- 삭제(`pop()`) : 연결 리스트의 맨 앞 삭제와 같으므로 $O(1)$
- 데이터 조회(`top()`) : 연결 리스트의 `head` 조회와 같으므로 $O(1)$
- 비어있는지 확인(`IsEmpty()`) : `top`만 확인하면 되므로 $O(1)$

## 4. 요약 정리

1. 스택은 다양한 방식(배열 / 연결 리스트 등)으로 구현될 수 있는
LIFO(후입선출) 자료구조이다.
2. 스택에 가장 마지막으로 들어온 원소의 위치를 `top`이라 하고,
이 `top`을 기반으로 `push()` / `pop()` / `top()` 등의 동작이 수행된다.
3. 스택을 고정 크기 배열로 구현할 때는 크기가 고정이기 때문에
고정 크기 배열의 크기를 초과하는 스택 오버플로우를 신경써줘야한다.
4. 고정 크기 배열로 구현할 경우,
`push()`를 수행할 때는 스택 오버플로우가 발생하지 않게 
고정 크기 배열의 크기를 고려해줘야한다.
5. `pop()` / `top()`을 수행할 때는 원소가 하나라도 존재해야하므로
원소가 하나도 없는 경우를 고려해줘야한다.
