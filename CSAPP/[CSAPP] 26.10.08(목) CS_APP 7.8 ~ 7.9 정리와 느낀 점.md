## 1. Executable Object Files - 실행가능 오브젝트 파일

### 정리

1. 실행가능 오브젝트 파일의 섹션들
    - 재배치가능 오브젝트 파일의 섹션과 이름이 같은 섹션들이 있지만,
    다른 점은 해당 섹션들은 재배치가능 오브젝트 파일의 섹션들이 합쳐져있다는 것이다.
    - ELF 헤더 : 말 그대로 해당 오브젝트 파일의 정보를 담고있는 헤더
    - 세그먼트 헤더 테이블 : 프로그램을 로드할 때의 각 섹션의 정보를 담고있는 테이블
    - `.init` : 프로그램의 초기화 코드에서 호출될 `_init` 함수
    - `.text` / `.rodata` / `.data` / `.bss` : 재배치가능 오브젝트 파일과 동일함
      - `.text` : 코드
      - `.rodata` : 읽기 전용 데이터
      - `.data` : 초기화된 데이터
      - `.bss` : 초기화되지 않은(값이 0인) 데이터
    - `.symtab` : 심볼 테이블
    - `.debug` : 디버그 용도
    - `.line` : 디버깅 용도 - 소스 코드의 라인과 기계어가 매핑되어있음
    - `.strtab` : 문자열들이 저장되어있는 테이블
    - 섹션 헤더 테이블 : 섹션들에 대한 정보가 저장되어있는 테이블
    - `.rel.*` 섹션들은 참조 재배치가 완료되었으므로 필요하지 않다.
    
2. 세그먼트 헤더 테이블과 로드
    - 프로그램을 로드할 때는 섹션 단위가 아닌 세그먼트 단위로 메모리에 올려놓게 된다.
    - 세그먼트는, 
    링커 관점이 아닌 로더 관점에서
    메모리에 배치할 영역을 나타내는 단위이다.
    (섹션과는 관점이 다르다.
    섹션 : 링커 / 세그먼트 : 로더)
    - 세그먼트 헤더 테이블에는,
    각 세그먼트가 어느 주소부터 시작되며, 파일의 어디서부터 어디까지가 메모리에 올라가며,
    어떤 권한을 가지고있는지(r/w/x) 등
    로드에 필요한 정보들이 저장되어있다.
    - 세그먼트 헤더 테이블의 각 필드는,
      - `p_type` : 세그먼트의 종류
      - `p_offset` : 파일에서 해당 세그먼트 데이터가 시작하는 위치
      - `p_vaddr` : 세그먼트의 가상 주소
      - `p_filesz` : 파일에서 가져올 데이터 크기(`p_memsz`와 다름)
      - `p_memsz` : 메모리에서 차지할 크기(`p_filesz`와 다름)
      - `p_flags` : 접근 권한(r/w/x)
      - `p_align` : 정렬 조건
    - 이 정도가 있고,
    - 로더는 이 정보들을 이용해 실행 파일의 세그먼트를 적절한 가상 메모리 영역에 배치한다.

### 느낀 점 & 배운 점

이번 파트는 사실상 기존의 오브젝트 파일과 다른 점은

- 재배치가 완료되었으므로 `.rel.*`(재배치 엔트리)이 필요 없음
- 프로그램 초기화 시 호출되는 `_init`이 들어가있는 `.init`이 있음
- 로더가 사용할 세그먼트 헤더 테이블이 있음

이 세 가지 뿐이야.

첫 번째부터 살펴보자면,
일단 실행가능 오브젝트 파일(실행 파일)은 재배치가 끝났기 때문에
재배치를 위한(수정할 참조를 적어놓은) `.rel.*`은 필요없게 되어서
`.rel.*` 섹션들은 필요가 없어져.

두 번째도 살펴보자면,
실행 파일은 결국 실행을 위한 파일이기 때문에
프로그램 초기화에 관련한 `_init` 함수가 필요하게 되어서,
`.init` 섹션이 추가로 생겨.

세 번째도 살펴보자면,
결국 실행 파일의 일부분(실행 파일에서 메모리에 적재되지 않는 부분도 있음)이 
메모리에 적재될 때의(로드될 때의) 속성을 저장해놓을 필요가 있기 때문에
(각 세그먼트에는 접근 권한 / 시작 주소 / 오프셋 등의 속성이 있고,
이 속성들을 고려해서 각 세그먼트가 메모리에 적재됨)
세그먼트 헤더 테이블이 필요한거지.

그리고 여기서 세그먼트라는 개념이 처음 나오는데
그냥 로더 관점에서 메모리에 적재하는 단위라고 보면 편해.
물론 속성도 있고.
해당 세그먼트가 어떤 타입인지 / 오프셋을 기준으로 몇 바이트를 읽어와서 적재해야 하는지
/ 메모리는 얼마를 확보해야 하는지 / 첫 주소가 어떻게 되는지 / 접근 권한이 어떻게 되는지
등등에 대한 속성이야.

## 2. Loading Executable Object Files - 실행가능 오브젝트 파일의 로딩

### 정리

1. 로더
    - 실행가능 오브젝트 파일(실행 파일)을 실행해주는 프로그램이다.
    - 로더는 디스크에 있는 실행가능 오브젝트 파일의 코드와 데이터를 메모리로 복사한 다음,
    프로그램의 진입점(첫 번째 명령어)으로 점프해서 프로그램을 실행시킨다.
      - 이렇게 프로그램을 메모리로 복사한 후 실행하는 과정을
      로딩이라고 한다.

### 느낀 점 & 배운 점

이번 파트는 상당히 간단했어.

2. 프로그램의 진입점으로 점프해서 프로그램을 실행시키는

프로그램이야.
