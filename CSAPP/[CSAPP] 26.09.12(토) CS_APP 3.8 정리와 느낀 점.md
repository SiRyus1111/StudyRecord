## 1. Basic Principles - 기본 원칙

### 정리

1. 배열은 기본적으로 첫 원소의 주소를 나타내는 포인터로 구성되어있고,
총 `L * N` 바이트의 크기를 가진다.
(`L`은 배열에 담긴 원소의 크기)
(`N`은 배열의 원소 갯수)

2. 배열은 각 인덱스에 `첫 원소의 주소 + L * index`의 형태로 접근한다.
    - 즉, `%rdx`에 배열의 첫 원소의 주소가,
    `%rcx`에 인덱스가 저장되어있고,
    원소의 크기가 `4`라면,
    `(%rdx, %rcv, 4)`로 접근할 수 있다.

### 느낀 점 & 배운 점

솔직히 이번 챕터는 그냥
기존에 알던 지식들을 다시 나열해주는 느낌이었어.

근데 솔직히 이거 코딩 해본사람이면 다 알만한 지식들이라..

1. C언어에서 배열은 첫 원소의 주소를 나타내는 포인터로 동작하고,
총 `L * N` 크기이다.
(`L`은 배열의 각 원소의 크기)
(`N`은 배열의 크기(인덱스의 수))
2. 배열의 각 원소에 접근하려면 `첫 원소의 주소 + L * index`의 주소에 접근하면 된다.

## 2. Pointer Arithmetic - 포인터 연산

### 정리

1. C언어의 포인터 연산
    - C언어의 포인터 연산은
    포인터가 참조하고 있는 자료형의 크기가 어느정도인지에 따라
    실제 참조하는 메모리 주소가 달라진다.
      - `p + i`(포인터 연산) = `p + L * i`(실제 메모리 주소)
      
2. 포인터에 대한 역참조(`*p`)는 데이터의 주소에 대한 역참조(`*&data`)와 같다.
    - 그렇기 때문에 배열 인덱스 참조(`A[i]`)는 포인터 역참조(`*(A + i)`)와 동일하다.

### 느낀 점 & 배운 점

솔직히 이번 챕터도 상식을 장황하게 늘어놓은 기분이었어.

그냥

1. 포인터 연산은 `i * 데이터 크기`만큼 실제 주소가 움직인다.
2. `*p`와 `*&data`는 같기 때문에 포인터 연산 후 역참조와 인덱스 참조가 동일하다.

이게 끝임..

+@로
인덱스 참조는 실제 어셈블리에서
`*(p + i)`, 
즉 `(p, i, L)`로 구현된다는 것 정도?

그리고 예시도 나오긴 하는데,
나한테는 너무 당연하게 여겨지는 그런 예시라..

## 4. Fixed-Size Arrays - 고정 크기 배열

### 정리

1. 고정 크기 배열은 열의 갯수 / 한 원소의 바이트 수(`L`)이 고정되어있기 때문에
최적화할 수 있다.
    - 기본적으로, 이중 배열에 접근할 때 `p + (i * 열의 갯수 + j) * L`을 계산하지 않고,
    이미 열의 갯수와 `L`이 컴파일 시점에 고정되므로
    (예시로 *열의 갯수 : 16, `L` : 4*라고 할 때)
    `p + (i * 16 + j) * 4` = `p + i * 64 + j * 4`로 미리 바꿀 수 있다.
    - 그렇다면, 인덱스를 증가시킬 때 마다 계속 주소를 새로 계산하지 않고
    미리 `i` / `j`를 가리키는 포인터를 둔 후
    `i`는 `64`만큼 / `j`는 `4`만큼씩 증가시키는 것만으로
    간단하게 인덱스를 증가시킬 수 있다.

### 느낀 점 & 배운 점

솔직히 이번 파트는 좀 이해하기 어려웠는데,
결국 요약하면 이거야.

> 고정 크기 배열은 배열의 크기와 한 원소의 크기가
> 컴파일 시점에 고정이라
> 그 두 가지를 상수로 둠으로써
> 배열 원소의 주소 계산을 상수 기반의 단순한 포인터 연산으로 변환할 수 있다.

배열의 크기라는건,
1차원 배열이든 2차원 배열이든 고정되는건데,
책에서 든 예시는 좀 더 주소 계산이 복잡한 2차원 배열로 든 것 같아.

`p + i * L`보다
`p + (i * 열의 갯수 + j) * L`이 더 상수로 넣을 것도 많고
변수도 많아서 예시를 들기가 쉬웠나봐.

근데 결국 열의 갯수랑 `L`이 상수다보니까,
`i` / `j`를 각각 1씩 증가시킨다면
`열의 갯수 * L` / `L`만큼 주소를 증가시키면 되다 보니까..

근데 솔직히 이해는 잘 안돼..

그냥 고정 크기 배열은
특히 배열의 크기(특히 2차원 배열의 한 행의 크기)가 상수인지라
행과 열을 이동할 때 필요한 값을 상수로 계산해두고
굳이 `p + (i * 열의 갯수 + j) * L`를 계속 계산하지 않고
`+ L` / `+ 열의 갯수 * L`을 해서
단순한 포인터 연산으로 바꿀 수 있다는거지.

## 5. Variable-Size Arrays - 가변 크기 배열

### 정리

1. C언어에서 가변 크기 배열(특히 2차원 이상)을 선언하려면
`A[n][m]`에서 `n` / `m`이 먼저 정의되어있어야 한다.
2. 가변 크기 배열은 고정 크기 배열과 다르게
`p + (i * m + j) * L`에서 열의 갯수를 나타내는 `m`이 사전에 정해져있지 않으므로
`i * m`을 구하는 과정이 달라진다.
   - 기존의 고정 크기 배열에서는 `m`이 상수였어서
   `m * i`를 구하는 데에 다양한 최적화가 가능했지만(`m`을 미리 알고 있었으므로)
   가변 크기 배열의 `m`은 고정되어있지 않으므로 `m * i`를 구할 때 곱셈 명령어를 써야 한다.
   - 결국, 순서는 
   1. `m`과 `i`를 곱해서 `m * i`를 구한다.
   2. 거기에다 `j`를 더해서 인덱스를 구한다.(`(i * m + j)`)
   3. 원소 크기(`L`)를 곱하고 배열의 첫 주소를 더해 최종 주소를 구한다.
   - 이렇게 된다.

### 느낀 점 & 배운 점

이번 파트는 고정 크기 배열과의 차이로 보면 잘 읽히는 것 같아.

|차이점|고정 크기 배열|가변 크기 배열|
|---|---|---|
|열의 개수(`m`)|컴파일 시점 상수|실행 시간 값|
|행 간격(`m * L`)|컴파일 시점에 결정됨|실행 중 계산해야함|
|성능 / 특징|상수 기반 주소 계산 최적화 가능|약간의 곱셈 비용이 발생함 / 대신 유연함|

결국 핵심적인 차이는
열의 개수를 컴파일 시점에 알 수 없기 때문에,
열의 개수가 상수가 아니라서 `i * m` / `m * L`을 구하는데 
곱셈 명령어를 사용해야 한다는 점이라고 할 수 있어.

좀 더 정확히 설명해보자면, `m`을 컴파일 시점에 알 수 없으니
실행 시간(런타임)에 들어오는 `m`을 얻어서 실행 시간에 계산해야한다.
라고 할 수 있겠네.
(열의 개수를 상수로 알 수 없으니 특정 수에서만 성립하는 최적화를 시도할 수 없음)

## 6. 요약

1. 배열은 일반적으로 첫 원소의 주소(포인터)를 가지고
`원소의 수 * 한 원소의 크기`의 크기를 가진다.
2. (1차원) 배열의 각 원소에는 `첫 주소 포인터 + 인덱스 * 한 원소의 크기`의 형태로 접근한다.
3. 포인터 연산은 `p + index * 한 원소의 크기`로 실행된다.
4. `A[i]`는 어셈블리에선 포인터 연산의 형태로, `base + index * L`의 형태로 실행된다.
5. (2차원) 배열은 오른쪽 인덱스(행)를 우선으로 메모리에 적재된다.
6. (2차원) 배열의 각 원소에는 `첫 주소 포인터 + (i * 열의 갯수 + j) * 한 원소의 크기` 형태로 접근한다.
7. 고정 크기 배열과 가변 크기 배열의 차이는
배열의 크기 정보가 컴파일 시점에 정해지는가 / 정해지지 않는가이다.
8. 특히 다중 배열에서 이 사실이 크게 영향을 준다.
열의 갯수를 알아야 주소를 계산할 수 있는데,
이 열의 갯수가 컴파일 시점에 주어지지 않아
고정 크기 배열에 적용할 수 있는
열의 갯수가 상수여서 가능한 최적화를 적용하지 못한다.
