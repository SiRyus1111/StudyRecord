## 1. Condition Codes - 조건 코드

### 정리

1. 조건 코드란?
    - 정수 레지스터 말고도, CPU는 단일 비트의 조건 코드라는 레지스터를 가지고 있다.
    - 조건 코드란, 가장 최근의 산술 / 논리 연산의 특성을 나타내는 레지스터라고 할 수 있다.
      - Carry Flag(`CF`) : 부호없는 정수의 연산에서 최상위 비트가 올림 / 빌림이 발생했는지 나타냄
      - Zero Flag(`ZF`) : 연산한 결과가 0인지를 나타냄
      - Sign Flag(`SF`) : 연산한 결과가 음수인지를 나타냄
      - Overflow Flag(`OF`) : 2의 보수의 연산에서 오버플로우가 발생했는지 나타냄
    - `leaq` 명령어는 주소 계산에 사용되도록 설계된 명령어이기 때문에
    어떤 조건 코드도 변경하지 않음.
    - 각 연산들의 특수한 플래그 동작
      - 논리 연산의 경우, `CF` / `OF`은 `0`으로 설정됨.
      - 시프트 연산의 경우, `CF`는 마지막으로 밀려져 나간 비트의 값이 저장되고, 
      `OF`는 `0`으로 설정됨.
      - `inc` / `dec` 명령어는 `OF` / `ZF`를 설정하지만 `CF`는 변경되지 않음.
      
2. 조건 코드를 설정하는 명령어
    - 이 명령어들은 destination을 설정하지 않고
    조건 코드만 설정한다.
    - `cmp S1, S2` : compare
      - `S2 - S1`를 기반으로 조건 코드를 설정한다.
        - 즉, 두 오퍼랜드가 같을 경우 `zf`를 설정한다.
      - `cmpb S1, S2` : compare byte
      - `cmpw S1, S2` : compare word
      - `cmpl S1, S2` : compare double word
      - `cmpq S1, S2` : compare quad word
    - `test` : test
      - `S1 & S2`를 기반으로 조건 코드를 설정한다.
        - 오퍼랜드에 대해 어떤 조건을 가지고 있는지 테스트하는 용도로 쓰인다.
        (`testq %rax, %rax`같은 느낌)
        - 오퍼랜드 중 하나가 테스트할 비트를 지정하는 마스크 역할을 한다.
      - `testb S1, S2` : test byte
      - `testw S1, S2` : test word
      - `testl S1, S2` : test double word
      - `testq S1, S2` : test quad word

### 느낀 점 & 배운 점

뭔가 이번 파트는 연산을 했을 때
해당 연산의 결과의 성질을 파악하는 데 쓰이는 것들을 배운 것 같아.

- 연산의 결과가 0이라는 것을 나타내는 `ZF`(zero flag)
- 부호없는 정수의 연산에서 최상위 비트 이상으로 올림됐다는 것을 나타내는 `CF`(carry flag)
- 연산한 결과가 음수인지를 나타내는 `SF`(sign flag)
- 2의 보수 정수의 연산에서 오버플로우가 발생했다는 것을 나타내는 `OF`(overflow flag)

이런 것들로 해당 연산의 결과가 어떻게 나왔는지를 판별할 수 있는거지.

그리고 이번에 해당 연산의 결과를 저장하지 않고
단순히 해당 연산의 결과에 대한 조건 코드만 나타내는 명령어(`cmp` / `test`)를 배웠는데,

이건 어떻게 설명은 잘 안 나오지만..
딱 상태 플래그만 세팅해서
지난 연산의 상태 플래그를 보고 동작하는 코드가 있을 때
요긴하게 써먹을 수 있는 연산들인 것 같았어..

뒤의 점프 / 조건부 값 설정 / 조건부 이동에서 나오겠지?ㅋㅋ

예를 들어,
`cmpq S1, S2`가 `S2 - S1`을 실행해서 업데이트한 조건 코드에 따라,
`ZF` / `SF` / `OF`를 보고
`S1 == S2` / `S1 > S2` / `S1 < S2`같은 조건을 판별할 수 있는 거겠지.

`test`도 비슷해.
이건 그냥 값을 변경하지 않고 단일 오퍼랜드가 어떤 조건 코드를 설정하는지 
알아보기 위한 연산이라고 생각해.
거기에다가 마스크도 얹을 수 있는거고.

결국 C언어에서의 조건문의 기반이 이런 어셈블리 명령어라는걸 알 수 있는 것 같아.

## 2. Accessing the Condition Codes - 조건 코드에 접근하기

### 정리

1. 세팅된 조건 코드를 사용하는 법 1
    - `cmp` 등의 조건 코드를 설정하는 명령어가 설정한 조건 코드를 기반으로
    조건 코드의 특정 조합에 따라 단일 바이트 레지스터 / 메모리를 0 / 1로 설정한다.
    - 이런 역할을 수행하는 명령어를 통칭해서 `set` 명령어라고 부른다.
    - `set` 명령어들은 suffix(접미사)로 피연산자 크기를 나타내지는 않고,
    조건을 나타낸다.
    - 예 : `setl` : set long word가 아닌 set less
    
2. `set` 명령어들
    - |명령어|효과|나타내는 상태|
    |---|---|---|
    |`sete D` / `setz D`| `ZF -> D`| 일치(Equal) / 0(Zero) |
    |`setne D` / `setnz D`| `~ZF -> D` | 일치하지 않음(Not Equal) / 0이 아님(Not Zero)|
    ||||
    |`sets D`| `SF -> D` | 음수(sign)임 |
    |`setns D` | `~SF -> D` | 음수(Not Sign)가 아님 |
    ||||
    |`setg D` / `setnle D`|`~(SF ^ OF) & ~ZF -> D`| 더 큼(Greater)(`signed >`)|
    |`setge D` / `setnl D`|`~(SF ^ OF) -> D`| 더 크거나(Greater) 같음(Equal)(`signed >=`)|
    |`setl D` / `setnge D`|`SF ^ OF -> D`| 더 작음(Less)(`signed <`) |
    |`setle D` / `setng D`|`(SF ^ OF)` \| `ZF`| 더 작거나(Less) 같음(Equal)(`signed <=`) |
    ||||
    |`seta D` / `Setnbe D`|`~CF & ~ZF -> D`|더 큼(Above)(`unsigned >`)|
    |`setae D` / `setnb`| `~CF -> D` |더 크거나(Above) 같음(Equal)(`unsigned >=`)|
    |`setb D` / `setnae D`| `CF -> D`|더 작음(Below)(`unsigned <`)|
    |`setbe D` / `setna D`|`CF` \| `ZF -> D`|더 작거나(Below) 같음(Equal)(`unsigned <=`)|

### 느낀 점 & 배운 점

이거 뭔가 개념은 간단한데,
실제 조건 코드로 대소 관계를 도출해내는게 너무 어려웠어.

`set` 명령어 = 그냥 조건 코드로 대소 관계를 도출해주는 명령어

라고 이해했는데,
그 `set` 명령어들이 어떻게 조건 코드로 대소 관계를 도출해주는지를 생각해보는게 어려웠어.

특히 처음에는 어떻게 `CF`만으로 unsigned integer(부호없는 정수)의 대소관계를 알 수 있는지
도저히 모르겠었음..

이거 한번 설명해볼게.

일단, `cmp A, B` 명령어로 나온 결과는
`B - A`에서의 조건 코드겠지?

나는 이 정도로 도출해봤어.
(글 지저분함 주의)

- signed 기준
  - `B - A`의 결과가 0, 즉 `ZF = 1`이면 두 수가 같다고 할 수 있고,
  - `B - A`의 결과가 `OF = 0`(오버플로우 X) / `SF = 1`(음수)이면 
  두 수를 뺐을 때 오버플로우 없었고 음수가 나왔으니
  `A`가 더 컸다는 말이므로 
  `B < A`라고 할 수 있고,
    - (오버플로우가 발생한 경우에도(`OF = 1`)
    결과가 양수(`SF = 0`)라면 결국 음의 오버플로우(결과는 음수)라는 것임)
  - `B - A`의 결과가 `OF = 0`(오버플로우 X) / `SF = 1`(음수)이거나 `ZF = 1`(0)이면
  두 수를 뺐을 때 오버플로우 없었고 음수 / 0이 나왔으니 
  두 수가 같거나 `A`가 더 컸다는 말이므로
  `B <= A`라고 할 수 있는데,
    - (오버플로우가 발생한 경우에도(`OF = 1`)
    결과가 양수(`SF = 0`)라면 결국 음의 오버풀로우(결과는 음수)라는 것임)
  - 더 컸을 때의 경우는 해당 결과를 부정하면 된다.
    - `B > A` : `B <= A`의 부정이므로 `OF = 0` / `SF = 1`이 아니거나
    `ZF = 0`이라는 것이고,
    - `B >= A` : `B < A`의 부정이므로 `OF = 0` / `SF = 1`이 아니라는 것이다.
- unsigned 기준
  - `B - A`의 결과가 0, 즉 `ZF = 1`이면 두 수가 같다고 할 수 있고,
  - `B - A`의 결과가 `CF = 1`이라면
  빌림수가 있다는 뜻이므로
  `B < A`라고 할 수 있고,
  - `B - A`의 결과가 `CF = 1` 이거나 `ZF = 1`이면
  두 수를 뺐을 때 빌림수가 있거나 0이라는 뜻이므로
  `B <= A`라고 할 수 있는데,
  - 더 컸을 때의 경우는 해당 결과를 부정하면 된다.
    - `B > A` : `B <= A`의 부정이므로 `CF = 0`이라는 것이고,
    - `B >= A` : `B < A`의 부정이므로 `CF = 0`이고 `ZF = 0`이라는 것이다.

요약하자면,

```text
같은 경우:
    B - A가 0이 나오는 경우(ZF)
    
signed - (B < A)
    B - A가 결과적으로는(음의 오버플로우 포함) 음수가 나오는 경우(OF ^ SF)
    
signed - (B <= A)
    B - A가 결과적으로는(음의 오버플로우 포함) 음수가 나오거나 같은 경우((OF ^ SF) | ZF)
    
signed - (B >= A) / (B > A)
    앞의 두 결과를 부정하면 나옴
    
unsigned - (B < A)
    B - A에서 빌림수가 있는 경우(CF)
    
unsigned - (B <= A)
    B - A에서 빌림수가 있거나 같은 경우(CF | ZF)
    
unsigned - (B >= A) / (B > A)
    앞의 두 결과를 부정하면 나옴
```

이 정도라고 할 수 있겠네.

결국 점프 명령어를 알기 위한 기반 지식은 이렇게 정리돼.

1. 가장 최근에 한 연산의 결과와 상태를 조건 코드의 형태로 저장한다.
    - `CF` : carry flag, 최상위 비트 이상의 올림 / 빌림이 발생한 경우 활성화
    - `ZF` : zero flag, 0인 경우 활성화
    - `SF` : sign flag, 음수인 경우 활성화
    - `OF` : overflow flag, 오버플로우가 발생한 경우 활성화
2. 그 조건 코드만 갱신하는 `cmp`(`S2 - S1`) / `test`(`S1 & S2`) 명령어가 있다.
3. signed 정수의 비교는 SF, OF를 주로 사용하고 unsigned 정수의 비교는 CF를 주로 사용하며
두 수가 같은지 비교는 ZF를 사용한다.

이 정도가 되겠네.

## 3. Jump Instructions - 점프 명령어

### 정리

1. 점프 명령어
    - 특정 레이블(위치)로 코드의 실행 위치를 이동 시키는 명령어라고 할 수 있다.
    - 어셈블러가 목적 파일을 생성할 때,
    레이블이 저장된 모든 명령어의 주소를 파악하고
    점프 대상인 명령어의 주소를 점프 명령어의 일부로 인코딩한다.
    - |명령어|점프 조건|설명|
    |---|---|---
    |`jmp Label`|무조건|직접 점프|
    |`jmp *Operand`|무조건|간접 점프|
    ||||
    |`je Label` / `jz Label` |`ZF`|일치함(Equal) / 0임(Zero)|
    |`jne Label` / `jnz Label`|`~ZF`|일치하지 않음(Not Equal) / 0이 아님(Not Zero)|
    |`js Label`|`SF`|음수임(Sign)|
    |`jns Label`|`~SF`|음수가 아님(Not Sign)|
    ||||
    |`jg Label` / `jnle Label`|`~(SF ^ OF) & ~ZF`|더 큼(Greater)(`signed >`)|
    |`jge Label` / `jnl Label`|`~(SF ^ OF)`|더 크거나(Greater) 같음(Equal)(`signed >=`)|
    |`jl Label` / `jnge Label`|`SF ^ OF`| 더 작음(Less)(`signed <`)|
    |`jle Label` / `jng Label`|`(SF ^ OF)` \| `ZF`|더 작거나(Greater) 같음(Equal)(`signed <=`)|
    ||||
    |`ja Label` / `jnbe Label`|`~CF & ~ZF`|더 큼(Above)(`unsigned >`)|
    |`jae Label` / `jnb Label`|`~CF`|더 크거나(Above) 같음(Equal)(`unsigned >=`)|
    |`jb Label` / `jnae Label`|`CF`|더 작음(Below)(`unsigned <`)|
    |`jbe Label` / `jna Label`|`CF` \| `ZF`|더 작거나(Below) 같음(Equal)(`unsigned <=`)|
    - `set`과 상당히 조건이 비슷하다.(일치 / 음수 / 대소 비교)
    - 크게 다른 점이라면,
    무조건 점프가 있다는 것이 있다.
    - 무조건 점프는 레이블을 이용한 점프(직접 점프) 뿐만 아니라
    점프 대상 명령어의 주소가 레지스터나 메모리 위치에서 읽혀지는 점프(간접 점프)일 수도 있다.
    - 조건 점프는 직접 점프로만 수행될 수 있다.

### 느낀 점 & 배운 점

결국, 이거 특정 레이블로 점프한다는 것만 다르지
이전에 `set`에서 봤던 규칙이 그대로 적용되는 것 같아.

그 레이블의 명령어의 주소를 다 파악해놓고 점프 명령어의 일부로 인코딩..

근데 이건 이번 파트의 주제는 아니니까 넘어가자.

## 4. Jump Instruction Encodings - 점프 명령어 인코딩

### 정리

1. 점프 명령어에서, 레이블은 어떻게 기계어로 인코딩될까?
    - 점프 명령어에서 사용하는 레이블은 어셈블러 / 링크에서
    별도의 주소로 점프 명령어와 함께 인코딩된다.
    - 인코딩 방식은, 주로 PC(Program Counter) 상대 주소 방식을 사용한다.
      - 현재 명령어와 점프로 실행할 명령어의 상대적 위치를

      실제 목적지를 계산한다는 점이다.
      (`현재 명령어 주소 + 오프셋 아님`)
    - 다른 인코딩 방식으로는, 절대 주소 방식으로,
    말 그대로 절대적인 주소를 4바이트로 인코딩한다.

## 5. Implementing Conditional Branches with Conditional Control - 조건문 구현 : 조건부 분기

### 정리

1. C언어의 조건문을 기계어로 나타내는 일반적인 방법은 조건 점프 / 무조건 점프를 조합하는 것이다.
    - C언어의 `goto`문을 생각하면 된다.
      - 조건이 맞는다면 `goto`를 사용해서 조건이 맞을 때의 레이블로 이동하고,
      조건이 맞지 않는다면 `goto`를 사용해서 조건이 맞지 않을 때의 레이블로 이동하는 것이다.
      ```c
      long gotoExemple(long a, long b) {
          long result = 0;
          if (a > b) {
              goto Label1; // 조건이 맞는다면 Label1로 점프
          }
          goto Label2;
          
      Label1: // 조건이 맞는다면 여기로 점프
          result = a + b;
          return result;
      
      Label2: // 조건이 맞지 않는다면
          result = a - b;
          return result; 
      
      }
      ```
      - 어셈블리 코드로는,
      ```x86asm
      # a : %rdi
      # b : %rsi
      gotoExemple:
          cmpq %rsi, %rdi
          jg .Label1
          jmp .Label2
      .Label1
          addq %rsi, %rdi
          movq %rdi, %rax
          ret
      .Label2
          subq %rsi, %rdi
          movq %rdi, %rax
          ret
      ```
      - 이렇게 작성될 수 있다.
      - `goto`를 사용하여 작성된 코드와
      어셈블리에서 구현된 조건문이 상당히 비슷하다.
      
2. 실제 어셈블리에서의 기본적인 조건문 구현
    - 기본적인 형태는,
    이런 형태이다.
    - 조건 : `test` / `cmp` 등으로 나온 조건 코드
    ```c
        t = 조건;
        if (!t) {
            goto false;
        }
        // 조건이 맞는다면 실행할 코드
        goto done;
        
    false:
        // 조건이 맞지 않는다면 실행할 코드
    done:
    ```
    - 조건이 맞지 않는다면 해당 분기의 코드로 점프하고,
    조건이 맞다면 계속 코드를 실행한다.

### 느낀 점 & 배운 점

이번 챕터는 상당히 간단했어.

특히 어셈블리의 조건 점프를 C언어의 `goto`문에 대응시킨건
진짜로 어셈블리의 점프를 이해하기에 좋은 아이디어인 것 같아.

애초에 `goto`가 어셈블리의 '레이블로 점프하는' 느낌으로 쓰이던게 아닐까 싶어.

어쨌든 요약하면,

1. 어셈블리의 조건 점프를 이용한 조건문의 구현은
조건 점프 / 무조건 점프 명령어로 구현될 수 있다.
2. 어셈블리의 조건 점프는 C언어의 `goto`문 처럼 볼 수 있는데,
마치 `cmp` / `test`로 조건 코드를 설정한 후
조건 점프 명령어로 조건이 맞는지 / 아닌지에 따라
코드를 계속 진행할지 / 분기에 따라 선택할지가 갈리는 것이다.

이 정도라고 할 수 있겠네..

문제는 그 다음의 `cmov`를 이용한 조건문 구현겠지..
그냥 책 한바닥에 텍스트밖에 없는데 두렵다..

## 6. Implementing Conditional Branches with Conditional Moves - 조건 이동을 이용한 구현

### 정리

1. 기존의 일반적인 조건문 구현 방식인 조건에 따라 실행 경로를 선택하는 방식은
간단하지만 비효율적일 수 있다.
   - 분기 예측(Branch Prediction) / 파이프라이닝 성능 등..
2. 그래서 조건에 따라 실행 경로를 선택하는 것이 아닌
두 경로의 값을 미리 계산해놓은 뒤 조건에 따라 계산된 값을 선택하는 전략을 취할 수 있다.
   - 쉽게 설명하면, 삼항 연산자(`T ? A : B`)와 비슷하다고 할 수 있다.
   - 이러면 두 값을 모두 계산하기 때문에 분기 예측 실패로 인한 오버헤드를 줄일 수 있다.
     - 정확히는, 분기 예측 성공 / 실패에 따른 클럭 수가 들쑥날쑥하지 않고,
     일정한 클럭 수 내로(분기 예측 실패했을 때보다는 적은) 실행이 된다는 것이다.
3. `cmov` - 조건 이동 명령어(Conditional Move)
    - 말 그대로, 조건에 해당할 경우 이동 명령어가 수행되지만,
    조건에 해당되지 않을 경우 이동 명령어가 수행되지 않는 명령어이다.
    - 조건에 해당하는 경우를 미리 `R`에 올려놓고,
    조건에 해당하지 않을 때 `R`을 해당 명령어로 교체되게 해놓는 것으로
    조건문을 구현할 수 있다.
    - |명령어|이동 조건|설명|
    |---|---|---|
    |`cmove S, R` / `cmovz S, R`| `ZF` | 일치함(Equal) / 0임(Zero) |
    |`cmovne S, R` `cmovnz S, R`| `~ZF` | 일치하지 않음(Not Equal) / 0이 아님(Not Zero)
    |`cmovs S, R`| `SF`| 음수임 (Sign)|
    |`cmovns S, R`| `~SF`| 음수가 아님(Not Sign)|
    |`cmovg S, R` `cmovnle S, R`|`~(SF ^ OF) & ~ZF`| 더 큼(Greater)(`signed >`)|
    |`cmovge S, R` `cmovnl S, R`|`~(SF ^ OF)` | 더 크거나(Greater) 같음(Equal)(`signed >=`)|
    |`cmovl S, R` `cmovnge S, R` |`SF ^ OF` |더 작음(Less)(`signed <`)|
    |`cmovle S, R` `cmovng S, R`|`(SF ^ OF)` \| `ZF` |더 작거나(Less) 같음(Equal)(`signed <=`)|
    |`cmova S, R` `cmovnbe S, R`|`~CF & ~ZF` |더 큼(Above)(`unsigned >`)|
    |`cmovae S, R` `cmovnb S, R`| `~CF` |더 크거나(Above) 같음(Equal)(`unsigned >=`)
    |`cmovb S, R` `cmovnae S, R`| `CF` | 더 작음(Below)(`unsigned <`)|
    |`cmovbe S, R` `cmovna S, R` | `CF` \| `ZF` |더 작거나(Below) 같음(Equal)(`unsigned <=`)|
    
4. 조건 이동 명령어를 이용한 조건문의 구현
    - 앞에서 설명했듯,
    먼저 조건이 맞는 경우와 안 맞는 경우에 대한 값을 전부 계산해두고,
    조건이 맞는 경우의 값을 미리 `R`에 저장해둔 후,
    조건이 맞지 않는 경우에 `R`을 조건이 맞지 않는 경우의 값으로 교체하면 된다.
    ```c
        v = 조건이_맞는_경우의_값;
        ve = 조건이_맞지_않는_경우의_값;
        t = 조건;
        if (!t) v = ve; // cmov 사용
    ```
    
5. 조건 이동 명령어를 이용한 조건문의 구현이 불가능한 경우
    - 결국, 두 경우의 값을 계산할 때 에러 / 사이드 이펙트가 발생할 수 있는 경우이다.
      - 예를 들어, `nullptr`인 포인터가 역참조될 수 있다거나..
    - 그리고, 조건 이동이 무조건 유리한 것도 아니다.
    - 애초에 두 경우의 값을 계산하는데에 분기 예측 실패의 오버헤드보다
    더 많은 연산이 필요하게 되는 경우에는 조건 점프를 사용하는게 좋을 수도 있다.

### 느낀 점 & 배운 점

이번에는 뭔가 색다른 방식의 조건문 구현을 배운 것 같아.
솔직히 조건 점프로 조건문을 구현하는건 그리 떠올리기 어렵지 않겠지만,
두 경우의 값을 모두 계산해놓고 조건에 따라 그 값 중 하나를 선택하는 그런건
솔직히 이게 직관적이긴 한데 떠올리긴 어려운 아이디어니까..

결국 이번에 배운건,

1. 왜 조건 이동이 필요한가
    - 분기 예측 실패에 대한 오버헤드를 줄이려고.
    - 조건 이동은 제어 흐름을 분기시키지 않기 때문에
    분기 예측 실패로 인한 오버헤드를 피할 수 있다.
2. 어떻게 조건 이동을 사용해서 조건문을 구현할 수 있는가
    - 일단 대상이 되는 레지스터에 조건 만족 시의 값을 넣어놓고,
    조건이 만족하지 않는 경우에만 해당 값을 조건이 만족하지 않을 시의 값으로 교체한다.
    - 어쨌든 특정 조건을 만족한 경우에 특정 조건의 값으로
    해당 값을 교체한다.
3. 조건 이동으로 구현한 조건문의 한계는 어떠한가
    - 결국 미리 두 값을 계산해야하기 때문에
    두 값을 계산할 때 에러나 사이드 이펙트가 발생할 수 있다면
    조건 이동으로 구현한 조건문을 사용할 수 없다.
    - 그리고, 두 값을 미리 계산해놓는게 분기 예측 실패보다 더 오래 걸린다면,
    조건 이동이 아니라 조건 점프가 더 유리할 수도 있다.
    
이 정도라고 할 수 있겠네.

결국 요약하면,

> 분기 예측의 실패 오버헤드를 피하기 위해
> 각 분기의 값을 미리 계산해놓고 조건에 따라 값을 선택하는 식으로 조건문을 구현할 수도 있다.
> 하지만, 값을 계산할 때 에러 / 사이드 이펙트가 발생할 수 있거나
> 계산 비용이 너무 크다면
> 점프를 이용해 조건문을 구현하는게 더 적절하다.

## 7. Loops - 반복문

### 정리

1. `do-while`문의 어셈블리 구현
    - `do-while`문은 먼저 반복문 안의 코드를 실행한 후
    조건을 검사하고
    조건이 참이라면 계속 반복하는 반복문이다.
    - 다음과 같은 형태로 어셈블리로 구현될 수 있다.
    ```c
    loop:
        // 실행될 코드
        t = 조건;
        if (t) {
            goto loop;
        }
    ```
    - 즉, `do-while`문은 일단 코드를 실행한 후
    조건을 검사하고 조건이 참이라면 반복문의 처음으로 점프하는 것으로
    구현될 수 있다.
2. `while`문의 어셈블리 구현 1(Jump to Middle)
    - `while`문은 먼저 조건을 검사한 후
    조건이 참이라면 반복문 안의 코드를 실행하고
    조건이 거짓이라면 반복문을 종료하는 반복문이다.
    - 중요한 것은, 반복문 진입 시 이미 조건이 거짓이라면,
    반복문을 실행하지 않는 것이다.
    - 다음과 같은 형태로 어셈블리로 구현될 수 있다.
    ```c
        goto test;
    loop:
        // 실행될 코드
    test:
        t = 조건;
        if (t) {
            goto loop;
        }
    ```
    - 조건을 먼저 확인하고
    조건이 맞지 않는 경우 반복문을 탈출하기 위해
    조건을 테스트하는 코드를 루프 뒤에 적어서
    조건이 맞지 않는 경우 점프를 하지 않고 그대로 실행하면
    바로 `while`문을 빠져나갈 수 있게 하는 것이다.
    - 그리고 조건이 맞다면 `while`문 내부의 코드를 실행하면 된다.
    - `while`문 내부의 코드가 실행된 후
    다시 조건을 테스트하는 코드가 실행된다.
3. `while`문의 어셈블리 구현 2(Guarded do)
    - 전용 테스트 코드를 이용하는 것 말고도,
    처음 반복문에 진입할 때 조건 검사를 한 후
    `do-while`문과 같은 형태를 사용해서 `while`문을 구현할 수 있다.
    ```c
        t = 조건;
        if (!t) {
            goto done; // 첫 반복 조건이 성립되지 않았을 경우에 반복문 실행하지 않음
        }
    loop:
        // 실행될 코드
        t = 조건
        if (t) {
            goto loop;
        }
    done:
    ```
4. `for`문의 어셈블리 구현
    - `for`문은 기본적으로 초기값 / 반복 조건 / 증감값의 형태로
    반복 조건이 만족될 때 까지만 반복을 하고,
    매 반복 마다 증감값에 맞춰 조건이 증감이 되는 반복문이다.
    - 결국 이 세 가지를 어셈블리로 어떻게 쪼개는지를 보면 구현이 나온다.
    ```c
    // 초기값 밖으로 빼서 while문으로 생각하기
    초기값;
    while (조건) {
        // 실행할 코드
        조건 증감;
    }
    ```
    ```c
    // jump-to-middle 방식
        초기값;
        goto test;
    loop:
        // 실행할 코드
        조건 증감;
    test:
        t = 조건;
        if (t) {
            goto loop;
        }
    ```
    ```c
    // guarded-do 방식
        초기값;
        t = 조건;
        if (!t) {
            goto done;
        }
    loop:
        // 실행할 코드
        조건 증감;
        t = 조건;
        if (t) {
            goto loop;
        }
    done:
    ```

### 느낀 점 & 배운 점

이번 챕터는 뭔가 쉬우면서 어려웠어.

일단 나, 예전에는 반복문의 기본이 `for`문이고,
그 다음이 `while`문, 제일 고급인게 `do-while`문인 줄 알았거든?

근데 어셈블리 구현을 보니까 `do-while`이 제일 기본적이네..

나 그리고 처음에는 조건 점프를 반복하는데 쓰지 않고,
무조건 점프로만 반복을 수행하면서
조건 검사를 하고 조건 점프로 그 반복을 빠져나가는 식으로 반복문이 구현된다고 생각했는데,
```c
loop:
    // 실행될 코드
    t = 조건;
    if (!t) {
        goto done;
    }
    goto loop;
done:
```
(이런 느낌으로..)

결국 쉬운 구현은 
반복할지 여부 자체를 조건 점프 명령어로 판별하게 만드는 거였어.

이번 챕터를 요약하자면,

1. `do-while`문 구현
    - 반복문의 끝에서만 조건을 검사하면 된다.
    - 반복문의 끝에서 조건 점프로 처음으로 돌아감
    - 어셈블리로 구현하기엔 제일 간단하다.
2. `while`문 구현
    - 반복 시작 전에도 조건을 검사해야한다.
    - 따로 `test` 레이블을 만들어서 조건이 맞을 때만 점프해서 반복문의 코드를 실행하게 하고,
    조건이 안 맞을 때 그냥 이후의 코드를 실행하게 해서 빠지게 하는 jump-to-middle 구현
    - 첫 조건 검사를 추가하고 `do-while`문을 그대로 써서 구현한
    guarded-do 구현
3. `for`문 구현
    - 초기값을 먼저 설정 + 조건 증감이 들어간 `while`문으로 보면 됨
    - jump-to-middle / guarded-do 둘 다 가능함

이 정도로 볼 수 있겠네.

## 8. Switch Statements - switch문

### 정리

1. `switch`문은 내부적으로 점프 테이블이라는 배열으로,
각 `case`의 인덱스마다 실행해야할 코드의 주소를 가진다.
   - 이 구조의 장점은 단순히 `if`문을 나열할 때와 다르게
   실행 시간이 `case` 수의 영향을 받지 않는다는 것이다.
   - `gcc`는 케이스의 수와 케이스의 값의 분포에 따라
   `switch`문의 어셈블리 구현 방식을 선택한다.
     - 일반적으로 케이스가 여러개(4개 이상)이고
     케이스의 값의 범위가 좁을 때 사용된다.
     - 케이스의 값 사이의 빈 공간도 테이블의 원소로 존재하기 때문이다.
   - 그리고 점프 테이블을 사용하기 전,
   인덱스 범위를 초과하지는 않는지 검사를 해야한다.
     - 인덱스 범위를 초과한다면 `default` 케이스에 해당하는 코드로 점프한다.
   - 그리고 중간에 빈 케이스들은 `default` 케이스에 해당하는 코드의 주소가 할당된다.

### 느낀 점 & 배운 점

사실상 이번 챕터는 정말 쉽게 요약할 수 있겠어.

> 어셈블리에서는 `switch`문을 구현할 때
> 각 `case`에 해당하는 인덱스를 사용해서 바로바로 점프해야할 주소를 알 수 있도록
> 점프 테이블을 사용한다.

솔직히 이게 끝 아님?

책에서는 이게 C언어로 봤을 때 어떤 느낌인지,
그리고 점프 테이블은 어셈블리에서 어떻게 생겼는지까지 보여주는데,
나는 솔직히 그건 진짜 예시라서 생략했어.

살짝 요약해보자면,
C언어로 봤을 때,
`&&`(논리 AND 연산자 아님)을 붙여서 이동해야할 코드 주소를 배열에 담고,
그 배열의 원소를 역참조해서 `goto`(점프)를 실행한다고 할 수 있겠고,
어셈블리에서는 점프 명령어에서 `*`를 붙여서 간접 점프로 해당 배열의 원소를 조회해서
점프를 한다고 할 수 있어.

`.rodata` 영역에 넣는다고 해.
