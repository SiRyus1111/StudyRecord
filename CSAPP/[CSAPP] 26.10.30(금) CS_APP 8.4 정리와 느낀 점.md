## 1. Creating and Terminating Processes - 프로세스 생성 및 종료하기

### 정리

1. 프로그래머의 관점에서의 프로세스 상태
    - 실행 : CPU에서 실행 중 OR 실행을 기다리고 있는 상태, 스케줄링 됨
    - 정지 : 프로세스의 실행이 일시 중단되어있는 상태, 스케줄링 되지 않음
      - 프로세스는 SIGSTOP 등의 정지 신호를 수신할 때 정지되며,
      SIGCONT 신호를 수신할 때까지 정지 상태를 유지하고 실행된다.
    - 종료 : 프로세스가 영구적으로 중지된 상태
    
2. `fork`(유닉스 기준)
    - `fork` 함수로 자식 프로세스를 생성할 수 있다.
    - 자식 프로세스는 부모 프로세스의 복사본이라고 할 수 있다.
    (별개의 가상 주소 공간을 가진다.)
    (세그먼트 / 힙 / 공유 라이브러리 / 사용자 스택같은 정보들이 복사된다.)
    - 자식 프로세스는 부모 프로세스의 
    모든 열려있는 파일의 파일 디스크립터에 대한 복사본을 얻게 된다.
    (부모 프로세스가 `fork`를 호출한 시점의 열려있는 파일을 읽고 쓸 수 있게 된다.)
    - 부모 프로세스와 새로 생성된 직후의 자식 프로세스 간의 가장 큰 차이점은
    PID가 다르다는 점이다.
    
3. `fork`의 특성(유닉스 기준)
    - `fork` 함수는 한 번 호출되지만
    부모 프로세스에서 한 번, 생성된 자식 프로세스에서 한 번 반환된다.
    (부모 프로세스에서는 자식 프로세스의 PID를,
    자식 프로세스에서는 일반적으로 0을 반환한다.)
    - 부모 프로세스와 생성된 자식 프로세스는 동시에 실행되는 별개의 프로세스이다.
    그래서 동시적으로 실행될 수 있다.
    - 부모 프로세스와 생성된 자식 프로세스는 별개의 프로세스라서,
    자식 프로세스 생성 직후의 자식 프로세스 상태는 부모 프로세스와 같지만
    동일한 메모리 영역을 공유하지 않는다.
    - 부모 프로세스와 자식 프로세스는 파일을 공유한다.
    자식 프로세스는 부모 프로세스의 모든 열린 파일을 상속받는다.

### 느낀 점 & 배운 점

이번에는 아는 내용이 좀 많았어.

결국,

- 프로세스는 실행(준비 상태 포함) / 정지 / 종료 상태를 가질 수 있다.
- 자식 프로세스를 생성하려면 `fork()` 함수를 사용한다.
  - `fork()` 함수는 부모 프로세스의 모든 구성 요소를
  자식 프로세스로 복사하여 다른 메모리 공간에서 실행한다.
  - 파일 디스크립터들도 그대로 복사하여,
  자식 프로세스는 부모 프로세스가 `fork()`를 호출한 시점에 열려있던 파일들을
  부모 프로세스와 공유한다.
  - `fork()` 함수는 자식 프로세스와 부모 프로세스에서 각각 반환되며,
  부모 프로세스에서는 자식 프로세스의 PID가,
  자식 프로세스에서는 일반적인 경우 0이 반환된다.
  
이게 끝이야.

그리고 이 챕터의 예시들을 읽으면서 생긴 관점이 있는데,
자식 프로세스는 부모 프로세스와 같은 코드를 그대로 이어서 실행한다는 점이야.
(하이 레벨 관점에서..)

## 2. Reaping Child Processes - 자식 프로세스 회수하기

### 정리

1. 자식 프로세스의 종료와 회수
    - 프로세스가 종료되었을 때,
    커널은 해당 프로세스를 시스템에서 즉시 제거하지 않고,
    부모 프로세스에 의해 회수될 때 까지 종료 상태로 유지한 후
    부모 프로세스가 자식 프로세스를 회수하면 자식 프로세스의 종료 상태를 부모 프로세스에 전달한 뒤
    종료된 프로세스를 최종적으로 폐기한다.
    - 아직 회수되지 않은 종료된 프로세스를 좀비(zombie)라고 부른다.
    - 오래 실행되는 프로그램의 경우, 항상 좀비 자식 프로세스를 회수해야 한다.
    (좀비 프로세스는 종료 상태더라도 시스템의 메모리를 점유하기 때문이다.)
    
2. 부모 프로세스가 먼저 종료되는 경우
    - 자식 프로세스를 남기고 부모 프로세스가 먼저 종료되는 경우,
    커널은 더 상위의 프로세스가 부모 프로세스가 되도록 조치한다.
    - 여기서 최상위 프로세스가 종료되면 어쩌나 하는데,
    PID가 1인 최상위(init) 프로세스는 절대 종료되지 않는다.
      - 해당 프로세스는 모든 프로세스의 조상이라고 할 수 있다.
      
3. 자식 프로세스가 종료될 때 까지 기다리는 함수
    - `waitpid()` 함수이다.
    - `pid_t waitpid(pid_t pid, int* statusp, int options)`
    - 해당 함수는 `std::thread`의 `join()` 함수마냥,
    자식 프로세스 중 하나 또는 여러개 종료될 때 까지 기다리고,
    자식 프로세스가 종료되면 반환되며
    종료된 자식 프로세스의 PID를 반환한다.
    (해당 시점에서 종료된 자식 프로세스는 회수되었다고 할 수 있다.)
      - 그렇기 때문에 자식 프로세스의 회수를 확정할 수 있다.
    - 호출 시점의 대기 집합에 있는
    자식 프로세스가 이미 종료된 경우,
    해당 함수는 즉시 반환되며 
    종료된 자식 프로세스의 PID를 반환한다.
    - `pid` 인자의 값에 따라 1개 뿐만 아니라
    여러 자식 프로세스의 집합(대기 집합)의 모든 프로세스가 종료될 때 까지 기다릴 수 있다.
      - `pid > 0`인 경우 해당 PID의 자식 프로세스가 종료될 때 까지 대기하며,
        - 이미 종료된 경우 바로 반환
      - `pid == -1`인 경우 해당 프로세스의 모든 자식 프로세스가 종료될 때 까지 대기한다.
        - 이미 모든 프로세스가 종료된 경우 바로 반환
    - 동기식 말고도 비동기식으로 대기할 수 있고,(`WNOHANG`)
    `pid == -1`일 때 한 프로세스만 기다릴 수도 있다.(`WUNTRACED`)
    (여러 옵션을 동시에 적용할 수도 있다.)
    - 다양한 매크로도 지원하며(`statusp`에 넣음)
    에러가 발생했을 때의 에러 조건도 있다.(`ECHILD` 등)

- `waitpid()` 함수로 회수를 확정할 수 있다.

## 3. Loading and Running Programs - 프로그램 로드하고 실행하기

### 정리

1. `execve`
    - `execve` 함수는 현재 프로세스에 새 프로그램을 로드하고 실행하는 함수이다.
    - `int execve(const char* filename, const char* argv[], const char* envp[])`
    - `filename`의 실행가능 오브젝트 파일을 로드 -> 실행하고,
    인자목록 `argv` / 환경 변수 목록 `envp`를 사용한다.
    - `filename`의 파일을 찾을 수 없는 경우같은 오류가 발생한 경우에만 반환되고,
    일반적으로는 반환되지 않는다.
    - `argv`는 널문자로 종료되는 포인터 배열이다.(인자목록)
      - `argv[0]`은 실행가능 오브젝트 파일의 이름을 가리키는 포인터로 고정되어있다.
      (관례)
    - `envp`는 널문자로 종료되는 포인터 배열이다.(환경변수목록)
      - 각 포인터는 `name=value` 형식의 쌍을 가리킨다.
    - `execve` 함수는 `filename`을 로드한 후,
    해당 프로그램의 시작 명령어를 호출한다.
    (`main()` 함수의 첫 명령어 아님)
    - `main`의 실행이 시작된 시점에서,
    런타임 스택은(스택의 아래(높은 주소)부터)
      - 인자 / 환경 문자열(널문자 종료)
      - `envp`
      - `argv`
      - `libc_start_main`의 스택 프레임
      - 추후의 `main` 스택 프레임
    - 이렇게 배치된다.
    - `envp`의 첫 데이터는 데이터 영역에 `environ` 포인터가 가리킨다.
    - `main()` 함수에는 세 개의 인자가 전달된다.
      - `argc` : `argv` 배열의 원소 갯수(`null` 제외)
      - `argv` : `argv` 배열의 첫 번째 데이터 포인터
      - `envp` : `envp` 배열의 첫 번째 데이터 포인터

### 느낀 점 & 배운 점

이번 챕터에서는,

간단하게 `execve()` 함수를 알아본 것 같아.

말 그대로,
해당 프로세스에 새 프로그램을 덮어쓰는거지.

`filename`(말 그대로 실행파일) / `argv`(말 그대로 인자) / `envp`(말 그대로 환경 변수)
이렇게 인자를 받아서,

`filename` 인자로 새 실행가능 오브젝트 파일을 불러오고,
`argv` / `envp`로 새 실행가능 오브젝트 파일의 `main()`에 인자 / 환경변수를 전달하고..

`argv` / `envp`도 포인터 배열이고,
각 배열은 널문자로 종료되고..

근데 솔직히 내가 궁금했던 것들은 딱히 없더라고..
아쉬움..
