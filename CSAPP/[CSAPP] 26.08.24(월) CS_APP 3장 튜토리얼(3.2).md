## 2. Program Encodings - 프로그램 인코딩

1. C언어로 작성된 프로그램은 다음 과정을 거쳐서 번역된다.
    - 1. 전처리기는 소스 파일(`.c`)의 `#include`로 지정된 모든 파일을 포함시키고
    `#define` 으로 지정된 모든 매크로를 전개한다.(Preprocessing)
    - 2. 컴파일러는 소스 파일을 어셈블리 코드(`.s`)로 변환한다.(Compile)
    - 3. 어셈블러는 어셈블리 코드를 바이너리 오브젝트 파일(`.o`)로 변환한다.(Assemble)
    - 4. 링커는 포함된 라이브러리들을 엮어 실행 파일을 만든다.(Linking)
    - 그리고, CPU에서는 실행 파일이 실행된다. 
    - 실행 파일은 CPU가 실행할 기계어 코드와 프로그램 실행에 필요한 여러 정보를 포함한다.
    
2. 컴퓨터는 두 가지 추상 모델을 통해 구현의 세부 사항을 숨긴다.
    - 첫 번째로, ISA로 소프트웨어가 CPU 내부 구현을 몰라도 CPU를 사용할 수 있게 해주는 인터페이스를 제공한다.
      - 이것 덕분에 우리는 CPU의 내부 구조를 몰라도
      (어셈블리 수준보다 더 깊은 수준, 명령어 fetch부터 실행 과정의 동작 등을 몰라도)
      해당 인터페이스(ISA)를 통해 CPU를 조작할 수 있다.
      - (ISA는 Instruction Set Architecture의 줄임말로,
      말 그대로 x86_64같은 명령어의 집합이다.)
      - (명령어들만 저장되어있는 것이 아닌
      해당 명령어들이 어떤 동작을 하는지, 어떤 레지스터가 존재하는지,
      오퍼랜드를 어떻게 지정하는지 등등까지 정의되어있다.)
      - (이런 명령어 집합의 명령어들로 CPU의 내부 구조를 몰라도 CPU를 조작할 수 있게 된다.)
      - 그리고, 실제 어셈블리 코드 상으로는 차례대로 실행되는 것 같지만,
      실제로는 비순차적 명령어 처리(OoO Execution)를 할 수도 있고 
      여러 명령어를 동시에 처리할 수도 있다.
      - 어셈블리는 딱 ISA의 영역이다.
      즉, 이 이하로는 안 내려간다.
      - 막 트랜지스터까지 내려가지는 않는다.
    - 두 번째로, 가상 메모리로 프로세스가 자신만의 연속적인 주소 공간을 가진 것 처럼 보이게 한다.
      - 이것 덕분이 실제 물리적으로는 해당 프로세스의 메모리가 여기저기 흩어져있어도,
      해당 프로세스는 메모리 공간이 연속되어있는 것 처럼 인식하게 된다.
      - 데이터가 실제 물리 메모리의 어디에 배치되어 있는지는 추상화 뒤에 숨겨진다.
      - 어셈블리를 다룰 때 계속 메모리의 주소 공간을 봐야하기 때문에
      가상 메모리를 다시 짧게 복습한다.
      
3. 어셈블리 코드에는 C언어에서는 볼 수 없었던 기계어 수준의 세부 상태가 드러난다.
    - 프로그램 카운터 / 그 외의 레지스터 / 메모리 주소 등등..
    
4. 어셈블리는 C언어처럼 데이터를 객체 느낌으로 다루지 않고, 
고수준 추상화가 대부분 사라진다.
   - 기계어 수준에는 자료형 / 객체 같은 고수준 추상화가 대부분 사라진다.
   - 데이터는 레지스터 이름이나 메모리 위치를 통해 다루어진다.
   - 막 `int` / `long` / `float`같은 고수준 자료형으로 다루어지지 않는다는 느낌이다.
   - 기계어 시점에서는 그냥 비트 패턴일 뿐이고,
   그 값을 어떻게 사용할지는
   실제로 명령어가 그 값을 어떻게 사용하느냐에 달려있다.
   - 물론, 아예 분리되는 것은 아니다.
     - (정수형 연산 명령어 따로 / 부동소수점 연산 명령어 따로 있다.)
     - (물론 바이트 수마다 따로 있기도 하고..)
     (이건 다음 챕터에서 나옴)
    
    
5. 결국 CPU에서 실행되는건 어셈블리를 바이트열로 옮긴 기계어이고,
어셈블리는 기계어를 사람이 읽을 수 있도록 표현한 것이다.

### 느낀 점 & 배운 점

이번 챕터는 튜토리얼 성격이 매우 강한 챕터였어.

본격적으로 어셈블리를 들어가기 전에

- 컴파일 과정 이론적으로 알려주고
  - Preprocessing : 전처리 지시문 처리하기
  - Compile : 소스 코드 어셈블리로 바꾸기
  - Assemble : 어셈블리 기계어로 바꾸기
  - Linking : 라이브러리 등 연결하기
- ISA가 실제 CPU의 세부 동작을 추상화해서 나타내준다는걸 알려주고
  - (ISA는 명령어의 생김새 뿐 만 아니라 명령어의 동작 / 제공하는 레지스터 등의 정보도 들어있음)
- 가상 메모리로 어셈블리에서는 그렇게 물리 주소가 아니라 가상 주소가 쓰인다는걸 알려주고
- C언어와 다르게 더 많은 정보들이 표시된다는거 알려주고
  - C언어와 다르게 다양한 레지스터도 표시됨
- C언어의 고수준 자료형도 어셈블리에는 없다는 것도 알려주고
- 결국 돌아돌아 CPU에서 실행되는건 바이트열인 기계어고,
어셈블리는 기계어를 사람이 읽을 수 있도록 표기한 것이라는 것을 알려주고.

그냥 튜토리얼이야.

나 솔직히 처음에는 이것들이 뭘 말하는건지 모르겠어서 갈팡질팡했는데,
그냥 어셈블리를 배우기 위한 사전 지식이라고 이해하니까 잘 이해되더라..

결국 이런 것들을 더 요약해보자면,

1. C언어 코드는 컴파일 과정을 거쳐 기계어로 변환되고,
그런 기계어가 실제로 CPU에서 실행된다.
2. 어셈블리는 그런 기계어를 사람이 읽을 수 있게 표현한 것이다.
3. 어셈블리 명령어의 집합인 ISA 자체도 추상화가 되어있는 것들이기 때문에,
딱 ISA 수준에서 어셈블리를 다룬다.
4. 어셈블리는 메모리 주소를 가상 메모리의 가상 주소로 다룬다.

이 정도로 최종 요약할 수 있겠네..
