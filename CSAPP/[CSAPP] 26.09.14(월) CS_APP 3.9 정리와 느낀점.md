## 0. 서론

저번에는 특수한 데이터인 배열에 대해 다뤄봤었는데,
이번에도 특수한 데이터를 다룰거야.

- 구조체
- 공용체

이렇게.

근데 구조체는 많이 들어봤어도 공용체는 뭔지 모르는 사람이 좀 많을 것 같은데..
(나도 모름)

간단하게 말해서

> 여러 자료형을 겹쳐서 한 메모리 공간에 저장할 수 있게 해주는 자료형

즉,

> 하나의 메모리 공간을 여러 타입을 사용할 수 있게 해주는 자료형

이라고 볼 수 있어.

이거 솔직히 사용처가 뭔지 도저히 모르겠다는 생각이 들 만도 한데,
그냥 
한 객체가 여러 상태 중 하나의 데이터만 가질 때,
메모리를 절약하기 위해서 쓰는거야.

`A` 객체의 `data`라는 멤버가 있다고 해보자.
그 `data` 멤버는 해당 객체가 생성될 때
`int` 타입일 수도 있고, `float` 타입일 수도 있어.

공용체 없이 구현을 해본다면,

```cpp
class A {
    int data1;
    float data2;
}
```

이렇게,
둘 중 하나는 사용하지 않는데도 해당 데이터는 `A` 객체 내부에서
메모리 공간을 차지하고 있겠지.

하지만, 결국 사용하는 데이터가 둘 중 하나니까,

```cpp
class A {
    union {
        int data1;
        float data2;
    } data;
};
```

그럴 때 이렇게 공용체를 쓰는거야.
`int` 타입으로 결정됐다면 저 메모리 공간을 `int`로 쓰는거고,
`float` 타입으로 결정됐다면 저 메모리 공간을 `float`로 쓰는거지.

이 정도면

- 공용체가 뭔지
- 공용체를 어디에다 쓰는지

이 정도는 설명 됐을거라고 생각해.

그리고 이렇게 타입을 겹쳐 쓰기 때문에,
공용체의 크기는 가장 큰 타입을 기준으로 잡혀.

## 1. Structures - 구조체

### 정리

1. 구조체의 각 원소에 접근하기
    - 구조체에 대한 포인터는 구조체의 첫 번째 바이트(주소)이고,
    구조체의 각 원소에 접근하려면 첫 번째 주소로부터 오프셋을 이용해 접근하게 된다.
    - 컴파일러는 구조체의 각 멤버의 바이트 오프셋을 나타내는 정보를 관리한다.
      - 컴파일러는 그렇게 저장한 오프셋을 메모리 참조의 오프셋으로 사용해서
      구조체의 원소에 대한 참조를 한다.
      - 
      ```c
      struct A {
          int i;
          int j;
          int a[2];
          int *p;
      };
      ```
      - 이런 구조체가 있다고 할 때,
      - `int` : 4바이트 / `int[2]` 각각 4바이트, 총 8바이트 / `int*` : 8바이트이므로
      `i` / `j`에 접근하려면,
      ```x86asm
      # %rdi : A의 첫 번째 주소
      
      movl (%rdi), %eax # i에 접근(오프셋 0)
      movl 4(%rdi), %eax # j에 접근(오프셋 4)
      ```
      `a`의 각 원소에 접근하려면,
      ```x86asm
      # %rdi : A의 첫 번째 주소
      # %rsi : 접근할 인덱스
      
      movl 8(%rdi, %rsi, 4), %eax # a의 각 인덱스에 접근(오프셋 8)
      ```
      `p`에 접근하려면,
      ```x86asm
      # %rdi : A의 첫 번째 주소
      
      movq 16(%rdi), %rax # p에 접근(오프셋 16)
      ```
      이렇게 하면 된다.
      - 구조체 내의 원소에 대한 포인터를 생성하려면,
      해당 필드의 오프셋을 구조체의 주소에 더하면 된다.

### 느낀 점 & 배운 점

이번 챕터는 한 줄 요약이 되겠는데?

> 어셈블리에서 구조체의 각 필드에 접근하려면
> 구조체의 첫 번째 주소에 오프셋을 더하면 된다.

이게 사실상 끝임..

물론 구조체의 원소에 배열이 들어가있는 경우에도
구조체의 첫 번째 주소 + 배열의 첫 주소 오프셋 + 배열의 각 원소 오프셋을 하면 되고..

구조체의 각 원소의 포인터를 얻으려고 할 때도,
그냥 구조체 첫 주소 + 오프셋으로 얻으면 되고..

물론 구조체에서 각 멤버의 오프셋이
단순히 앞 필드들의 크기 합과 항상 같지는 않다는 내용도 있긴 한데,
이건 3.9.3에서 제대로 나오겠지.
(패딩(정렬)때문에 그럼)

## 2. Unions - 공용체

### 정리

1. 공용체는 구조체와 다르게 여러 데이터 유형이 겹쳐 있기 때문에,
모든 멤버의 오프셋이 공용체의 첫 번째 바이트(주소)에서 시작한다.

2. 공용체는 일반적인 경우에는 위험하지만,
멤버 여러 개 중 택 1이 되는 상황에서는 유용하다.

### 느낀 점 & 배운 점

솔직히 이거 서론에서 다 써버림..ㅋㅋ
이 챕터에서는 공용체의 모든 멤버가 0부터 시작한다는 것 이외에는
다 서론에 써놓았던 내용 뿐이었어..

하지만 이거 고치기가 귀찮아서 그냥 냅둠..ㅋㅋ

그냥

1. 공용체는 여러 데이터 타입을 겹쳐서 그 중 하나로 해당 메모리를 사용할 수 있게 해주는 자료형이다.
2. 여러 데이터 타입이 겹쳐있기 때문에 모든 멤버는 0의 오프셋을 가진다.
3. 어떤 멤버를 사용해야하는지 명시되어있지 않은 상황에서는 위험하지만,
멤버 여러 개 중 택 1이 되는 상황에서는 메모리를 아끼기 위해 유용하다.

## 3. Data Alignment - 데이터 정렬

### 정리

1. 많은 컴퓨터 시스템은 각 객체의 시작 주소가
주로 2 / 4 / 8의 배수일 것을 권장한다.
   - 각 데이터 타입이 요구하는 정렬 단위의 배수 주소로 정렬이 권장된다.
     - `char` : 1의 배수
     - `int` : 4의 배수
     - `double` : 8의 배수
     - 이렇게 각 데이터 타입이 요구하는 권장 정렬 주소가 있다.
   - 만약 저렇게 데이터를 정렬한다면,
     - (예) 8바이트짜리 데이터를 가져올 때
     강제적으로 8의 배수로 시작 주소가 되어있어서
     그저 한 번의 메모리 접근으로만 데이터를 가져올 수 있다.
   - 만약 저렇게 데이터를 정렬하지 않는다면,
     - (예) 8바이트짜리 데이터를 가져올 때
     데이터가 두 개의 8바이트 블록에 겹쳐있을 수 있어서
     두 번의 메모리 접근이 필요해진다.
   - 어쨌든 많은 컴퓨터 시스템에서 객체의 시작 주소를
   특정 숫자(요즘에는 주로 8바이트)의 배수로 맞추는걸 선호한다는 것만 알아두자.
2. 그렇기 때문에,
대표적으로 구조체의 각 원소가 해당 데이터 정렬에 맞지 않을 경우,
중간에 패딩을 삽입해 데이터 정렬을 맞춘다.
   - 물론 일반적인 변수들도 그렇지만,
   구조체에서 특히 눈에 띈다.
   - 
   ```cpp
   struct A {
       int i;
       char j;
       char* k;
   }
   ```
   이런 구조체가 있다고 했을 때
   ```text
   0      4 5      8                16
    |  i   |j|      |       k        |
                 ^          ^
                 |          |
        포인터가 8의 배수에 놓이도록 패딩을 설정한다.
   ```
   - 그렇기 때문에 뒤의 원소의 오프셋이 무조건 앞의 원소의 합이 아닌 것이다.
   - 물론 이 패딩은 데이터의 배치 순서에 따라 위치가 달라질 수 있다.

### 느낀 점 & 배운 점

솔직히 이번 챕터는 이미 알고 있었던 거였어.

데이터를 다 붙여놓으면 메모리 접근 명령어로 메모리에 접근할 때
시작 주소가 해당 데이터 타입의 배수가 되기 때문에
(하드웨어 입장에서) 좀 더 편리하게 메모리에 접근해서 데이터를 가져올 수 있어서,
각 데이터 타입이 요구하는 정렬 단위의 배수 주소에 놓이도록 데이터를 정렬하고,
딱 그 규격에 맞지 않으면 패딩을 넣는다.

이 정도?

솔직히 저게 요약이야.

## 4. 요약

1. 구조체는 시작 주소 포인터 + 오프셋으로 각 원소에 접근한다.
2. 공용체는 여러 타입이 겹쳐있기 때문에 시작 주소 포인터로 각 타입에 접근한다.
물론 실제로 사용할 때는 하나의 타입으로 통일해서 사용해야한다.
3. 하드웨어에 친화적이기 위해 각 데이터 타입이 요구하는 정렬 단위로 데이터를 정렬하고
그 정렬에 맞지 않으면 패딩을 사용해서 정렬을 맞춘다.
