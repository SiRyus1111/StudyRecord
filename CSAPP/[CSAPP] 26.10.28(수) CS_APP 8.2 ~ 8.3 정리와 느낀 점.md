## 1. Logical Control Flow - 논리적 제어 흐름

### 정리

1. 논리적 제어 흐름
    - 프로세서에서 실제로 실행된 전체 명령어의 흐름(물리적 제어 흐름) 중,
    오직 해당 프로그램(프로세스)의 코드만 추려낸 시퀀스를
    논리적 제어 흐름이라고 한다.

### 느낀 점 & 배운 점

이번 챕터는 매우 간단하네..

이 정도로 간단한 챕터가 있나 싶을 정도야..

결국 논리적 제어 흐름이라는건,

프로세서가 실행하는 명령어의 흐름 중,
해당 프로세스의 명령어의 시퀀스만 추려낸거라고 하면 되겠네?

## 2. Concurrent Flows - 동시적 흐름

### 정리

1. 동시적 흐름
    - 다른 실행 흐름과 실행 시점이 겹치는 논리적 흐름을
    동시적 흐름이라고 한다.
    - 논리적으로 동시에 실행되는 것을 동시성이라고 한다.
      - 실제 물리적으로 동시에 실행되지 않더라도,
      여러 프로세스 / 스레드가 논리적으로는 동시적으로 실행된다면
      동시성이 있다고 한다.
      - 이렇게 한 프로세스가 다른 프로세스와 번갈아 가며 실행되는 개념을
      멀티태스킹이라고 한다.
      - 프로세스가 흐름의 일부를 실행하는 각 시간 단위를
      타임 슬라이스라고 한다.
    - 동시적 흐름의 개념 자체는
    흐름이 실행되는 프로세서 코어 수나 컴퓨터의 수와 무관하다.
      - 두 흐름이 시간적으로 겹친다면,
      동일한 프로세서에서 실행되고 있어도 이 흐름은 동시적이라고 한다.
    - 병렬성은 물리적으로 동시에 실행되는 것으로써,
    두 흐름이 물리적으로 서로 다른 프로세서 코어나 컴퓨터에서 동시에 실행되고 있다면,
    그건 병렬 흐름이라고 한다.

### 느낀 점 & 배운 점

이건 앞의 논리적 제어 흐름에다가
좀 더 살을 붙인 개념이라고 할 수 있을 것 같아.

말 그대로,

논리적으로 한 프로세스가 다른 프로세스와 동시에 실행되는 흐름을
동시적 흐름이라고 하는거지.

별건 아니야.

그리고 결국 이렇게 동시적 흐름을 만드는건

- 멀티태스킹 / 타임 슬라이싱 : 여러 프로세스를 프로세서에서 번갈아 실행

이라고 할 수 있어.

그리고 이 챕터는 아마
그런 타임 슬라이스와 컨텍스트 스위칭을 설명하기 위한 챕터라는 생각이 드네..

예전에 동시성과 병렬성에 대한 명확한 정의를 공부해놓은게 계속 도움이 되네..

- 동시성 : 논리적 - 한 코어로도 동시성이 성립할 수 있음
- 병렬성 : 물리적 - 여러 코어로만 병렬성이 성립할 수 있음

## 3. Private Address Space - 개인 주소 공간

### 정리

1. 프로세스의 개인 주소 공간
    - 프로세스는 시스템의 주소 공간을 자기 혼자만 사용하는 듯한 착각을 심어준다.
    - 이 공간은 해당 프로세스 전용이며,
    해당 공간을 다른 프로세스가 사용할 수 없다.
    - 물론 각 프로세스의 주소 공간의 바이트들은 다르지만,
    각 프로세스는 동일한 구조를 가진다.
      - `.text` / `.rodata` / `.init` : 읽기 전용
      - `.data` / `.bss` : 읽기 / 쓰기 전용
      - 런타임 힙 : `malloc()`으로 할당됨
      - 런타임 스택 : 런타임에 사용됨
      - 커널 : 시스템 콜에 사용됨

### 느낀 점 & 배운 점

이번 챕터도 간단했어.

그냥 가상 메모리 조금이라도 배웠으면
쉬운 구간임..

각 프로세스는 독립적인 개인 주소 공간을 가지고 있어서,
해당 프로세스가 메모리를 독점하고 있는 듯한 착각을 심어주는거.

솔직히 이게 끝이야..

근데 솔직히 이 파트는 다음 파트(커널 모드)를 위한 빌드업에 가깝다고 생각해..

지금까지를 적당히 요약해보면,

- 논리적 실행 흐름 / 동시적 흐름 : CPU 독점 착각
- 개인 주소 공간 : 메모리 독점 착각

이렇게 해서
프로세스가 어떻게 추상화를 하는지를 알 수 있는거라고 생각해.

## 4. User and Kernel Modes - 유저 모드와 커널 모드

### 정리

1. 유저 모드와 커널 모드
    - 프로세서는 일반적으로 특정 제어 레지스터에 있는
    모드 비트를 통해
    애플리케이션이 실행할 수 있는 명령어와 접근할 수 있는 주소 공간의 범위를 제한한다.
    - 모드 비트가 활성화되면 프로세스는 커널 모드에서 실행되고,
    커널 모드에서 실행되는 프로세스는 명령어 세트의 모든 명령어를 실행할 수 있으며
    시스템 내의 모든 메모리 위치에 접근할 수 있게 된다.
    - 모드 비트가 비활성화되면 프로세스는 사용자 모드에서 실행되고,
    사용자 모드에서 실행되는 프로세스는
    프로세서를 정지시키거나, 모드 비트를 변경하거나, I/O 작업을 시작하는 등의
    특권 명령어를 실행할 수 없다.
    또한 주소 공간의 커널 영역에 접근할 수도 없게 된다.
    - 프로세스가 사용자 모드에서 커널 모드로 전환되는 유일한 방법은
    인터럽트 / 폴트 / 트랩(시스템 콜)과 같은 예외를 통하는 것이고,
    예외가 발생하여 제어권이 예외 핸들러로 넘어가면,
    프로세스는 모드를 커널 모드로 변경한다.
    핸들러가 반환되면, 프로세서는 해당 프로세서의 모드를 다시 사용자 모드로 변경한다.

### 느낀 점 & 배운 점

이번 파트도 나름 어렵지 않았어.

요약해보자면,

- 모드 비트로 커널 모드 / 유저 모드를 판별한다.
- 커널 모드라면 모든 명령어를 사용할 수 있고 모든 메모리 공간에 접근할 수 있다.
- 유저 모드라면 일부 명령어(OS의 권한이 필요한 명령어)는 사용할 수 없고,
커널 영역에 접근할 수 없다.
- 유저 모드에서 커널 모드로 바꾸는 법은 예외(인터럽트 / 폴트 / 트랩(시스템 콜))를
이용하는 것이며,
예외 핸들러를 통해 커널 모드로 전환되고, 예외 핸들러가 반환되면 사용자 모드로 전환된다.

이 정도..

뭔가 왜 메모리 펜스가 연상되는지는 모르겠다..

특정 명령어 / 특정 코드 영역을 실행할 수 없도록 제약
vs 특정 명령어를 먼저 / 나중에 실행할 수 없도록 제약..

그리고 뭔가 특정 경계선을 넘길 수 없는 느낌이 비슷함..

## 5. Context Swithes - 컨텍스트 스위칭

### 정리

1. 컨텍스트 스위칭과 멀티태스킹
    - 멀티태스킹은 커널의 컨텍스트 스위칭이라는 예외적 제어 흐름을 사용하여 구현된다.
      - 커널은 각 프로세스에 대한 컨텍스트,
      즉 해당 프로세스를 다시 시작하는데 필요한 상태를 유지한다.
        - 범용 레지스터 / 부동소수점 레지스터 / PC / 스택 정보
        / 상태 레지스터 / 커널 스택 / 페이지 테이블 / 프로세스 테이블 / 파일 테이블 
        등이 포함된다.
      - 프로세스 실행 중 특정 시점(타임 슬라이스가 다 되었을 때 등)에서
      커널은 이전에 프로세스를 선점하고 있었던 프로세스를 다시 시작하기로 결정할 수 있다.
        - 이런 결정을 스케줄링이라고 하며,
        스케줄러라고 불리는 커널 내 코드가 이를 처리한다.
        - 커널은
          - 현재 프로세스의 컨텍스트를 저장하고,
          - 이전에 선점되었던 해당 프로세스의 컨텍스트를 복원하고,
          - 새로 복원된 해당 프로세스로 제어 흐름을 넘기는 컨텍스트 스위칭이라는 매커니즘을 통해
        - 새로 복원된 프로세스로 제어권을 넘긴다.
    - 컨텍스트 스위칭은 커널이 유저를 대신하여 시스템 콜을 처리하는 도중에도 발생할 수 있다.
    - 컨텍스트 스위칭은 인터럽트의 결과로 발생할 수도 있다.

### 느낀 점 & 배운 점

결국 이번 파트를 한 줄로 요약하면,

> 멀티태스킹을 위한 컨텍스트 스위칭이
> 어떤 정보를 저장하며,
> 어떻게 실행되며,
> 무엇이 실행시키는지

라고 할 수 있어.

어떤 정보를 저장하냐면,
해당 프로세스를 다시 실행하기 위한 정보인 컨텍스트를 저장하지.

어떻게 실행되냐면,

- 실행하고 있는 프로세스의 컨텍스트를 보존하고
- 스위칭할 프로세스의 컨텍스트를 복원하고
- 스위칭할 프로세스로 제어 흐름을 넘기는 것으로

컨텍스트 스위칭이 실행되지.

그리고 컨텍스트 스위칭은
OS 커널의 스케줄러가 실행하고.

그리고 저렇게 보존하는 것들도 많고,
캐시 메모리도 초기화되다보니까(콜드 캐시 미스 발생)
컨텍스트 스위칭에는 많은 자원이 소모된다는 것도 알겠어.

## 6. 요약

1. 프로세스는 자신만의 논리적 제어 흐름 / 동시적 흐름을 가져서
CPU를 독점하고있다고 착각하게 된다.
2. 프로세스는 자신만의 메모리 공간을 가지게 되어,
메모리를 독점하고 있다고 착각하게 된다.
3. 프로세스는 유저 모드와 커널 모드를 예외를 통해 오가며,
사용자 모드에서는 일부 명령어와 커널 메모리에 접근할 수 없지만
커널 모드에서는 모든 명령어와 모든 메모리에 접근할 수 있게 된다.
(권한이 생김)
이것으로 프로세스가 자신만의 메모리 공간을 벗어나는 접근을 하지 않게 해준다.
4. 여러 프로세스가 CPU에서 번갈아서 실행되는 멀티태스킹이 진행되며,
컨텍스트 스위칭을 통해 멀티태스킹이 구현된다.
5. 컨텍스트 스위칭이란,
현재 프로세스의 컨텍스트(재실행에 필요한 정보)를 저장하고
새로 실행할 프로세스의 컨텍스트를 복구하고
새로 실행할 프로세스로 제어 흐름을 옮기는 과정이다.
