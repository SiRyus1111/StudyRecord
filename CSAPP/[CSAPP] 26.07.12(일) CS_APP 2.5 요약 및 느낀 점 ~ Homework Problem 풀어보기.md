### 요약

1. 컴퓨터는 정수 / 실수 / 문자 등의 정보를 바이트열로 표현한다.

2. 64비트 시스템은 32비트 시스템을 가정하고 만들어진 프로그램이 호환된다.
    - 64비트 / 32비트의 제일 큰 차이는 워드 크기이다. 
    워드 크기가 8바이트 / 4바이트라서
    포인터 변수의 크기가 8바이트 / 4바이트로
    지정할 수 있는 주소의 범위가 $0$부터 $2^{64} - 1$ / $0$부터 $2^{32} - 1$로 다르게 된다.
 
3. 컴퓨터는 2의 보수로 정수를 표현하고, IEEE 754 부동소수점 포맷으로 실수를 표현한다.
    - 2의 보수의 장점 : 양수든 음수든 같은 가산기로 더할 수 있다. 그저 비트열을 더하기만 하면 된다.
      - `~x + 1`로 음수(`-x`, 역원, 원래 수와 더해서 0이 나오는 값)를 구현하기 쉽다.
    - IEEE 754의 장점 : 부호 / 가수부 / 지수부로 나누어서 과학적 표기법으로 
    (상대적으로) 직관적이게 실수를 표현할 수 있다.
      - 과학적 표기법으로 지수부와 가수부를 따로 두기 때문에 
      제한된 $w$비트 내에서 큰 값부터 작은 값까지 표현할 수 있다.
 
4. 컴퓨터의 정수 산술연산은 무조건 고정된 $w$비트 이내에서 수행되어야하므로,
$w$비트를 초과하면 $w$비트 초과 비트들이 절삭된다.
   - 이게 오버플로우이다.
   - 비트적으로는 $w$비트 초과 비트 절삭,
   - 수학적으로는 $\bmod 2^{w}$이라고 할 수 있다.
   - 물론 unsigned 기준이긴 하다. signed 정수는 양의 오버플로우 / 음의 오버플로우로 나뉜다.
     - signed 정수의 오버플로우는 unsigned 정수처럼 단순한 $\bmod$연산으로 정의되지 않고,
     표현 범위($TMax$ / $TMin$)를 벗어나면 오버플로우가 발생한다.
    
5. 컴퓨터의 정수 곱셈연산은 비트시프트와 덧셈 연산으로 최적화될 수 있다.
    - (뺄셈은 음수를 더하는 것과 다르지 않다.)
    - `x * 7` = `(x * 2^3) - (x * 2^0)` = `(x << 3) - x`
    - `x * 13` = `(x * 2^3) + (x * 2^2) + (x * 2^0)` = `(x << 3) + (x << 2) + x`

6. 컴퓨터의 정수 나눗셈 연산은 소수부 절삭, 즉 결과값에서 0을 향해 반올림한 값이 나와야한다.
    - 오른쪽 시프트 연산은 $\lfloor x / 2^k \rfloor$, 즉 내림처럼 동작하기 때문에,
    0을 향해 반올림이 올림이 되는 음수의 값들은 
    별도의 $bias$를 달고 값을 보정해줘야한다.
      - 이 $bias$는 `(1 << k) - 1`로, 나머지가 될 수 있는 최댓값이기 때문에
      딱 떨어지는 값은 그대로 유지되고,
      딱 떨어지지 않는 값만 올림이 적용되게 된다.
      
7. IEEE 754 부동소수점 포맷으로는 가수부에 모두 담을 수 없는 경우 근사치로 표현된다.
    - 과학적 표기법 : $\pm M \times 2^{E}$
    - 그리고, IEEE 754 부동소수점 포맷은 부호 비트 / 지수부 / 가수부로 나뉜다.
      - 부호비트($s$) : 부호 표현
      - 지수부($exp$) : 과학적 표기법의 지수 표현($E$ 결정)
      - 가수부($frac$) : 수의 모양 표현($M$ 결정)
    - 가수부 내에서 표현할 수 없는 모양의 수는 근사치로 표현된다.
    - $M$은 $1.xxxx_{2}$ 형태로 통일된 정규화의 형태로 표현되고,
    $0$과 정규화된 값의 최솟값 사이를 이어주는 $0.xxxx_{2}$ 형태의 비정규화 형태로도 표현된다.
    - 근사치로 표현할 때, 가수부 내에 다 담지 못하는 경우
    반올림을 해준다.
      - 반올림을 할 때, 정확히 가수부로 표현할 수 있는 값의 절반($\frac{1}{2}ulp$)이 되는 경우,
      최하위 비트가 0이 되는 쪽(짝수)으로 Rounding한다.
      
8. IEEE 754 부동소수점 포맷의 산술연산은 주의해야한다.
    - 결합법칙이 성립하지 않기 때문에 연산의 순서에 따라 결과값이 달라질 수 있다.
    - 이 차이는 평소에는 거의 눈에 띄지 않지만, 
    특정 연산들에 있어서는 Rounding 때문에 큰 차이가 발생할 수 있다.
    
9. 정수 표현 <-> 부동소수점 표현을 할 때도 주의해야한다.
    - 부동소수점 표현이 연속된 정수를 표현할 수 없는 경우(`float` 기준 $2^24$ 이상)에는
    정수 표현을 부동소수점 표현으로 캐스팅할 때 Rounding으로 인해 값의 정밀도가 손실될 수 있다.

### 2.61. C 표현식 작성하기 - 정수

> 다음 조건이 참일 때는 1로, 거짓일 때는 0으로 평가되는 C 표현식을 작성하시오. 
> `x`는 int형이라고 가정하시오.

#### 내가 쓴 답

1. `x`의 어떤 비트가 1일 때 `true`, 아니라면(모든 비트가 0이라면) `false`.
    - `x & 0xFFFFFFFF`
    - `x`의 어떤 비트가 1이라면 무조건 `0`이 아닌 값이 나오므로
    `true`를 나타내게되고,
    - `x`의 모든 비트가 0이라면 무조건 `0`이 나오므로 `false`를 나타낸다.
    - 채점 : 이해적으로는 맞는데,
    결국 1 / 0으로 이분화되어 나오지는 않는다.
    더 잘 맞는 답은 `!!x`(두번 논리부정해서 참일 때 무조건 1 나오게 하기)임.
2. `x`의 어떤 비트가 0일 때 `true`, 아니라면(모든 비트가 1이라면) `false`.
    - `~x & 0xFFFFFFFF`
    - `x`를 비트 부정(`~x`)하면 0과 1이 뒤집힘.
    - `~x`의 어떤 비트가 1일 때 `true` / 모든 비트가 0일 때 `false`.
    - `~x`의 어떤 비트가 1이라면 무조건 `1` ~ `0xFFFFFFFF` 사이의 수가 나오므로
    `true`를 나타내고,
    - `~x`의 모든 비트가 0이라면 무조건 `0`이 나오므로 `false`.
    - 채점 : 이것도 이해적으로는 맞는데,
    이것도 1 / 0으로 이분화되어 나오지는 않는다.
    사실 `!!~x`로 됨.
3. 최하위 바이트의 어떤 비트가 1일 때 `true`, 아니라면(모든 비트가 0이라면) `false`.
    - `!!(x & 0xFF)`
    - (위의 문제들 채점한 후에 풀었음. 그래서 `!!` 쓴거임.)
    - 비트마스킹으로 최하위 바이트만 골라내고, 
    모두 0인지 파악함.
4. 최상위 바이트의 어떤 비트가 0일 때 `true`, 아니라면(모든 비트가 1이라면) `false`.
    - `!!(~(x >> ((sizeof(x) - 1) << 3)) & 0xFF)`
    - 최상위 바이트만 골라내기 -> 부정으로 모두 1인지 파악하기.

- 대표적인 틀린 이유 : `&`와 `&&`을 혼동함,
`x & 0xFFFFFFFF` = `int`에서는 그냥 바이트열 그대로,
`~`연산자 순서 잘못적음.

#### 오답노트

1. 단순히 `x & 0xFFFFFFFF`만으로는 
32비트의 `int` 자료형에서는 원래 값을 그대로 나타내는것(`x`)과 다를바가 없음.
그리고 `0`과 `1`로 이분화되어야하니 0이 아닌 모든 값들을 1로 통일해주는 로직이 필요했음.
   - 즉, `!!x`를 하면,
     - 0이 아닌 값 -> 0 -> 1로 통일되고,
     - 0 -> 1 -> 0으로 통일되서
   - 완벽하게 이분화됨.
   - 물론, 비트 연산자 `&`를 써야하는걸 논리 연산자 `&&`으로 써버리기도 했고.
2. 1번과 같음.
3. 안틀림.
4. 여기도 `&`을 `&&`으로 잘못써버림.
그리고 `~`을 쓰는 위치도 잘못되었음.
   - `!!~((x >> shift) & 0xFF)`처럼 맨 밖에 적었었는데,
   그러면 결국 
   비트마스크로 걸러짐 
   -> 상위 `shift`비트는 무조건 전부 0
   -> 그 상태에서 비트 뒤집기
   -> 최종적으로 논리연산할 때 무조건 1나옴
   이렇게 됨.
   - `!!(~(x >> shift) & 0xFF)`처럼 **비트마스크로 거르기 전에** 비트 뒤집기를 해야만,
   먼저 비트 뒤집음
   -> 비트마스크로 걸러짐
   -> 최종적으로 논리연산할 때 맨앞의 비트들은 비트마스크 때문에 고려되지 않음
   이렇게 되어서, 비트마스크로 걸러진 결과들이 최종 결과에 반영이 됨.

### 2.62. 논리시프트인지 산술시프트인지 검증하기 - 정수

> `int` 자료형에 대하 산술 오른쪽 시프트를 사용하는 컴퓨터에서 실행하면 1을 반환하고,
> 그렇지 않은 경우에는 0을 반환하는 `int_shifts_are_arithmetic()` 함수를 작성하시오.
> 작성한 코드는 어떤 워드 크기를 가진 컴퓨터에서도 정상적으로 작동해야합니다.

#### 내가 쓴 답

```cpp
bool int_shifts_are_arithmetic() {
    int num = 0;
    num = 1 << ((sizeof(int) << 3) - 1); // 최상위 비트만 1로 만들기
    // 왼쪽 시프트만 쓰므로 논리 / 산술 시프트에 대한 편차 발생하지 않음

    int mask = num;

    num = num >> 1; // 한칸 오른쪽 시프트. 산술이면 최상위 비트 = 1, 논리라면 최상위 비트 = 0

    return !!((num & mask) == mask);
}
```

#### 오답노트

이게 1을 부호비트까지 시프트하는 동작이 C 표준에서는
Undefined Behaivor가 될 수 있음.

즉,

```cpp
num = 1 << ((sizeof(int) << 3) - 1);
```

이 코드는 문제가 될 수 있다는 것.

그냥 

```cpp
int num = -1;
```

로 해버리는게 좋았을 듯.

`-1`은 어떤 워드 크기에서도 `0xFF...FF`라서,
즉 모든 비트가 `1`인게 확정이라서,
편하게 할 수 있음.

그리고, `mask`랑 비트 AND 연산을 한 후
`mask`랑 대조해보는 로직도 충분히 좋은데,

`==`연산자가 이미 논리연산자라

```cpp
(num & mask) == mask
```

만 적었어도 됐을 듯.

결국,

그냥

```cpp
bool int_shifts_are_arithmetic() {
    return (-1 >> 1) == -1;
}
```

이렇게 해버려도 됐을듯.

### 2.74. 뺄셈에서에 오버플로우 판별 - 정수

> 오버플로우 없이 `x - y`를 수행할 수 있는지를 확인할 수 있는 함수를 작성하시요.
> 오버플로우가 발생하지 않으면 1을 반환해야합니다.

#### 내가 쓴 답

```cpp
#include <iostream>
#include <limits.h>

// x - y를 했을 때 오버플로우를 판별하는 함수
// 오버플로우가 발생하지 않으면 1을 반환
int tsub_ok(int x, int y){
    int s = x - y;

    int mask = INT_MIN; // 1000...0000

    return !(((x ^ y) & mask) && ((x ^ s) & mask));
}

// x - y가 오버플로우가 발생하려면

// 1. x = 음수, y = 양수일 때 x - y가 TMin 미만
// 2. x = 양수, y = 음수일 때 x - y가 TMax 이상

// 결론적으로, 부호가 다르고 절댓값 씌워서 더했을 때..
// 이건 아닌 듯..

// 일단 positive든 negative든 오버플로우가 발생할 수 있음.
```

### 2.78. 2^k로 나누기 - 정수

> 비트 레벨 연산만으로 2^k로 x를 나누고 결과를 반환하는 함수를 작성하시오.

#### 내가 쓴 답

```cpp
#include <iostream>

int divide_power2(int x, int k){
    // 쉽지!

    int sign_mask = x >> 31; // 산술 시프트임.

    // 여기서 x가 양수 / 음수에 따라 음수에만 바이어스가 적용되는 그런거..(이게 핵심)
    // 만들었다.. (100% 내 머리로 한건 아니긴 한데..)
    int bias = ((1 << k) - 1) & sign_mask;

    return ((x + bias) >> k);
}
```

#### 오답노트

처음에는 단순히

```cpp
int sign_bit = x >> 31 & 0x1;
int bias = ((1 << k) - 1) * sign_bit;
```

이렇게 하려고 했는데,
이게 `*` 연산자가 허용이 안됐었음.

그래서 `signed int`의 오른쪽 시프트는 산술 시프트라는 점을 이용해서

```cpp
int sign_mask = x >> 31;
int bias = ((1 << k) - 1) & sign_mask;
```

이렇게 고침.

부호비트가 `1`이라면 `bias`는 비트 AND 연산(`&`)으로 값이 제대로 들어가고,
부호비트기 `0`이라면 `bias`는 비트 AND 연산으로 값이 0이 되는..

진짜 이거 천재적이다.
내가 직접 이 아이디어를 떠올린건 아니긴 한데..

그냥 if문이 대체됨..

### 2.84. 부동소수점 값 비교 - 부동소수점

> 첫 번째 인자가 두 번째 인자보다 작거나 같은지 여부를 검사하는 다음 함수의 반환값을 기입하시오.
> 함수 `f2u()`는 부동소수점 인자와 동일한 비트 표현을 가진 부호없는 32비트 정수를 반환합니다.
> 두 인자 모두 $NaN$이 아니라고 가정합니다.
> `+0`과 `-0`은 서로 같다고 간주됩니다.

#### 내가 쓴 답

솔직히 이건 이 정도까지는 추론 됐는데 논리식을 어떻게 써야할지 모르겠음..

```cpp
// 경우를 분리해보자..

// 1. x와 y가 부호가 다른 경우 - 바로 구별 가능
// x와 y가 부호가 다르면 x <= y를 바로 구별할 수 있음.
// x : 음수 / y : 양수라면 바로 1 나오고,
// x : 양수 / y : 음수라면 바로 0 나옴.

// 2. x와 y가 부호에 상관없이 0인 경우 - 바로 구별 가능
// x와 y가 부호에 상관없이 0이라면 바로 구별할 수 있음.
// 부호를 안보고 exp / frac만 보면 됨. 둘다 0인지 확인하고.

// 3. x와 y가 같은 부호인 경우 - 별도로 구별해야함
// 같은 부호라면 x와 y를 직접 비교해봐야함.
// 어차피 부호가 같으면 최상위 비트도 같을테니
// x와 y를 직접 비교해보면 됨.
// 둘다 양수 / 둘다 음수인 경우 따로따로 해서.
// 주의점 : 음수일 때와 양수일 때 비교하는 방향이 다름.
```

근데 이게 frac 구간에서 exp 구간으로 자연스럽게 이어진다는게 전제라..

frac 구간 : 작은자릿수
exp 구간 : 큰자릿수

이런 느낌으로..

실제로도 그럼.

비트 배치 구조상 가중치가 frac -> exp 순으로 올라감. s는 별개지만..
그래서 unsigned처럼 비교해버려도 상관 없음.

#### 오답노트

결국 if문 없이 조건 분기하는 쪽에서 막힘.

- 둘다 0이다 -> `!((ux << 1) | (uy << 1))`
  - 부호비트 없앴을 때 나머지 비트가 0이면 0인 것.
- 부호가 다르다 -> `sx & !sy`
  - `x <= y`를 판별하는 것이므로 `sx`가 1, `sy`가 0인 경우에 `x <= y`가 됨.
- 둘다 양수이다 -> `(!sx & !sy) & (((ux - uy) >> 31) | !(ux - uy))`
  - `!sx & !sy`로 둘 다 양수인 경우에 제대로된 값이 나오도록 함.
  - 두 수를 `(x - y) >> 31`의 형태(`x - y`가 음수이면 `x < y`라는 느낌)로 `x < y`를 판별하고,
  두 수를 `!(x - y)`의 형태로 `x == y`를 판별
- 둘다 음수이다 -> `(sx & sy) & (((uy - ux) >> 31) | !(uy - ux))`
  - `sx & sy`로 둘 다 음수인 경우에 제대로된 값이 나오도록 함.
  - 두 수를 `y - x`의 형태(`y - x`가 음수라면 `y < x`라는 느낌)로 `y < x`를 판별하고,
  두 수를 `!(y - x)`의 형태로 `x == y`를 판별
  - 왜 거꾸로 하냐면,
  음수일 때는 절댓값이 더 작아야 해당 수의 크기가 더 크기 때문에.

어떻게 이걸 한번에 떠올림?

```cpp
// x가 y보다 작거나 같은지 여부를 검사하는 함수
int float_le(float x, float y) {
    unsigned ux = f2u(x);
    unsigned uy = f2u(y);

    unsigned sx = ux >> 31;
    unsigned sy = uy >> 31;

    int both_zero = !((ux << 1) | (uy << 1));

    int neg_pos = sx & !sy;

    int both_pos_le = (!sx & !sy) & (((ux - uy) >> 31) | !(ux - uy));

    int both_neg_le = (sx & sy) & (((uy - ux) >> 31) | !(uy - ux));

    // 함수의 반환값(0 / 1)
    return (both_zero | neg_pos | both_pos_le | both_neg_le);
}
```

### 2.92. -f를 계산하기 - 부동소수점

> 부동소수점 수 `f`를 인수로 받아 `-f`를 계산하는 `float_negate()` 함수를 작성하시오.
> `f`가 $NaN$인 경우, 함수는 그대로 `f`를 반환해야합니다.

```cpp
typedef unsigned float_bits;

float_bits float_negate(float_bits f){
    unsigned sign_bit = f >> 31;
    unsigned exp = f >> 23 & 0xFF; // exp 필드의 크기인 8비트만 마스크로 빼오기
    unsigned frac = f & 0x7FFFFF; // frac 구간 = 23비트이므로 하위 23비트만 마스크로 빼오기

    if (exp == 0xFF && (frac != 0)){
        return f;
    }
    else {
        float_bits neg_f = 0; // 0x00000000
        neg_f = ((sign_bit ^ 0x00000001) << 31) | (exp << 23) | frac;

        return neg_f;
    }
}
```

1. 부호비트 / exp / frac을 각각 분리
2. NaN인 경우 : exp = 전부 1이고 frac이 0이 아닌 경우
    - f를 그대로 반환
3. NaN이 아닌 경우
    - neg_f를 반환 : 부호비트 / exp / frac을 비트 OR 연산자(`|`)로 조립

#### 오답노트

처음에는 $NaN$ 판별에 `(exp == FF && !(frac == 0x7FFFFF))`로 헷갈려 적어서
`frac != 0`일 때 $NaN$으로 판별하지 못했었음.

그리고, else 부분을 좀 더 깔끔하게 갈아엎을 수 있을 듯.
딱 부호 비트만 반전해주는 식으로.

```cpp
else {
    return f ^ 0x80000000; // 부호 비트만 반전
}
```
