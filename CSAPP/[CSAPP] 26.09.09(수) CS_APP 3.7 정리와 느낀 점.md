## 1. The Run-Time Stack - 런타임 스택

### 정리

1. 프로시저는 후입 선출(LIFO), 즉 스택을 사용해서 프로시저에 필요한 저장 공간을 관리할 수 있다.
    - 나중에 호출된 프로시저가 먼저 반환되기 때문에, 후입 선출이 적합하다.
    - 따라서 프로그램은 스택을 사용해서 프로시저에 필요한 저장 공간을 관리할 수 있다.
    - 스택에는 제어 / 데이터 / 메모리 관리에 필요한 정보를 저장한다.
2. 런타임 스택과 스택 프레임
    - `x86_64`에서의 스택은 낮은 주소 방향으로 확장되고,
    스택 포인터(`%rsp`)는 스택의 최상위 원소(가장 낮은 주소의 원소)를 가리킨다.
    - `pushq` / `popq`를 사용해서 스택에 데이터를 저장하거나 가져올 수 있다.
    - 만약 프로시저가 레지스터에 담을 수 있는 용량 이상으로 데이터를 저장해야 하는 경우,
    스택에 공간을 할당하고, 이 영역을 **스택 프레임**이라고 한다.
      - 현재 실행중인 프로시저의 스택 프레임은 항상 스택 최상단에 위치한다.
      - 만약 한 프로시저가 다른 프로시저를 호출하게 된다면,
      먼저 호출된 프로시저가 해당 프로시저의 스택 프레임의 최상단에
      반환 주소를 `pushq`해서 
      해당 프로시저가 반환된 후 프로그램이 어디서 실행을 재개해야하는지를 나타낸다.
      - 그리고 새로 호출된 프로시저는 레지스터의 값을 저장하고,
      지역 변수를 저장할 공간을 스택에 할당하며,
      해당 프로시저에 대한 매개변수를 설정할 수 있다.
      - 대부분의 프로시저에 대한 스택 프레임은 고정된 크기를 가지고,
      프로시저가 시작될 때 할당된다.
      - 일부 프로시저는 가변 길이 프레임을 가진다.
    - 프로시저는 기본적으로 6개의 매개변수를 받을 수 있고,
    6개 이상으로 매개변수를 받아야 하는 경우,
    새 프로시저를 호출하는 프로시저가 자신의 스택 프레임 내에 이 매개변수를 저장할 수 있다.

### 느낀 점 & 배운 점

이번 챕터는 진짜 프로시저 튜토리얼 느낌이야.

대충 요약해보면,

> 프로시저에 대한 정보들은 스택 프레임에 저장된다.

라고 할 수 있어.

- 반환 주소 저장
- 지역 변수 저장
- 레지스터 저장
- 매개변수 저장

이런 것들은 좀 곁다리고,
(좀 나중에 제대로 배울 듯)

결국 핵심은
프로시저는 스택의 형태로 호출된다는거지.
LIFO 형태로.
나중에 호출된게 먼저 반환되는거지.

그리고 그렇기 때문에 프로시저 실행에 필요한 정보들,
정확히는 레지스터만으로 저장하고 처리할 수 없는 것들을
스택 프레임의 형태로 관리하는거고.

## 2. Control Transfer - 제어 전달

### 정리

1. `call` 
    - 프로시저 A에서 프로시저 B로 제어를 넘기는 건 단순히 프로그램 카운터를
    프로시저 B 코드의 시작 주소로 넘기는 것이다.
    - 하지만 프로시저 B를 반환할 때, 
    다시 프로시저 A를 실행할 때의 코드 위치를 기록해두어서
    계속 프로시저 A를 실행해야한다.
    - `x86_64`에서는 `call B` 명령어로 프로시저 B를 호출해서
    프로시저 A를 다시 실행할 때의 코드 위치(반환 주소)를 기록해놓는다.
    - 이 `call B` 명령어는 프로시저 A의 다시 실행할 위치를 기록해놓고
    프로그램 카운터를 프로시저 B의 시작 주소로 설정해준다.
    - `call Label` 형태나 `call *Operand` 형태로 작성될 수 있다.
      - 점프 처럼, `call` 명령어도 직접 / 간접이 나뉜다.
    
2. `ret`
    - 말 그대로 프로시저를 반환하는 명령어로,
    스택에서 `call`을 호출했을 때 저장된 프로시저 A의 코드 위치를 `pop`하고
    프로그램 카운터를 해당 주소로 설정한다.
    - 프로시저의 반환 시점에서 `ret`를 작성하면 된다.

### 느낀 점 & 배운 점

이번 챕터는 솔직히 내용은 별게 없는데(반환 주소와 `call` / `ret`)
예시가 좀 많았어..

그냥 `call` / `ret`을 호출했을 때 스택이 어떻게 되는지,
실행 흐름이 어떻게 되는지에 대한 예시인데,
어차피 직관적으로 와닫기 때문에 굳이 글에 넣지는 않았어.

`call` 명령어를 설명해보자면,

1. 반환 주소(반환 후 실행할 명령어의 주소)를 기존 스택의 최상단에 저장
2. PC를 피호출자 프로시저의 맨 앞을 가리키도록 변경

이렇게 볼 수 있어.
그러니까,

```x86asm
pushq return_address
jmp Callee_Procedure
```

이렇게 볼 수 있는거지.

그리고 여기서 중요한게,
반환 주소는 새로 호출한 프로시저의 스택 프레임에 들어가는게 아니라,
해당 프로시저를 호출한 프로시저의 스택 프레임에 들어가서,
해당 프로시저가 반환되며 해당 프로시저의 스택 프레임이 날아가도
해당 프로시저를 호출한 프로시저의 스택 프레임에서는 안 날아가게 된다는거.
그래서 반환 후 해당 값을 참조할 수 있는거지.
(난 이렇게 이해함)

그리고 `ret` 명령어도 설명해보자면,

1. 스택의 최상단에서 반환 주소를 꺼냄
2. PC를 해당 주소를 가리키도록 변경

이렇게 볼 수 있어.

```x86asm
# 이미 새로 호출했던 프로시저의 스택 프레임은 날아갔을테니까
# 스택의 최상단은 반환 주소임
popq %rip
jmp %rip
```

이런 느낌이지.

어차피 새로 호출한 프로시저의 스택 프레임은 반환과 함께 날아갔을테니까,
스택의 최상단을 조회하면 반환 주소가 나오는거지.

그리고 그 반환 주소부터 다시 호출자 프로시저를 실행하는거고.
물론 반환 주소는 사용한 후 스택에서 제거되고.

이 정도.

솔직히 이게 아이디어는 정말 직관적이라
이해가 그리 어렵지는 않았어.

뭔가 점점 퍼즐 조각이 모이고 있는 느낌이야.

일단 방금 런타임 스택 파트에서
프로시저의 정보(레지스터 값 / 지역변수 / 매개변수 등)가 어떻게 저장되는지,
그러니까 스택에 저장되는걸 알아봤었고,
(+ 각 프로시저의 스택 프레임은 따로 있음, 일반적으로 크기 고정)

이번에 다른 프로시저를 어떻게 호출하고 어떻게 반환하며
반환되었을 때 어떻게 다시 호출자 프로시저로 돌아가는지를 알아봤지.

이제 다음에 해당 프로시저에 어떻게 매개변수를 전달하는지 알아보면
사실상 프로시저는 다 한듯ㅋㅋ

## 3. Data Transfer - 데이터 전달

### 정리

1. 프로시저 호출 시 데이터는 기본적으로 레지스터를 통해 호출된 프로세서로 옮겨진다.
    - 인자가 `%rdi` / `%rsi`등의 레지스터로 전달되고,
    반환값은 `%rax`으로 전달된다.
    - 데이터는 정수형으로 들어간다.
      - 인자가 들어가는 레지스터는 
      `%rdi` / `%rsi` / `%rdx` / `%rcx` / `%r8` / `%r9`가 있다.
      - 순서대로 사용된다.
      
2. 함수의 인자가 6개 이상일 경우
    - 6개 이후의 인자들은 스택을 통해 전달할 수 있다.
    - 7번째 인자부터 스택의 최상단에 쌓는다.
    (반환 주소 이전, 반환주소가 마지막에 들어온다.)
    - 그리고 스택을 통해 인자를 전달할 때는 모든 데이터 크기를 8의 배수가 되도록 처리한다.(패딩)

### 느낀 점 & 배운 점

솔직히 이번 챕터도 상당히 간단했어..
그냥 

1. 레지스터에다가 정수값으로 6번째까지의 매개변수를 넘겨주고,
2. 6번째 이상의 매개변수는 스택에 넘겨주고..
(물론 반환 주소보다 높은 주소에..)
(반환주소가 `call`을 호출할 때 스택 프레임에 들어가니까..)
(그리고 8바이트 정렬을 맞춰서)

솔직히 이거 겁먹었거든?
생각보다 매우 간단하네..ㅋㅋ

지금까지 프로시저를 설명하는데 기본적인 삼신기는 다 나온 것 같아.

1. 프로시저는 어떤 형태인가?
    - LIFO 구조의 런타임 스택의 각 프로시저 별로 매개변수 / 레지스터 값 등을 저장하는 스택 프레임
2. 프로시저의 제어는 어떻게 되나?
    - `call`로 반환 주소(Return Address)를 스택의 최상단에 저장 후 PC를 이동
    - `ret`을 호출할 때 스택의 최상단의 반환 주소(Return Address)를 이용해서 원래 제어 흐름대로 돌아감
3. 프로시저에 인자를 어떻게 넘기며 어떻게 반환받나?
    - 6개까진 레지스터로 넘기고, 7개부턴 호출하는 곳에서 스택에 저장해놓음
    - 반환은 `%rax` 레지스터에
    
사실상 이 정도가 요약 끝이야.

## 4. Local Storage on the Stack - 스택의 로컬 저장소

### 정리

1. 특정 경우에는 레지스터 뿐만이 아니라 메모리에 접근해야한다.
    - 레지스터만으로 모든 지역 변수를 다룰 수 없을 때
    - 지역 변수에 주소 연산자(`&`)가 적용되어 주소를 생성해야하는 경우
    - 배열 / 구조체같이 메모리를 써야만하는 경우
    
2. 그래서, 따로 런타임 스택의 스택 프레임에 데이터를 할당할 수 있다.
    - 스택 포인터를 조작(`sub`)해서 런타임 스택에 공간을 할당받고,
    그 할당받은 위치에 스택 포인터와 오프셋을 사용해서 데이터를 삽입하고, 접근한다.
    - 스택 포인터를 조작(`add`)해서 런타임 스택에 할당받은 공간을 해제할 수 있다.

### 느낀 점 & 배운 점

이 챕터도 예시를 좀 많이 드는 챕터인데,
결국 여기서 말하는건
스택 포인터(`%rsp`)를 감소시켜서 공간을 할당받고,
그 공간에다가 메모리에 저장해야하는 지역 변수를
스택 포인터 + 오프셋(`Imm(%rsp)`)으로 저장 / 접근한 후,
스택 포인터를 증가시켜서 할당받은 메모리 공간을 해제한다는거야.

솔직히 처음 봤을 때 스택 메모리 할당 받는게
되게 어려워보였는데,
실상은 그냥 스택 포인터 딸깍이네ㅋㅋ

물론 7개 이상의 전달해야하는 인자가 있을 때도
로컬 데이터들을 다 스택에 저장한 후
제대로 스택의 최하단에 `pushq` 해주고 프로시저를 호출해야겠지.

이제

- 제어
- 데이터 전달
- 메모리 관리

중에 메모리 관리에 접어든 것 같네.

## 5. Local Storage on the Registers - 레지스터의 로컬 저장소

### 정리

1. 레지스터 집합은 모든 프로시저가 공유한다.
    - 그렇기 때문에 피호출된 프로시저가 호출자 프로시저에서 추후 사용할 값을
    덮어쓰는 것을 피해야 한다.

2. 관례에 따라, 호출자 프로시저에서 추후 사용할 값을 나타내는
피호출자 보존 레지스터(callee-saved registers)가 있다.
   - `%rbx` / `%rbp` / `%r12` ~ `%r15`가 호출자 보존 레지스터이다.
   - 이 레지스터들은 호출된 프로시저가 기존 값을 보존해야한다.
   - 물론 아예 바꾸면 안된다기보다,
   호출된 프로시저가 반환되었을 때 기존 값이 보존되어야한다는 것으로,
   해당 값들을 스택에 저장해놓고
   해당 레지스터들을 사용한 후
   스택에 저장되어있던 값들로 값을 복구하는 것도 괜찮다.
   - 그렇기 때문에 피호출자 보존 레지스터의 값을 따로 스택에 `push`하는 작업을 한다.
     - 이건 피호출된 프로시저의 스택 프레임에 저장되고,
     피호출된 프로시저가 반환되기 전에 해당 레지스터의 값을 복구해놓는다.
      
3. 피호출자 보존 레지스터와 스택 포인터를 제외한 다른 모든 레지스터는
호출자 보존 레지스터(caller-saved register)이다.
   - 이 레지스터들은 모든 프로시저가 자유롭게 값을 바꿔도 되는 레지스터이다.

### 느낀 점 & 배운 점

이번 챕터는
해당 코어의 모든 프로시저가 레지스터 집합을 공유하는데,
상위 프로시저에서 추후 쓸 값을 하위 프로시저가 바꿔버리면 안되기 때문에
따로 하위 프로시저가 반환 시 그대로 값을 유지해야하는
피호출자 보존 레지스터(callee-saved registers)를 둔다는 걸로 요약할 수 있겠네.

물론 이게 반환 시에 해당 레지스터들의 값을 보존해야하기 때문에
미리 스택에 백업해두고 실컷 해당 레지스터들을 사용한 후
해당 프로시저가 반환되기 전에 백업해둔 레지스터의 값들을
다시 해당 레지스터들로 옮겨주기만 하면 되서
해당 레지스터들도 하위 프로시저에서 자유롭게 사용할 수 있게 되기 때문에
다행인 것 같아.

물론 호출자 보존 레지스터(caller-saved registers)는 진짜 백업같은거 없이
자유롭게 사용해도 되는 느낌이고..

뭔가 이거 처음 했을 때는 어려워보였는데,
본질을 알고 나니까 쉬워보이는 것 같아.

그저,

> 하위 프로시저가 보존해야 하는 값들을 callee-saved register에 담고,
> 하위 프로시저는 **반환 시** 해당 레지스터들의 값들을 유지한다.
> 반환 시에만 보존하면 되기 때문에 해당 값들을 백업해놓고 해당 레지스터들을 사용하면 된다.

## 6. Recursive Procedures - 재귀 프로시저

### 정리

1. 각 프로시저가 각자의 스택 프레임을 사용하고,
피호출자 보존 레지스터의 규칙 덕분에
프로시저는 재귀적으로 자신을 호출할 수 있다.
   - 각 프로시저는 런타임 스택 상에 고유한 전용 공간을 가지기 때문에,
   여러 프로시저의 지역 변수들이 서로 간섭하지 않기 때문에
   재귀적인 호출이 가능하다.
   - 하위 프로시저는 피호출자 보존 레지스터의 값을 보존해야하기 때문에,
   상위 프로시저는 하위 프로시저를 호출해도
   피호출자 보존 레지스터의 값이 바뀌지 않은 채로 실행될 수 있다.

## 7. 요약

1. 프로시저는 런타임 스택에서 실행된 각 프로시저의 스택 프레임에 
상위 프로시저의 피호출자 보존 레지스터의 데이터,
지역 데이터,
하위 프로시저에 인수로 넘길 데이터 등
해당 프로시저의 데이터를 담은 채로 실행된다.
2. 프로시저는 다른 프로시저를 호출했을 때
다른 프로시저가 반환된 후 계속 해당 프로시저가 실행될 수 있도록
`call`을 실행할 때 해당 프로시저의 최상단에
반환 주소를 기록해놓는다.
그리고 호출된 프로시저로 제어를 넘긴다.
`ret`을 호출할 때 해당 반환 주소로 PC를 이동시킨다.
3. 다른 프로시저로 데이터를 전달할 때는
6개까지는 전용 레지스터들을 이용하고,
그 이후 인자를 전달할 때는 스택을 이용한다.
그리고 그렇게 스택에 올라와있는 인자는 8바이트 단위로 배치한다.
반환값은 주로 `%rax`를 이용한다.
4. 스택에 메모리를 할당하려면
스택 포인터를 감소시키면 되고,
해당 메모리를 해제하려면
스택포인터를 증가시키면 된다.
5. 상위 프로시저가 하위 프로시저를 호출했을 때,
피호출자 보존 레지스터들의 값은
반환 시점에 상위 프로시저에서 내려온 값이어야 한다.
하지만 딱 반환 시점에 한정된 이야기이므로
반환 시점 이전에는 스택에 해당 레지스터들의 데이터를 백업해놓고
해당 레지스터들을 마구 사용해도 된다.
6. 스택 프레임과 반환 주소는 각 프로시저마다 분리되어있고,
피호출자 보존 레지스터의 규칙이 있어서
프로시저는 재귀적으로 실행될 수 있다.
