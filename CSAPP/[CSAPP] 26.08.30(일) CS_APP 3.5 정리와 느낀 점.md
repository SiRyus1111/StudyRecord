## 1. Arithmetic and Logical Operations - 산술 / 논리 연산

### 정리

1. `x86_64` 어셈블리의 산술 / 논리 연산자들(AT&T 기준)
    - `S` : source
    - `D` : destination
    - `D`에 주소값을 받는 `leaq`를 제외하고는,
    전부 접미사(suffix)에 따라 다루는 바이트를 다르게 할 수 있다.
      - 예 : `addb`(바이트), `addw`(워드), `addl`(더블 워드), `addq`(쿼드 워드)
    - | 명령어 | 효과 | 설명 |
    |---|---|---|
    | `leaq S, D` | `&S -> D` |`S`의 유효 주소를 `D`로 Load|
    ||||
    |`INC D`|`D + 1 -> D`|단항 증가 연산자|
    |`DEC D`|`D - 1 -> D`|단항 감소 연산자|
    |`NEG D`|`-D -> D`|역원 구하기|
    |`NOT D`|`~D -> D`|1의 보수(비트 반전) 구하기|
    ||||
    |`ADD S, D`|`D + S -> D`| 더하기 |
    |`SUB S, D`|`D - S -> D`| 빼기 |
    |`IMUL S, D`|`D * S -> D`| 곱하기 |
    |`XOR S, D`| `D ^ S -> D` | 비트 XOR 연산 |
    |`OR S, D`| `D` \| `S -> D` | 비트 OR 연산|
    |`AND S, D`| `D & S -> D` | 비트 AND 연산|
    ||||
    |`SAL k, D`| `D << k -> D`| 산술 왼쪽 시프트|
    |`SHL k, D`| `D << k -> D`| 논리 왼쪽 시프트(`SAL`과 같음)|
    |`SAR k, D`| `D >> k -> D`| 산술 오른쪽 시프트|
    |`SHR k, D`| `D >> k -> D`| 논리 오른쪽 시프트|
    
2. `x86_64` 어셈블리의 산술 / 논리 연산은 다음과 같이 나눌 수 있다.
    - 주소 계산(Load Effective Address)
      - `leaq`
    - 단항 연산(Unary Operations)
      - `inc` / `dec`
      - `neg` / `not`
    - 이항 연산(Binary Operations)
      - `add` / `sub` / `imul` 
      - `xor` / `or` / `and`
    - 시프트 연산(Shift Operations)
      - `sal` / `shl`
      - `sar` / `shr`

## 2. Load Effective Address - 유효 주소의 Load

### 정리

1. 유효 주소란?
    - 베이스 레지스터 / 인덱스 레지스터 / 오프셋 등을 계산해서 나온 
    최종 메모리 주소라고 보면 된다.
    - 즉, `Imm(rb, ri, s)`의 형식으로 최종적으로 나온 메모리 주소이다.
    
2. `leaq S, D`
    - `l`oad `e`ffective `a`ddress `q`uad word
    - `S`에는 메모리의 주소를 나타내는 `( )`가 들어가고,
    `D`에는 해당 메모리 주소를 받을 레지스터가 들어간다.
    - 즉, `S`로 계산된 유효 주소를 `D`에 넣는 명령어이다.
    - `movq`의 변형이라고 볼 수 있지만,
    `S`의 괄호 안의 메모리 주소의 데이터를 열어보지 않고,
    `S`로 나온 유효 주소를 그대로 `D`에 저장한다.
   
3. `leaq`의 응용
    - 결국 `S`의 값을 계산하여 `D`에 넣는 명령어다 보니,
    산술 연산을 수행하는데 응용할 수 있다.
      - 예 : `leaq 8(%rdi, %rdi, 4), %rax`에서 `8(%rdi, %rdi, 4)`는
      `5 * %rdi + 8`과 같은 의미를 가지기 때문에,
      사실상 곱하기 한 번과  더하기 한 번을 스킵할 수 있다.

### 느낀 점 & 배운 점

솔직히 이 명령어를 배우면서
정수보다는 꼼수를 더 많이 배운 것 같아..

이게 유효 주소를 얻어오는 용도로 쓰는게 아니라
덧셈과 곱셈을 하는 용도로 더 많이 봤음..

결국 `leaq S, D`에서
메모리 주소를 `S`에 넣으면 그 메모리 주소에 접근하지 않고
그 메모리 주소를 `D`에 넣어준다는 것이라고 이해했어.

말 그대로 `movq`의 메모리 주소 버전이라고 할 수 있을 것 같아.

`leaq (%rdi), %rax`가 사실상
`movq %rdi, %rax`인 것 처럼..

하지만 그 메모리 주소를 계산하는 과정에서
덧셈과 곱셈들을 처리할 수 있다는 점 때문에
산술 연산 최적화를 위해 쓰일 수 있다고 생각해.

예를 들어, 메모리 주소를 계산할 때,
`Imm(base, index, scale)`으로,
$base + (index \times scale) + Imm$처럼 계산하게 되는데,
`index * scale`은 그대로 곱셈 연산이고,
`base` / `Imm`은 그대로 덧셈 연산이기 때문에,
`4(,%rdi, 8)`을 하면 `8 * %rdi + 4`처럼 쓰일 수 있는거지.

물론 이건 한 번의 곱셈과 두 번의 덧셈밖에 할 수 없기 때문에,
여러번의 곱셈과 덧셈의 결과가 필요하다면
`base`에 기존 결과를 넣거나 하는 식으로 쓸 수 있겠지..

내가 왜 이걸 쓰는지 궁금해서 추가로 알아보니까,
결국 ALU를 쓰지 않고
따로 주소 전용 연산기(AGU)를 쓸 수 있다는 점에서
최적화가 된다고 하네.

다른 연산들을 ALU에게 맡기고,
해당 연산들은 AGU를 써버리면 되는 식으로..
(물론 CPU 내부 구현에 따라 이 정보와 차이는 있을 수 있음..)

그리고 클럭도 많이 절약된대.

예를 들어 앞선 `8 * x + 4`를 한다면,
곱하기 한 번 더하기 한 번해서 명령어가 두 개 필요하고,
곱셈은 CPU 클럭도 많이 먹겠지만,

`leaq`를 이용하면
명령어 한 개로 처리할 수 있고,
AGU가 이 정도의 덧셈과 곱셈 조합을 적은 클럭 사이클로 처리할 수 있어서

`leaq`를 쓰면 최적화가 가능하대.

그리고 이건 아직 안 배운 명령어들에 대한 정보긴 한데,
`add`같은 일반적인 산술 연산은 오퍼랜드가 2개라 
`D`의 정보가 사라진대.

하지만 `leaq`를 쓰면 구조적으로 원본을 건들지 않고 결과만 새 레지스터에 담을 수 있어.
이렇게.
`leaq (%rax, %rdi), %rsi` (`rsi = rax + rdi`)
(`%rax` / `%rdi`가 그대로 유지됨)

물론 이건 다른 CPU의 내부 구현마다 달라질 수 있긴 한데,
내가 찾아본 장점들은 이 정도였어.

## 3. Unary and Binary Operation - 단항 / 이항 연산

> 접미사(suffix) 일반적으로는 생략함.

### 정리

1. 단항 연산
    - `op D`
    - 오퍼랜드 하나를 가지고 
    해당 오퍼랜드가 source이자 destination인 명령어들이다.
    - 오퍼랜드는 레지스터 / 메모리 주소일 수 있다.
    - 예 : `incq (%rsp)`라면 스택의 top에 있는 8바이트짜리 요소를 1 감소시킨다.
    - 종류 : `inc`(증가 연산) / `dec`(감소 연산) / `neg`(역원) / `not`(부정)

2. 이항 연산
    - `op S, D`
    - 오퍼랜드 두 개를 가지고,
    첫 번째 오퍼랜드는 source,
    두 번째 오퍼랜드는 source이자 destination인 명령어들이다.
    - 첫 번째 오퍼랜드는 즉시값 / 레지스터 / 메모리 전부 가능하고,
    두 번째 오퍼랜드는 레지스터 / 메모리만 가능하다.
    - 물론 두 오퍼랜드 모두 메모리인 경우는 불가능하다.
    - 두 번째 오퍼랜드를 대상으로 첫 번째 오퍼랜드로 연산을 수행한다고 보면 된다.
    교환법칙이 성립하지 않는 경우에는 이 순서가 중요하다.
    (`op S, D` -> `D = D op S`)
    - 예 : `subq %rsp, %rax`라면 `%rax = %rax - %rsp`와 같은 동작을 한다.
    - 종류 : `add`(더하기) / `sub`(빼기) / `imul`(곱하기)
    `xor`(비트 xor) / `or`(비트 or) / `and`(비트 and)
    - 주의 : 빼기는 특히 `D`와 `S`의 순서가 중요한데,
    앞에서 나타낸 것 처럼 `sub S, D`라면 `D - S`가 `D`에 저장되게 된다.
    `S - D`가 아니다.

### 느낀 점 & 배운 점

책에서도 거의 반 페이지도 안되는 챕터였던 만큼,
정말정말 간단한 챕터였어.

그냥

1. 단항 연산
2. 이항 연산

하고 끝낸 느낌..

거기다가 기존 `mov`에서 얻은

- source는 메모리 / 레지스터 / 즉시값 다 되고
- dest는 메모리 / 레지스터만 된다.
- 그리고 두 오퍼랜드가 둘 다 메모리인 것은 불가능하다.

이걸 엮은 느낌..

아 그리고 좀 헷갈리는게 있었어.

나는 이게 빼기에서 처음 안 사실인데,
`sub S, D`라고 할 때
`D - S`의 값이 저장되더라고?
다른 연산들도 그런 느낌이고?

이건 진짜 처음 알아서 따로 기록해두려고..
나 연습문제 풀다가 뭔가 이상해서 알아봤는데,
저렇게 빼지더라고..
책에도 나와있더라ㅋㅋ 
내 영어 독해 실력이 참ㅋㅋ

맨 위의 표는 반쯤 무지성으로 써서 잘 몰랐네..

## 4. Shift Operation - 시프트 연산

### 정리

1. 시프트 연산
    - `op k, D`
    - 첫 번째 오퍼랜드는 시프트 할 양을 나타내고,
    두 번째 오퍼랜드는 시프트 될 값을 나타낸다.
    - 시프트 할 양(첫 번째 오퍼랜드)으로는 즉시값과 바이트 레지스터 `%cl`을 사용할 수 있고,
    `%cl`은 `0 ~ 255`까지의 값을 표현할 수 있으므로
    $w$비트 값을 대상으로 하는 시프트 명령어는
    `%cl`의 하위 `m`비트($2^m = w$)만 사용하여 시프트 될 양을 결정하게 된다.
      - (예 : `%cl`이 `0xFF`일 때, 
      `salb` 명령어는 `%cl`의 하위 3비트($2^3 = 8$)만을 사용해서 7칸 시프트를 수행하게 되고,
      `salw` 명령어는 `%cl`의 하위 4비트($2^4 = 16$)만을 사용해서 15칸 시프트를 수행하게 된다.
    - 시프트될 값(두 번째 오퍼랜드)으로는 레지스터 / 메모리 주소를 사용할 수 있다.
    - 왼쪽 시프트 명령어에는 `sal` / `shl`이 있지만,
    두 명령어 모두 빈 비트에는 0을 채운다.
    (산술 / 논리 시프트 구분 없음)
    - 오른쪽 시프트 명령어는 `sar` / `shr`이 있고,
    `sar`은 산술 시프트(빈 비트를 부호비트로 채움)를 수행하고,
    `shr`은 논리 시프트(빈 비트를 0으로 채움)를 수행한다.

### 느낀 점 & 배운 점

여기서 되게 아이디어 좋다고 느낀 게 있는데,
바로 `%cl` 레지스터의 하위 $m$비트만 사용해서
해당 오퍼랜드의 비트 수 이상으로 시프트 하는걸 막는 로직이었어.

그걸 딱 $2^m = w$로 맞춰놔서,
비트 수 $w$가 무조건 $m$비트로 표현될 수 있는 범위 안으로 맞춘건
진짜 천재적인 발상같아.

좀 더 알아보니까, `x86_64`에서는 32비트 **이하** 비트 수의 
레지스터 / 메모리 공간은 무조건 5비트로 맞춰논다고 하더라고..

16비트 / 8비트여도 5비트래..

저 이유는 어느정도는 맞지만, 
결론적으로는 틀린 것 같아.
그냥 shift count를 `0 ~ 31` / `0 ~ 63`으로 제한하는거라고 해..

32비트 / 64비트에선 이 범위가 정확하게 맞아떨어지는거고..

## 5. Special Arithmetic Operations - 특별한 산술 연산

### 정리

1. 두 개의 64비트 정수를 곱하면 값의 표현의 128비트가 필요한 문제
    - `x86_64`는 128비트 정수와 관련된 연산에 대해 제한적인 지원을 제공한다.
    - 128비트(16바이트) 크기의 수를 옥트 워드(oct word)라고 한다.
    - `imulq`는 부호 있는 정수의 곱셈을 수행하고,
    `mulq`는 부호 없는 정수의 곱셈을 수행한다.
    (전에 설명한 `imul`과는 다른 명령어이다.)
    - 두 명령어는 곱한 결과를 64비트 내에 저장한다.
    - 두 명령어 모두에서, `%rax`에 저장되어있는 값과 곱해지고,
    곱셈의 결과는 레지스터 `%rdx`(상위 64비트) / `%rax`(하위 64비트)에 나눠서 저장된다.
      - `imulq S` : `S * R[%rax] -> R[%rdx]:R[%rax]`
      - `mulq S` : `S * R[%rax] -> R[%rdx]:R[%rax]`
    - 이전에 나왔던 `imulq S, D`와는 오퍼랜드의 갯수로 구분한다.
    
2. 나누기 연산
    - 부호있는 / 부호없는 것에 따라 나눗셈 명령어가 갈린다.
      - `idiv S` : 부호 있는 정수
      - `div S` : 부호 없는 정수
    - 그리고 비트 수에 따라 나누어지는 수의 형태가 달라진다.
      - 8비트 : `%ax` - 워드 크기
      - 16비트 : `%dx : %ax` - 더블 워드 크기
      - 32비트 : `%edx : %eax` - 쿼드 워드 크기
      - 64비트 : `%rdx : %rax` - 옥트 워드 크기
    - 그리고 나머지와 몫을 따로 저장한다.
      - 8비트 : `%al`(몫) / `%ah`(나머지)
      - 16비트 : `%ax`(몫) / `%dx`(나머지)
      - 32비트 : `%eax`(몫) / `%edx`(나머지)
      - 64비트 : `%rax`(몫) / `%rdx`(나머지)
    - 그리고, 두 레지스터를 사용해서 나누어지는 수를 표현하기 때문에,
    사전에 상위 레지스터로 부호 확장을 해주어야 한다.
      - 부호 없는 나눗셈인 경우, 
      상위 레지스터를 단순히 0으로 비우면 되고,
      - 부호 있는 나눗셈임 경우,
        - 8비트 : `cbtw`
        - 16비트 : `cwtd`
        - 32비트 : `cltd`
        - 64비트 : `cqto`
      - 를 사용해서 상위 비트를 저장할 레지스터의 값을 부호에 맞게 설정해야한다.

### 느낀 점 & 배운 점

이번 파트는 뭔가
64비트 레지스터만 있는 상황에서
어떻게든 128비트의 값을 표현하려고
CPU 만드는 사람(단어가 생각이 안난다..)들이
죽어라 똥꼬쇼한 결과물인 것 같아..

64비트 레지스터 두 개(`%rdx` / `%rax`)에
상위 64비트 / 하위 64비트로 값을 나눠 담는 아이디어는
참 직관적이면서 구현하기는 어려울 것 같은 아이디어야.

그리고 나눗셈도 처음에 나누어지는 수를 두 개의 레지스터로 나눠서 표현하도록 해서,
뭔가 몫과 나머지를 저장할 레지스터를 
사전에 해당 나눗셈과 관련 없는 곳에서 사용하는 그런 상황을
막을 수 있는 것 같아.
(내 추측일 뿐임)

좀 더 찾아봤는데,
애초에 나눗셈이 `w * 2`비트의 수를 `w`비트의 수로 나누는 연산이라고 하네..
앞서 설명했던 곱셈에서 이어지는 식으로,
`64비트 * 64비트` 해서 128비트가 나왔으니,
`128비트 / 64비트` 하면 64비트가 나오게 한다는거지.
