## 1챕터 요약

### 1. 동시성이 뭐냐?

논리적으로 동시에 작업이 실행되는거. 무조건 물리적으로 동시에 실행되는건 아님.
물리적으로 동시에 실행되는건 병렬성이라고 함.

동시성은 여러 작업이 논리적으로 같은 시간 구간 동안 함께 진행되는 것.
(병렬적으로 실행될 수도 있긴 함)

- 동시성 : 여러 일을 동시에 다루는 것
- 병렬성 : 실제로 여러 일을 동시에 처리하는 것

### 2. 동시성 왜 씀?

1. 멀티 코어 프로세서에서 병렬성을 극대화하기 위해서 쓴다.
2. 관련 있는 코드들은 한 스레드에 모으고, 관련 없는 코드들은 서로 분리해서
프로그램의 가독성과 유지보수성을 높일 수 있다.

#### 언제 동시성 쓰면 안됨?

그냥, 동시성 쓰는 것보다 비용이 클 때.
예를 들어 

- 동시성 프로그래밍을 하면 쓸데없이 버그만 많이 생기고 성능 개선은 크게 없다거나

이럴 때.

## 2챕터 요약

### 1. 스레드들을 관리해보자.

#### 스레드 생성

```cpp
#include <thread>

void dosomething1(){
    // 대충 작업
}

int dosomething2(int value){
    // 대충 작업
}

int main() {
    std::thread t1(dosomething1); // callable한 객체로 스레드 생성
    std::thread t2 = std::move(t1); // 복사 불가능
    
    t1 = std::thread(dosomething1);
    t1 = std::move(t2); // 이미 작업이 할당된 스레드 객체에 다시 스레드 객체 소유권 넘기기 불가능
    // 즉, std::thread 객체가 thread를 소유중일 때(joinable할 때) 
    // 다른 스레드의 소유권을 넘겨줘도 std::terminate()가 호출된단 말임.
    // join() 하든 detach() 하든 소유 중인 스레드를 처리해아함.
    
    std::thread t4(dosomething2, 10); // 매개변수가 있는 경우 이렇게 쓰면 됨
}
```

#### 스레드 종료 시까지 기다리기 + 예외가 발생한 경우

```cpp
#include <thread>

void dosomething1(){
    // 대충 작업
}

int main() {
    std::thread t1(dosomething1);
    
    t1.join(); // t1 스레드가 종료될 때까지 기다리기
    
    std::thread t2(dosomething1);
    
    // 어쨌든 많은 동작
    // join()과 스레드 생성 사이에 main() 함수에서 예외가 던져져서 해당 스레드 객체가 날아가면 어캄?
    
    t2.join();
}
```

이렇게 `join()`과 스레드 생성 사이에 예외가 던져지면
`join()` 함수가 제대로 실행이 안될 수 있는데,
단순 `try-catch` 식 예외 처리 말고도

RAII 패턴을 적용해서 이런 경우를 예방할 수 있다.

```cpp
// 단순 try-catch

std::thread t1(dosomething);
try {
    // 어쨌든 많은 동작, 이 사이에 main()에서 예외가 발생하면 catch 쪽이 실행됨
}
catch (...) {
    t1.join();
    throw;
}
t1.join();
// main() 함수가 정상적으로 종료되든 예외로 종료되든 join() 보장
// 하지만 코드의 가독성은 좋지 않아질 수 있음..

// 그렇기 때문에, 스레드 객체를 객체로 감싸서 소멸자에서 자동으로 join() 해주는 RAII 패턴도 사용할 수 있음.

class ThreadGuard {
private:
    std::thread& t;
public:
    explicit ThreadGuard(std::thread& t_) : t(t_) {
    
    }
    ~ThreadGuard() { // 해당 객체가 스코프를 벗어나 소멸할 때 자동으로 join()
        if (t.joinable()) {
            t.join();
        }
    }
    
    // 스레드 객체는 복사되면 안되므로 복사 생성자 무효화
    ThreadGuard(const ThreadGuard&) = delete;
    ThreadGuard& operator=(const ThreadGuard&) = delete;
    
};
```

#### 스레드 백그라운드에서 실행

```cpp
#include <thread>

void dosomething1(){
    // 대충 작업
}

int main() {
    std::thread t1(dosomething1);
    
    t1.detach(); // 실제 스레드와 해당 스레드 객체 간의 연결을 끊어서 백그라운드에서 스레드가 실행될 수 있게 함.
    // 하지만 해당 스레드의 종료를 확인하지는 못함.
    // detach 이후에는 해당 스레드 객체를 통해 해당 스레드의 수명에 관여할 수가 없어서
    // 해당 스레드가 참조하고 있는 객체의 생명주기에 특히 주의해야함.
}
```

`detach()` 함수로 가능함.

#### 스레드 식별하기

스레드마다 별개의 `ThreadID`가 있는데,
`std::thread::id`의 형식으로 저장하고
`get_id()` 함수로 반환받을 수 있음.

그리고 이렇게 반환받은 `ThreadID`로 스레드를 식별할 수 있음.

지금 당장 실행되고 있는 해당 스레드의 `ThreadID`를 반환받으려면
`std::this_thread::get_id()`를 호출하면 됨.

```cpp
std::thread::id master_thread_id;
void dosomething() {
    if (std::this_thread::get_id() == master_thread_id) {
        // 대충 master thread만 할 수 있는 작업
    }
}
```

#### 결국 이 챕터가 말하는게 뭐냐?

> `std::thread` 객체를 그냥 날려버리지 말고,
> `std::thread` 객체가 소유한 스레드의 생명주기를 끝까지 확실히 책임져라.
