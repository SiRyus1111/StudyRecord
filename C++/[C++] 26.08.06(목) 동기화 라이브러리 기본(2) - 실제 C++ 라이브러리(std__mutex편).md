## 0. 서론

저번 글에서 동기화 라이브러리를 하자고 해놓고
그냥 

- 원자성 / 가시성 / 순서성
- 캐시 일관성 / MESI 프로토콜 / 캐시락
- 메모리 배리어 / release-acquire / happens-before

이런 이야기만 해서
싹다 CS이야기 범벅이었는데,
이번에는 진짜 제대로 C++의 동기화 라이브러리를 공부해볼거야.

- 뮤텍스의 종류
  - `mutex`
  - `timed_mutex`
  - `recursive_mutex`
  - `shared_mutex`
- 뮤텍스 소유권 관리 도구
  - `lock_guard`
  - `unique_lock`
  - `scoped_lock`
  - `shared_lock`
- 특수 락 태그
  - `defer_lock`
  - `try_to_lock`
  - `adopt_lock`

이 세 가지 주제로 한번 제대로 C++ 동기화 라이브러리를 공부해보자.

초반의 OSTEP / 공룡책 기반 간단한 뮤텍스 설명 파트를 제외하고는
내부 구현이라기보단 사용법 위주의 글이 될거야.
각 뮤텍스 / 소유권 관리 도구 / 특수 락 태그가 어떻게 돌아가는지보단 
어떤 역할을 하고 어떻게 사용되는지 느낌이야.

아, 참고로, 이 글에서는 `std::atomic` 관련 함수들은 다루지 않아.

애초에 이걸 다시 공부하는 목적이
내가 룸 시스템을 설계하다가 읽기 / 쓰기 락을 분리해야하는 경우가 생겨서.

한 `weak_ptr`에 대한 동기화 문제였는데,

- 읽기 도중에 쓰면 안되고(읽기는 가능)
- 쓰기 도중에 쓰거나 읽으면 안되서

읽기 / 쓰기 락을 분리하는 도구가 있다는게 어렴풋이 생각이 났거든.
이왕 쓸거면 제대로 알고 쓰자 이거지.

## 1. 뮤텍스란 뭘까?

(OSTEP 기반 간단한 뮤텍스 설명 파트임)

조금 짧게 설명할게.

뮤텍스란,

> 여러 실행 흐름이 공유 자원을 건드려서
> 실행 순서에 따라 결과가 달라져서 문제가 발생하는 것

인 레이스컨디션을 막기 위해서

> 공유 자원에 접근하는 코드 구역

인 임계 구역에 대한 

> 한 번에 한 스레드만 임계 구역에 들어올 수 있게 하는 것

인 상호 배제를 실행하는 동기화 도구라고 할 수 있어.

임계 구역 앞 / 뒤에 `lock()` / `unlock()`을 수행해서
이미 한 스레드가 락(뮤텍스)을 얻었다면 
다른 스레드는 해당 공유 자원에 대한 임계 구역 안으로 들어갈 수 없게 하는 식으로
상호 배제를 수행하지.

그리고 좀 자세하게는 `lock()` / `unlock()`을 원자적으로 수행해서
오직 한 스레드만 해당 락을 획득할 수 있게 해.

현대의 blocking 뮤텍스의 일반적인 경우,

- `lock()` / `unlock()`을 원자적으로 수행해서 
오직 한 스레드만 락을 획득할 수 있도록 하고(상호 배제를 갖춤)
- spin-lock 방식의 락 획득 방식 대신 
락 획득에 실패한 스레드를 재우고 큐에 담아서 차례대로 락을 획득할 수 있게 하는(공정성을 갖춤)

이런 방식으로 동작해.

- `lock()` / `unlock()`을 수행하는 원자적 연산은
  - Test-And-Set : 일단 바꾸고 기존 값 반환하기
  - Compare-And-Swap : 기대하는 값과 같다면 바꾸기
  
등이 있어.

이 정도면 기초적인 뮤텍스 설명은 다 끝난듯.

바로 라이브러리 설명으로 넘어가자.
