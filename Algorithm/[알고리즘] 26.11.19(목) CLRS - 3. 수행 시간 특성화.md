## 1. 왜 시간복잡도의 최고차항만 보면 되는가?

한 줄로 요약하면,
입력 크기가 커질수록
결국 시간복잡도에 영향을 가장 많이 끼치는건
해당 알고리즘의 수행 시간의 최고차항이기 때문이야.

대충 이런 알고리즘이 있다고 하자.

```cpp
for (int i = 0; i < n; i++) {
    for (int j = 0; j < n; j++) {
        for (int k = 0; k < n; k++) {
            // 뭐시기
        }
    }
}

for (int i = 0; i < n; i++) {
    for (int j = 0; j < n; j++) {
        // 뭐시기
    }
}

for (int i = 0; i < n; i++) {
    // 뭐시기
}

// 뭐시기
```

입력 크기 $n$에 대해서,
$n^3 + n^2 + n + 1$의 수행 시간을 가지겠지.
(`뭐시기`의 수행 시간이 1이라고 가정하면)

근데 이거 봐봐,

| n의 크기 | $n^3$ | $n^2$ | $n$ | $1$ |
|---|---|---|---|---|
| $1$ | $1$ | $1$ | $1$ | $1$ |
| $100$ | $10^{6}$($1000000$) |$10^{4}$($10000$)|$10^{2}$($100$)|$1$|
| $10000$ | $10^{12}$($1000000000000$) | $10^{8}$($100000000$) | $10^{4}$($10000$) | $1$ |

이렇게 입력 크기인 $n$이 커지면
최고차항일수록 더 큰 비중을 차지하게되지?

$n = 100$만 되어도
최고차항($n^3$)이 전체 수행 시간의 99%를 차지해.

이번에는 고작 입력 크기를 $10000$밖에 안 했을 뿐,
실제로는 $n$이 몇백만을 찍는 경우도 많아.

만약 $n$이 $1000000$(백만)을 찍었다?
그러면 $n^3$은 $10^{18}$이 찍혀나오고,
$n^2$는 $10^{12}$가 찍혀나오고,
$n$은 $10^{6}$이 찍혀나오겠지.

(컴퓨터는 1초에 약 $10^8$ ~ $10^9$번 연산함)

결국 요약하면 이거야,
처음에 말했던 것처럼
점근적으로 봤을 때는,
즉 $n$을 충분히 크게 봤을 때는
수행 시간에 끼치는 최고차항의 비중이 압도적이다.
그래서 보통 시간복잡도를 볼 때는 최고차항만 본다.

충분히 크게가 무슨 말인지 잘 이해가 안될 수 있는데,
그냥 $n$을 극한으로 키웠을 때라고 보면 편해.

## 2. 점근적 표기법

알고리즘의 수행 시간,
즉 시간 복잡도는 방금 말했듯이 점근적인 표기로 알 수 있어.

- 빅-오(big-$O$) : 상한(최악과 연관됨)
- 빅-오메가(big-$\Omega$) : 하한(최선과 연관됨)
- 빅-세타(big-$\Theta$) : 상한이면서 하한인 경계

이제 각각의 표기가 뭘 의미하는지 살펴보자.

### 2-1. big-$O$ 표기법

일단 수학적 정의부터 박아넣고 가자.

$O(g(n))$ = $\{T(n) : n \geq n_{0}$에 대해 $0 \leq T(n) \leq cg(n)$인 양의 상수 $c$와 $n_{0}$가 존재한다.$\}$

솔직히 무슨 말인지 모르겠지?
나도 그랬어.

좀 풀어서 이해해보자면,

$O(g(n))$이란, 
함수의 원래 시간복잡도 $T(n)$에 대해서
어떤 상수 $n_{0}$ 이상의 $n$들과
어떤 양의 상수 $c$에서는
모두 $0 \leq T(n) \leq cg(n)$이라는 것이다.

솔직히 이것도 이해가 잘 안되겠지?

이거 설명하기가 어렵네..

그러니까 점근적으로 봤을 때,
$n$을 어떤 상수 $n_{0}$ 이상으로 봤을 때
함수의 그래프 관점에서 $cg(n)$이 항상 
함수의 복잡도인 $T(n)$을 위에서 덮어준다는거야.

그러니까,
$n$이 몇 이상일 때부터는
$g(n)$에 $c$를 곱하면
무조건 $T(n)$의 그래프의 값보다 크다는건데..

이건 함수의 그래프를 보고 설명하는게 좋을 것 같네..
