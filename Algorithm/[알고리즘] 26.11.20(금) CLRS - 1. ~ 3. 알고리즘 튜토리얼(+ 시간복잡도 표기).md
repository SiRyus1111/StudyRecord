## 1. 알고리즘이란?

알고리즘은 어떤 값이나 값의 집합인 입력을 받아
특정 값이나 값의 집합인 출력을 내보내는
잘 정의된 계산 절차를 말한다고 해.

이렇게 엄밀하게 알고리즘을 정의하는 것도 참 재밌네ㅋㅋ

쉽게 말하면 함수 / PS 생각하면 돼.
책에서도 PS 느낌의 예시를 들고있어.
근데 솔직히 PS 느낌의 문제들도 현실에 충분히 적용 가능하다보니까..

결국 어떤 입력을 받아서
조건에 만족되는 출력을 내보내는 계산 절차(Computational Procedures)라고 할 수 있겠네.

예를 들어 정렬 알고리즘 같은 경우에는,
임의의 수열 $\{a_{1}, a_{2}, a_{3}, \dots\}$를 Input으로 받아서,
$a_{1}^{\prime} \leq a_{2}^{\prime} \leq a_{3}^{\prime} \leq \dots$을 만족하는 수열을 Output으로 내보내겠지.

그 중간의 입력을 출력으로 바꾸는 절차를 알고리즘이라고 할 수 있겠고.

그리고 저런 입력은 문제에서 정의하는 입력의 조건을 만족해야해.
그리고 입력의 조건을 만족하는 입력을 문제의 사례(Instance)라고 하고.
사례는 해당 문제의 해를 계산하기 위해 필요한 입력이라고 보면 돼.

백준 풀다보면 입력이 조건으로 주어지잖아?
그 입력 조건에 맞춘 입력값을 사례라고 한다는거임.

알고리즘이 모든 사례에 대해 항상 올바른 출력을 내면,
이걸 타당하다고 해.

근데 이런 용어들은 재미 없으니까
이 정도로 줄일게.

그리고 결국 효율적인 알고리즘을 쓰는게 중요하지.
같은 데이터를 처리하는데도 더 빠른 시간 내에 처리할 수 있으니까..

### 요약

1. 알고리즘이란 임의의 조건의 Input을 받아 조건에 맞는 Output을 내보내는 계산 절차이다.
2. 입력 조건에 맞는 입력을 Instance라고 한다.
3. 모든 Instance에 대해 항상 올바른 Output을 내면 해당 알고리즘은 타당하다고 한다.

## 2. 알고리즘의 분석

알고리즘의 분석은
해당 알고리즘을 실행하는데 필요한 자원을 예측하는거래.

보통은 주로 계산 시간을 예측하지.

### 2-1. 알고리즘 분석의 환경

그리고 알고리즘을 분석할 때는 
이용할 구현 기술의 모델을 정의해야하는데,
일반적으로는 단일 프로세서 / 임의 접근 머신(Random Access Machine) 모델에서
컴퓨터 프로그램으로 구현된다고 가정해.

#### 2-1-1. RAM 모델

RAM 모델은

- 명령어는 동시적으로 실행되지 않고 순차적으로 실행되며,
- 변수값을 사용하거나 변수에 저장하는 것이 다른 데이터 접근과 동일한 시간이 걸리고
(배열 인덱싱 포함)
- 캐시 / 가상 메모리 등 메모리 계층을 고려하지 않는

모델이라고 볼 수 있어.

더 엄밀하게 보면 각 명령어의 비용을 일일히 따로 쓸 수도 있지만,
현실적으로 그렇게 하면 너무 복잡해지기 때문에
보통은 
변수 사용 / 저장 / 단일 연산이 모두 상수 시간인
일반화된 RAM 모델을 사용해.

물론 실제와는 분명히 차이가 있을 수 있으니까
일반화된 RAM 모델에 너무 매몰되는 것도 좋지는 않지만,
이 정도로도 알고리즘을 분석하는데는 충분하기 때문에
일반화된 RAM 모델을 사용해.

그리고 추가적으로,
RAM 모델에서는 메모리 계층,
즉 가상 메모리나 캐시 메모리 등을 고려하지 않아.
(즉, 배열과 연결 리스트를 순회하는 비용이 같다는 것.)
(연결 리스트는 캐시 / TLB 히트율이 떨어지기 때문에 실제 실행시키면
연결 리스트가 더 오래 걸림)

이건 RAM 모델의 한계라고도 할 수 있지.

### 2-2. 알고리즘 분석하는 법

그리고, 이게 실제 실행 시간을 측정하는 방법으로는
기기에 따라, 컴파일러, 입력에 따라 편차가 있을 수 밖에 없기 때문에
실제 실행해보는 방법으로는 알고리즘의 시간복잡도를
일관성있게 분석할 수 없어서
일반적으로는 코드만 보고 분석을 해.
(물론 실무에서는 당연히 실행을 시켜봐야하는 경우도 있겠지만,
알고리즘이라는 학문에서는 실제 실행보다는 논리적으로 걸리는 시간만 본다는거임.)

이건 미리 알아두는게 좋을 것 같아서.

그리고 알고리즘은 보통
**입력 형태에 따른 수행 시간**과
**입력 크기에 따른 수행 시간 증가**로 분석돼.

입력 크기는 보통 입력 항목의 개수가 되고,
(입력 항목의 개수가 안 되는 경우도 있긴 함)
수행 시간은 알고리즘의 연산과 데이터 접근 시간을 합한 것이라고 할 수 있어.

#### 2-2-1. 최선의 경우, 최악의 경우, 평균의 경우

입력 크기($n$)가 같아도 입력 형태에 따라
수행 시간이 달라질 수 있어.

삽입 정렬같은 알고리즘을 예로 들어보면,

- 최선의 경우 : 가장 빨리 끝나는 입력 - 배열이 이미 다 정렬되어있는 경우
- 최악의 경우 : 가장 오래 걸리는 입력 - 배열이 역순으로 정렬되어있는 경우
- 평균의 경우 : 모든 입력이 똑같은 확률로 나온다고 했을 때의 기대 시간

이렇게 나눌 수 있겠네.

근데 보통은 최악의 경우를 기준으로 분석해.

어떤 입력이 들어와도 해당 시간은 넘지 않는다는 보장이 되고,
최악이 생각보다 자주 나오며,
평균과 최악의 증가율이 비슷한 경우가 많아서 그런거야.

반면 어떤 경우에는 평균의 경우가 중요한 경우가 있기도 해.

### 요약

1. 알고리즘 분석이란 보통 알고리즘이 수행될 때 필요한 자원을 예측하는 것이고,
보통은 실행 시간을 예측한다.
2. 알고리즘 분석의 환경은 보통 싱글 프로세서 + RAM(Random Access Machine) 모델을 기준으로 한다.
    - RAM 모델이란, 명령어가 순차적으로 실행되고
    접근 / 저장 / 연산이 다 같은 시간동안 실행되며
    캐시 / 가상 메모리 등의 메모리 계층도 무시하는 모델이다.
3. 알고리즘은 입력 형태에 따른 수행 시간과 입력 크기에 따른 수행 시간의 변화량을 기준으로 분석된다.
    - 입력 형태에 따른 수행 시간은
      - 최선의 경우 : 입력이 가장 빠르게 처리할 수 있는 경우
      - 최악의 경우 : 입력이 가장 느리게 처리되는 경우
      - 평균의 경우 : 입력들이 랜덤으로 들어오는 경우
      가 있다.

## 3. 추가 내용

책에서는 정렬 알고리즘 중 삽입 정렬 / 병합 정렬을 가지고 이 내용들을 차근히 설명해.

- 삽입 정렬 : 루프 불변성이 무엇인가
  - 요약 : 
    - 초기화 : 루프를 시작하기 전에 불변식이 참인가
    - 유지 : 루프를 돌 때마다 불변식이 참인가
    - 종료 : 초기화 + 유지를 이용해서 루프 종료 시에도 불변식이 참인가
    - 이런 루프 불변성을 이용해서 알고리즘의 정당성을 증명할 수 있다.
- 삽입 정렬 : 평균 / 최선 / 최악을 대충 어떻게 추론해낼 수 있나
  - 요약 :
    - 최선 : 가장 시간이 적게 걸리는 입력을 넣으면 된다.
    ($n$을 제외한 모든 변수에 1 넣기)
    - 최악 : 가장 시간이 많이 걸리는 입력을 넣으면 된다.
    ($n$을 제외한 모든 변수에 가능한 최댓값 넣기)
    - 평균 : 모든 입력이 비슷한 빈도로 나타난다고 가정하면 된다.
- 삽입 정렬 : 증가 차수가 무엇인가
  - 요약 : 수행 시간의 가장 높은 항의 차수만 가지고 알고리즘의 효율성을 평가하는 것이다.
- 병합 정렬 : 재귀란 무엇인가
  - 같은 함수를 해당 함수 안에서 호출하는 것(자기 자신을 재귀적으로 여러 번 호출하는 것)
- 병합 정렬 : 분할 정복이 무엇인가
  - 말 그대로 분할 후 각각의 영역을 정복하는 것.
    - 분할 : 현재의 문제를 같은 문제를 다루는 다수의 부분 문제로 분할
    - 정복 : 부분 문제를 재귀적으로 풀어서 정복
    - 결합 : 부분 문제의 해를 모아서 원래 문제의 해를 만듬
    - 이렇게 세 과정을 거친다.
- 병합 정렬 : 각 부분들로 어떻게 최종적인 수행 시간을 만드나
    - 부분 문제의 시간복잡도로
    전체의 시간복잡도를 나타내는 
    점화식으로 수행 시간을 설명할 수 있다.
    - 예(분할 정복의 수행 시간 분석) : 
    $$
    T(n) = 
    \begin{cases}
    \Theta(1) & (n < n_{0}) \\
    \Theta(1) + 2T(n/2) + \Theta(n) & \text{otherwise}
    \end{cases}
    $$
      - 최악의 경우, $2T(n/2) + \Theta(n)$의 수행 시간이 필요하다.($\Theta(1)$은 $\Theta(n)$과 합쳐짐)
      - $n$이 매우 작을 때는 $\Theta(1)$의 수행 시간을 가지지만,
      $n$이 매우 작지 않을 때는
      분할($\Theta(1)$)(가운데만 나누면 되므로 상수 시간 가능)
      + 정복($2T(n/2)$)(반으로 나눈 문제를 양쪽 다 해결하니)
      + 병합($\Theta(n)$)(반으로 나눈 문제를 합치니)
      의 수행 시간을 가진다.
      - 추가적으로 재귀 트리를 이용해서
      리프 노드 수 $n$을 기반으로
      $\log_{2} n + 1 = \text{총 레벨 수}$이므로
      ($n/2^{k}$를 이용하면 이 공식이 나옴. $+1$은 최상위 노드($k=0$일 때))
      모든 레벨의 비용을 더하면 $c_{2} n \log_{2} n + c_{1}n$

이 정도 내용들이 있는데,
나는 솔직히 이걸 각 알고리즘의 예시를 들며 글로 엮어쓸 자신이 없어서 요약 느낌으로만 썼어..

## 4. 수행 시간 특성화

알고리즘의 수행 시간은
$n$이 충분히 커졌을 때
결과에 영향을 압도적으로 크게 미치는 최고차항을 분석하는 것으로
더 간단하게 분석할 수 있어.

| n의 크기 | $n^3$ | $n^2$ | $n$ | $1$ |
|---|---|---|---|---|
| $1$ | $1$ | $1$ | $1$ | $1$ |
| $100$ | $10^{6}$($1000000$) |$10^{4}$($10000$)|$10^{2}$($100$)|$1$|
| $10000$ | $10^{12}$($1000000000000$) | $10^{8}$($100000000$) | $10^{4}$($10000$) | $1$ |

이렇게 되거든.

$n$의 크기가 100만 되어도,
$n^3$의 비중이 전체 수행 시간의 99%야.

대충 최고차항만 남겨두는 이유는 알겠지?

이 관점을 바탕으로 점근적 표기법들을 배워보자.

점근적 표기법으로는 보통

- big-$O$ : $n$에 따른 수행 시간의 점근적 상한
- big-$\Omega$ : $n$에 따른 수행 시간의 점근적 하한
- big-$\Theta$ : 상한과 하한이 겹치는 지점

이렇게 세 가지를 써.

이제 각각의 점근적 표기법을 자세히 알아보자.

### 4-1. big-$O$ 표기법

앞에서 설명한 것처럼,
big-$O$ 표기법은 점근적으로 봤을 때의,
즉 $n$을 충분히 크게 봤을 때의 상한이라고 할 수 있어.

직관부터 잡고 가자면,

> $O(g(n))$의 $g(n)$은 추가적으로 어떤 양의 정수 $c$를 곱했을 때($cg(n)$) 
> $n$이 작을 때는
> 해당 알고리즘의 수행 시간($f(n)$)의 그래프보다 작을 수도 있지만,

> $n$이 충분히 커졌을 때는(점근적으로 봤을 때는)
> 해당 알고리즘의 수행 시간의 그래프보다 $cg(n)$이 무조건 커지고,
> 수행 시간의 그래프보다 다시는 작아지지 않다는 의미

라고 할 수 있어.

핵심은,
$n$이 충분히 커졌을 때
해당 알고리즘의 수행 시간의 그래프보다 $cg(n)$이 무조건 커지고
해당 알고리즘의 수행 시간의 그래프보다 다시는 작아지지 않는다는거야.

그러니까 상한이 되어줄 수 있어.

예를 들어 $f(n) = 7n^2 + 3$이라고 해보자,
$g(n) = n^2$일 때
$n \geq 1$에서($n$을 충분히 크게 봤을 때)
$10g(n) = 10n^2$가
$7n^2 + 3$보다 무조건 크지?

이렇다는거야.
(물론 $g(n) = n^3$, $g(n) = 2^n$같은 더 큰 것도 해당돼.)
(이게 나름 핵심일수도?)

좀 더 엄밀한 정의는,

> $O(g(n)) = \{f(n) :$ 모든 $n \geq n_{0}$에 대해
$0 \leq f(n) \leq cg(n)$인 양의 정수 $c$와 $n_0$이 존재한다. $\}$

라는건데,

내가 위에서 설명한걸 좀 더 엄밀하게,
하지만 이해하기는 어렵게 설명한거라고 보면 돼.

엄밀한 정의를 요약하면,
$O(g(n))$이란
'$n \geq n_{0}$일 때
$cg(n)$이 무조건 $f(n)$보다 크거나 같다'라고 할 수 있다는거임.

추가적인 조건으로,
당연하지만 $n$의 변화에 따른 수행 시간인 $f(n)$은
점근적으로 봤을 때,
즉 $n \geq n_{0}$으로 봤을 때 
음수가 나오는 구간이 있어서는 안되고..

### 4-2. big-$\Omega$ 표기법

이것도 앞에서 설명한 것처럼,
big-$\Omega$ 표기법은
점근적으로 봤을 때의,
즉 $n$을 충분히 크게 봤을 때의 하한을 나타내는 표기법이라고 할 수 있어.

이것도 위의 big-$O$와 직관은 같아.

> $\Omega(g(n))$의 $g(n)$은 추가적으로 어떤 양의 정수 $c$를 곱했을 때($cg(n)$) 
> $n$이 작을 때는
> 해당 알고리즘의 수행 시간($f(n)$)의 그래프보다 클 수도 있지만,

> $n$이 충분히 커졌을 때는(점근적으로 봤을 때는)
> 해당 알고리즘의 수행 시간의 그래프보다 $cg(n)$이 무조건 작아지고,
> 수행 시간의 그래프보다 다시는 커지지 않다는 의미

사실,
그냥 복붙하고 반대로 쓴거야..

진짜로 big-$O$와 직관은 같아.

예를 들어,
$f(n) = 7n^2 + 3$이라고 해보자.
$g(n) = n^2$일 때
$n$이 임의의 양의 정수일 때,
$6g(n) = 6n^2$가
$7n^2 + 3$보다 무조건 작을테지?

(물론 $g(n) = n$, $g(n) = log n$같은 더 작은 것도 됨.)
(이것도 나름 핵심일수도?)

좀 더 엄밀한 정의는,

> $\Omega(g(n)) = \{ f(n):$ 모든 $n \geq n_{0}$에 대해
$0 \leq cg(n) \leq f(n)$인 양의 상수 $c$와 $n_{0}$이 존재한다 $\}$

라고 할 수 있어.

엄밀한 정의를 요약하면,
$\Omega(g(n))$이란
'모든 $n \geq n_{0}$에 대해
$cg(n)$이 $f(n)$보다 무조건 작거나 같다'라고 할 수 있다는거임.

### 4-3. big-$\Theta$ 표기법

이건 앞의 big-$O$와 big-$\Omega$를 겹친거라고 보면 돼.
명확한 이름은
점근적으로 엄밀한 경계(asymptotically tight bound)라고 할 수 있어.

이건 그냥 엄밀한 정의를 바로 보자.

> $\Theta(g(n)) = \{ f(n) :$ 모든 $n \geq n_{0}$에 대해
> $0 \leq c_{1}g(n) \leq f(n) \leq c_2g(n)$인 양의 정수 $c_{1}$, $c_{2}$, $n_{0}$이 존재한다.$\}$

라고 할 수 있어.

그러니까,
기존에 big-$O$와 big-$\Omega$를 합치는 느낌으로,
$c_{1}g(n)$(하한)과 $c_{2}g(n)$(상한) 사이에 들어가는 $f(n)$이라는거야.

상한과 하한을 겹치는거지.

정확히 말하면 상한이 될 수 있는 함수들($O(g(n))$)과
하한이 될 수 있는 함수들($\Omega(g(n))$)의 교집합이라고 할 수 있어.

그리고 여기서 도출해낼 수 있는 결론이 있어.
$f(n) = O(g(n))$이고,
$f(n) = \Omega(g(n))$이라면
$f(n) = \Theta(g(n))$이다.

$f(n)$이 $O(g(n))$과 $\Omega(g(n))$에 모두 속하니
두 집합의 교집합인 $\Theta(g(n))$도 성립하는거지.

($6n^{2} \leq 7n^{2} + 3 \leq 10n^{2}$)

물론 그 반대도 성립해.

### 4-4. 점근적 표기와 수행 시간

그리고 이거 중요한게,
입력의 형태(최선 / 최악 / 평균)와 점근적 표기는 어느정도 분리해서 생각해야한다는거야.

모든 입력 형태에 대해 공통으로 적용할 수 있는 하나의 점근적 표기법을 선택한다고 가정해보자.

예를 들어,

삽입 정렬은 입력의 모양에 따라 수행 시간이 천차만별이기 때문에,
상한을 나타내는 점근적 표기인 big-$O$를 사용하고,

병합 정렬은 입력의 모양에 따라 수행 시간이 동일하기 때문에,
상한과 하한의 교집합을 나타내는 점근적 표기인 big-$\Theta$를 사용하는거지.

이해가 잘 안될 수도 있는데,
삽입 정렬같은 경우 입력이 어떤 형태로 들어오느냐에 때라
$\Theta(n)$ ~ $\Theta(n^2)$이 될 수 있게 돼.
(이미 다 정렬되어있으면(최선) $\Theta(n)$임..)
(하나도 정렬되어있지 않으면(최악) $\Theta(n^2)$이고..)
그래서 어떤 입력이 들어오든 최선의 경우에도 최악의 경우에도 $O(n^2)$은 **안 넘는다**는 느낌으로
상한을 나타내는 표현인 big-$O$를 쓰면 편한거야.
최선 / 최악에 따라 big-$\Theta$가 좀 흔들리니까.

병합 정렬같은 경우 입력이 어떤 형태로 들어와도
무조건 반으로 계속 쪼개고 다시 합치는 과정을 반복하기 때문에
최선도 $\Theta(n \log n)$이고, 최악도 $\Theta(n \log n)$이기 때문에
안심하고 big-$\Theta$를 사용해도 되는거야.

결국
입력의 형태로부터 나오는

- 최선의 경우
- 최악의 경우
- 평균의 경우

와,

입력 $n$개가 들어왔을 때의

- big-$O$ : 상한
- big-$\Omega$ : 하한
- big-$\Theta$ : 상한과 하한의 교집합

은 분리해서 봐야한다는거야.

근데 솔직히 이 챕터 결론이

> 최선 / 최악 / 평균까지 고려해서
> 해당 알고리즘의 수행 시간을 안전빵인 상한(big-$O$)으로 표기할지,
> 더 엄밀한 표현인 상한과 하한의 교집합(big-$\Theta$)으로 표기할지 
> 올바르게 정해라.

라고 할 수 있을 것 같은데ㅋㅋ
(솔직히 이건 알고리즘 이론이라기보다 실무에 가까운 팁임..)

### 요약

1. 가장 수행 시간에 영향을 많이 미치는 최고차항만으로
알고리즘의 수행 시간을 추상화해서 표기할 수 있다.
2. 점근적으로 봤을 때,
즉 $n$을 충분히 크게 봤을 때의 수행 시간 표기법이 있다.
    - big-$O$(상한) : $O(g(n))$은 $n$을 충분히 크게 봤을 때 
    $cg(n)$이 $f(n)$보다 항상 크거나 같은 경우를 나타내는 표기이다.
    - big-$\Omega$(하한) : $\Omega(g(n))$은 $n$을 충분히 크게 봤을 때
    $cg(n)$이 $f(n)$보다 항상 작거나 같은 경우를 나타내는 표기이다.
    - big-$\Theta$(상한 $\cap$ 하한) : $\Theta(g(n))$에서 $n$을 충분히 크게 봤을 때
    $c_{1}g(n)$이 $f(n)$보다 항상 작거나 같으며
    $c_{2}g(n)$이 $f(n)$보다 항상 크거나 같은 경우를 나타내는 표기이다.
3. 입력의 형태(최선 / 평균 / 최악)와 점근적 표기법은 분리해서 봐야한다.
    - 최선 / 평균 / 최악의 경우에 각각 점근적 표기법을 적용할 수 있다.
    - 최선 / 평균 / 최악의 경우는 어떤 입력의 형태인지를 구분하고,
    big-$O$ / big-$\Omega$ / big-$\Theta$는
    그 입력의 형태에 대해 어떤 점근적인 표기인지를 나타낸다.
    - 입력의 형태에 따라 점근적으로 봤을 때의 상한 / 하한 / 교집합이 달라지면
    일반적으로 해당 알고리즘의 수행 시간의 상한은 굳건히 버텨주는
    big-$O$ 표기법이 좋다.
    - 입력의 형태에 상관없이 점근적으로 봤을 때의 상한 / 하한 / 교집합이 같다면
    일반적으로 해당 알고리즘의 수행 시간을 엄밀하게 나타내주는
    big-$\Theta$ 표기법이 좋다.
