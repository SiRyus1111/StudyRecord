## 1. 알고리즘이란?

알고리즘은 어떤 값이나 값의 집합인 입력을 받아
특정 값이나 값의 집합인 출력을 내보내는
잘 정의된 계산 절차를 말한다고 해.

이렇게 엄밀하게 알고리즘을 정의하는 것도 참 재밌네ㅋㅋ

쉽게 말하면 함수 / PS 생각하면 돼.
책에서도 PS 느낌의 예시를 들고있어.
근데 솔직히 PS 느낌의 문제들도 현실에 충분히 적용 가능하다보니까..

결국 어떤 입력을 받아서
조건에 만족되는 출력을 내보내는 계산 절차(Computational Procedures)라고 할 수 있겠네.

예를 들어 정렬 알고리즘 같은 경우에는,
임의의 수열 $\{a_{1}, a_{2}, a_{3}, \dots\}$를 Input으로 받아서,
$a_{1}^{\prime} \leq a_{2}^{\prime} \leq a_{3}^{\prime} \leq \dots$을 만족하는 수열을 Output으로 내보내겠지.

그 중간의 입력을 출력으로 바꾸는 절차를 알고리즘이라고 할 수 있겠고.

그리고 저런 입력은 문제에서 정의하는 입력의 조건을 만족해야해.
그리고 입력의 조건을 만족하는 입력을 문제의 사례(Instance)라고 하고.
사례는 해당 문제의 해를 계산하기 위해 필요한 입력이라고 보면 돼.

백준 풀다보면 입력이 조건으로 주어지잖아?
그 입력 조건에 맞춘 입력값을 사례라고 한다는거임.

알고리즘이 모든 사례에 대해 항상 올바른 출력을 내면,
이걸 타당하다고 해.

근데 이런 용어들은 재미 없으니까
이 정도로 줄일게.

그리고 결국 효율적인 알고리즘을 쓰는게 중요하지.
같은 데이터를 처리하는데도 더 빠른 시간 내에 처리할 수 있으니까..

### 요약

1. 알고리즘이란 임의의 조건의 Input을 받아 조건에 맞는 Output을 내보내는 계산 절차이다.
2. 입력 조건에 맞는 입력을 Instance라고 한다.
3. 모든 Instance에 대해 항상 올바른 Output을 내면 해당 알고리즘은 타당하다고 한다.

## 2. 예시 : 삽입 정렬 알고리즘과 알고리즘의 분석

이건 진짜 예시 느낌이야.

삽입 정렬을 분석해보고
삽입 정렬보다 더 나은 알고리즘을 설명해보는 예시지.

겸사겸사 삽입 정렬도 배우고.
(근데 나 삽입 정렬의 아이디어는 알고있긴 함.)

삽입 정렬은 말 그대로 정렬 알고리즘인데,

(초기 조건)
배열의 두 번째 인덱스부터 시작해서

(바깥 반복문)
삽입할 값인 키를 미리 빼두고

(안의 반복문)
계속 앞의 인덱스와 비교하며
앞의 인덱스가 키보다 크면 앞의 인덱스를 뒤로 한 칸 미루고
앞의 인덱스가 키보다 작으면 해당 인덱스에 키를 넣고 안의 반복문을 탈출하는

정렬 알고리즘이야.

이러면 정렬이 되지.

의사 코드로는,

```c
Insertion_sort(array) {
    
    for i = 1 to length(array)-1 {
    	key = array[i];
        
        j = i - 1;
        
        while j >= 0 and array[j] > key {
            array[j + 1] = array[j];
            j = j - 1;
        }
        
        array[j + 1] = key;
    }
}
```

이렇게 되겠고,

C++ 코드로는
(`int`형 사용)

```cpp
void insertion_sort(std::vector<int>& array) {

    int n = array.size(); // 배열의 크기만큼 반복하기 위해 미리 구해놓음
    
    for (int i = 1; i < n; i++) { // 첫 번째 원소는 이미 정렬되어있는걸로 침
    
        int key = array[i]; // key를 먼저 뽑아놓음
        int j = i - 1; // 0 ~ i - 1번 원소 사이에 key를 삽입하기 위해 이렇게 함
        
        // 0 ~ i - 1번 인덱스는 이미 정렬되어있음
        
        while ((j >= 0) && (key < array[j])) { // key가 j번 원소보다 작거나 같으면 루프 탈출
            array [j + 1] = array[j]; // j번째 원소를 j + 1번으로 밀음
            --j; // 더 이전의 원소를 탐색하기 위해 j를 1 줄임
        }
        
        array[j + 1] = key; // key를 j번 원소 바로 뒤에 삽입
    }
}
```

여기서 배열의 `0` ~ `i - 1`번째 원소들은
루프를 돌아도 무조건 정렬되어있는
루프 불변성(Loop Invariant)을 가진다고 해.

루프 불변성은

- 루프가 첫 반복을 시작하기 전에 참이어야 함
- 루프의 반복이 시작되기 전에 참이면 다음 반복이 시작되기 전에도 참이어야 함
- 루프가 종료될 때 그 불변식이 알고리즘의 타당성을 보이는데 유용한 특성을 가져야 함

이 세 가지 조건을 만족해야 성립돼.

삽입 정렬에서는,

- 루프가 첫 반복을 시작하기 전에 `0 ~ i - 1`(`0`)번 원소는
원소가 하나 뿐이므로 `0 ~ i - 1`번째 원소에 대해 정렬이 되어있고,
- 루프의 각 반복에서 `array[i]`(`key`)의 올바른 위치를 찾을 때 까지
`i - j`번째의 원소를 오른쪽으로 한 자리씩 이동시키며
`key`를 적절한 위치에 삽입하기 때문에
`0 ~ i - 1`번 원소에 대해 정렬이 되어있고,
- 루프가 종료될 때는 `i`가 `n`과 같아질 때 종료되니
`0 ~ n - 1`번 원소에 대해서는 정렬이 되어있으니
해당 알고리즘이 타당하므로

루프 불변성은 성립하게 돼.

이런 루프 불변성을 증명해서 알고리즘의 타당성을 증명하는거
나중에도 많이 나온다네..

AI한테 물어봤는데 수학적 귀납법을 반복문에 적용한거라더라..
귀납법이 이런거구나 싶네.

초기 조건($f(1)$) -> 중간 상태($f(k) \to f(k + 1)$) -> 최종 결론($f(n)$) 느낌?

### 요약

1. 삽입 정렬은 `i`번째 원소를 이미 정렬된 `0 ~ i - 1`번째 원소들 사이의
적절한 위치에 삽입하는 정렬 알고리즘이다.
2. 삽입 정렬의 타당성을 증명하기 위해서는 `0 ~ i - 1`번째 원소들의
루프 불변성을 증명하면 된다.
3. 루프 불변성이란,
    - 초기 조건이 불변식을 만족시키고(초기화)
    - 루프의 시작과 끝마다 불변식을 만족시키며(유지)
    - 루프의 종료 시에도 불변식을 만족시키며 알고리즘의 타당성을 증명할 수 있다는 것이다.(종료)
4. 삽입 정렬은
    - 초기 조건인 `0 ~ 0`번 원소(`0`번 원소)만으로 정렬이 되어있고(원소가 하나니까)
    (초기화)
    - 루프마다 `i`번 원소를 `0 ~ i - 1`번 원소들 사이에 적절한 위치에 삽입하므로
    루프의 시작과 끝마다 `0 ~ i - 1`번 원소는 정렬이 되어있으며
    (유지)
    - 루프에 끝에는 `0 ~ n - 1`번 원소들이 정렬이 되어있게 되니
    정렬 문제에 타당한 알고리즘이다.
    (종료)

### 2-1. 알고리즘의 분석

알고리즘의 분석은
해당 알고리즘을 실행하는데 필요한 자원을 예측하는거래.

보통은 주로 계산 시간을 예측하지.

그리고 알고리즘을 분석할 때는 
이용할 구현 기술의 모델을 정의해야하는데,
일반적으로는 단일 프로세서 / 임의 접근 머신(Random Access Machine) 모델에서
컴퓨터 프로그램으로 구현된다고 가정해.

RAM 모델은

- 명령어는 동시적으로 실행되지 않고 순차적으로 실행되며,
- 변수값을 사용하거나 변수에 저장하는 것이 다른 데이터 접근과 동일한 시간이 걸리고
(배열 인덱싱 포함)
- 캐시 / 가상 메모리 등 메모리 계층을 고려하지 않는

모델이라고 볼 수 있어.

더 엄밀하게 보면 각 명령어의 비용을 일일히 따로 쓸 수도 있지만,
현실적으로 그렇게 하면 너무 복잡해지기 때문에
보통은 
변수 사용 / 저장 / 단일 연산이 모두 상수 시간인
일반화된 RAM 모델을 사용해.

물론 실제와는 분명히 차이가 있을 수 있으니까
일반화된 RAM 모델에 너무 매몰되는 것도 좋지는 않지만,
이 정도로도 알고리즘을 분석하는데는 충분하기 때문에
일반화된 RAM 모델을 사용해.

그리고 추가적으로,
RAM 모델에서는 메모리 계층,
즉 가상 메모리나 캐시 메모리 등을 고려하지 않아.
(즉, 배열과 연결 리스트를 순회하는 비용이 같다는 것.)
(연결 리스트는 캐시 / TLB 히트율이 떨어지기 때문에 실제 실행시키면
연결 리스트가 더 오래 걸림)

이건 RAM 모델의 한계라고도 할 수 있지.

그리고, 이게 실제 실행 시간을 측정하는 방법으로는
기기에 따라, 컴파일러, 입력에 따라 편차가 있을 수 밖에 없기 때문에
실제 실행해보는 방법으로는 알고리즘의 시간복잡도를
일관성있게 분석할 수 없어서
일반적으로는 코드만 보고 분석을 해.
(물론 실무에서는 당연히 실행을 시켜봐야하는 경우도 있겠지만,
알고리즘이라는 학문에서는 실제 실행보다는 논리적으로 걸리는 시간만 본다는거임.)

이건 미리 알아두는게 좋을 것 같아서.

그리고 알고리즘은 보통
**입력 크기에 따른 수행 시간 증가**로 분석돼.

입력 크기는 보통 입력 항목의 개수가 되고,
(입력 항목의 개수가 안 되는 경우도 있긴 함)
수행 시간은 알고리즘의 연산과 데이터 접근 시간을 합한 것이라고 할 수 있어.


#### 2-1-1. 삽입 정렬의 분석

일단 앞에서 말하는 것처럼 일반적으로는 코드만 보고
얼마나 걸릴지 논리적으로 분석을 하거든?

앞에서 내가 보여준 삽입 정렬 코드를 보고,
각 줄을 실행하는데 걸리는 비용을 $ck$($k$는 상수)로 놓고,
실행하는 횟수까지 한번 세보자.
(수행 시간은 연산 + 데이터 접근 시간이니까.)

$\sum_{i = n}^{m} a_{i}$는 `sum(i = n, m, a_i)`로 씀.
(수식 표현이 어려워서..)

그리고 $t_i$란 중간에 `while`문에서 $i$값에 따라 실행되는 횟수라고 보자.

```cpp
void insertion_sort(std::vector<int>& array) {

    int n = array.size(); // c1, 1번 실행
    
    for (int i = 1; i < n; i++) { // c2, n번 실행
    
        int key = array[i]; // c3, n-1번 실행
        int j = i - 1; // c4, n-1번 실행
        
        while ((j >= 0) && (key < array[j])) { // c5, sum(i=1, n-1, t_i)번 실행
            array [j + 1] = array[j]; // c6, sum(i=1, n-1, t_i - 1)번 실행
            --j; // c7, sum(i=1, n-1, t_i - 1)번 실행
        }
        
        array[j + 1] = key; // c8, n-1번 실행
    }
}
```

알고리즘의 실행 시간은
각 줄의 실행 시간의 합이겠지?

즉,
입력 크기($n$)에 따른
삽입 정렬의 실행 시간($T(n)$)은

$$
T(n) = c_{1}1 + c_{2}n + c_{3}(n-1) + c_{4}(n-1) 
$$
$$
+ c_{5}(\sum_{i = 1}^{n-1}(t_i)) + c_{6}(\sum_{i = 1}^{n-1}(t_i - 1))+ c_{7}(\sum_{i = 1}^{n-1}(t_i - 1)) + c_{8}(n-1)
$$

이렇게 되겠지..

그리고 입력의 크기가 정해진 경우라도
어떤 입력이 주어지느냐에 따라
알고리즘의 수행 시간은 변하니까,(예를 들어, 입력 자체가 정렬되어있는 경우라던지)
$t_{i} = 1$인(`while`문을 실행할 필요가 없는)
최선의 상황도 구해보자면

$$
T(n) = c_{1}1 + c_{2}n + c_{3}(n-1) + c_{4}(n-1) + c_{5}(n-1) + c_{8}(n-1)
$$

이렇게 되겠지.

그리고 이 식들은 $c_{k}$로 합칠 수가 있어.

$$
T_{n} = (c_{2} + c_{3} + c_{4} + c_{5} + c_{8})n - (c_{3} + c_{4} + c_{5} + c_{8} - c_{1})
$$

최악의 경우도 보자.

배열이 완전히 역순으로 정렬되어있는게
모든 원소를 최대로 옮겨야 하니 최악의 상황이겠지.

그리고 `while`문을 최대로 돌아야하므로
$\sum_{i=1}^{n-1} t_{i} = \sum_{i=1}^{n-1} (i + 1)$겠지?
그러면 수열의 합 공식에 따라서
$\sum_{i=1}^{n-1}(i + 1) = \frac{n(n-1)}{2} + (n-1)$이겠고..

$$
T_{n} = c_{1}1 + c_{2}n + c_{3}(n-1) + c_{4}(n-1) + c_{5}() + c_{6}() + c_{7} + c_{8}
$$
