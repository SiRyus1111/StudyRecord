I/O 멀티플렉싱의 개념과 `select()` 함수를 공부해볼 생각이야.

## 1. I/O 멀티플렉싱

I/O 멀티플렉싱이란 개념은 그리 어렵지 않아.

멀티플렉싱이 뭔지부터 보자면,

> 하나의 통신 채널을 통해서 둘 이상의 데이터를 전송하는 것.

거기다가 I/O를 얹으면,

> 하나의 채널로 여러 read/write를 처리하는 것.

네트워크 쪽에서는 read/write 대신 recv/send일텐데,
결국 recv/send도 송/수신 버퍼에 read/write하는 작업이니까
어쨌든 read/write야.

기존의 thread-per-client 구조에서는
`recv()` 함수는 수신 버퍼에 읽을 데이터가 있을 때 까지 무작정 기다려야했고,
`send()` 함수도 송신 버퍼에 쓸 수 있을 때 까지 무작정 기다려야했어서
각 클라이언트마다 전용 송/수신 스레드를 별개로 둬야했지만,

I/O 멀티플렉싱을 하면
하나의 스레드만으로
그렇게 일일히 기다리지 않고 `recv()` / `send()`를 수행할 수 있어.

그리고, I/O 멀티플렉싱이 어떻게 동작하냐면
결국

> 한 스레드로 여러 소켓(파일 디스크립터)을 감시해서
> `recv()` 준비 / `send()` 준비 / 예외 발생 상태인 소켓을 따로 감지해서
> 해당 스레드만으로 `recv()` / `send()` / 예외 처리를 진행한다.

라고 할 수 있겠네.

그걸 가능하게 해주는 기본적인 함수가 뒤에 소개할 `select()` 함수라고 할 수 있겠고.

## 2. `select()`

`select()` 함수는

- 각 파일 디스크립터(소켓)를 감시하고
- 수신이 가능한지, 송신이 가능한지, 예외가 발생했는지를 알려주는 함수

라고 할 수 있겠어.

기본적으로 이 함수는 이렇게 동작해.

1. `select()` 함수의 매개변수를 지정한다.
    - 어떤 파일 디스크립터의 어떤 상태를 감시할지 설정한다.
    - 얼마나 많은 수의 파일 디스크립터를 감시할지 설정한다.
    - 타임아웃을 설정한다.
2. `select()` 함수를 호출한다.
3. 호출 결과를 확인한다.

### 2-1. `select()`의 매개변수와 반환값

일단 매개변수부터 보자.

```cpp
int select(int maxfd, 
           fd_set* readset, 
           fd_set* writeset, 
           fd_set* exceptset, 
           const struct timaval* timeout);
```

#### 2-1-1. `int` `max_fd`

(리눅스 기준 설명)
`int` `maxfd`에는 얼마나 많은 수의 파일 디스크립터를 감시할지를 넣어.
보통 `fd_set`에 등록된 파일 디스크립터의 수를 넣어.
모든 파일 디스크립터를 감시하겠다는거지.

보통은 파일 디스크립터의 값이 생성될 때마다 1씩 증가하기 때문에
가장 큰 파일 디스크립터의 값에 1을 더해서(파일 디스크립터의 번호는 0부터 시작함) `maxfd`로 전달해.

(윈도우 기준 설명)
윈도우에서는 파일 디스크립터의 값이 1씩 증가하지 않고 임의의 값으로 세팅되기 때문에
해당 필드는 안 쓰여.(무시됨)

#### 2-1-2. `fd_set`들

`fd_set`은 파일 디스크립터 집합(file descriptor set)으로 알면 돼.
근데 파일 디스크립터 집합이라기보단
**감시할 파일 디스크립터의 집합**이라고 할 수 있겠어.

(리눅스 기준 설명)
각 파일 디스크립터들은 1비트로 표현돼.
그리고 감시할지 말지에 따라 1이나 0으로 설정되지.(감시할거면 1)
그리고 각 인덱스는 해당 파일 디스크립터의 번호라고 보면 돼.

(윈도우 기준 설명)
앞서 설명했듯 소켓 핸들의 번호가 랜덤이라
`fd_set`은 
해당 `fd_set`의 소켓 핸들들의 수와 
소켓 핸들들의 배열로 구성되어있어.
감시할 소켓 핸들이 소켓들의 배열에 들어있지.

(공통 설명)
그리고 이게 비트 단위로 조작을 하거나
소켓 핸들을 넣었다 뺐다 해야하다보니까
조작하기가 힘들어서
별도의 매크로 함수들로 조작을 할 수 있게 되어있어.

(리눅스 기준, 윈도우도 `fd`에 소켓 핸들 그대로 넣으면 됨)

- `FD_ZERO(fd_set* fdset)` : `fdset`의 모든 비트를 0으로 초기화
- `FD_SET(int fd, fd_set* fdset)` : `fdset`에 `fd`의 정보를 등록함
- `FD_CLR(int fd, fd_set* fdset)` : `fdset`에 `fd`의 정보를 삭제함
- `FD_ISSET(int fd, fd_set* fdset)` : `fdset`에 `fd`가 있으면 양수를 반환

`fd_set*` `readset`에는 말 그대로 수신 버퍼를 읽을 수 있는 상태를 감지할 파일 디스크립터들을 설정해.
읽을 수 있는 상태를 감지할 파일 디스크립터를 `fd_set`에 등록하고 넣으면 돼.

`fd_set*` `writeset`에는 말 그대로 송신 버퍼에 쓸 수 있는 상태를 감지할 파일 디스크립터들을 설정해.
쓸 수 있는 상태를 감지할 파일 디스크립터를 `fd_set`에 등록하고 넣으면 돼.

`fd_set*` `exceptset`에는 말 그대로 예외를 감지할 파일 디스크립터들을 설정해.
예외를 감지할 파일 디스크립터를 `fd_set`에 등록하고 넣으면 돼.

#### 2-1-3. `const` `struct` `timeval*` `timeout`

이 구조체는 이렇게 생겼어.

```cpp
struct timeval {
    long tv_sec; // 초
    long tv_usec; // 밀리초
};
```

이건 해당 시간만큼이 지나면 바로 `select()`를 반환하게 하기 위해서 쓰는거야.
아무것도 감지되지 않는다면 `select()`는 무한히 블로킹될 수 있어.

그래서 '이 시간동안 아무것도 없으면 그냥 반환해라!' 하고 따로 타임아웃을 정해주는거야.

#### 2-1-4. 반환값

일단 `select()`에서 오류가 발생할 시 -1이 반환되고,
타임아웃에 의한 반환 시에는 0이 반환돼.

그리고 감지 대상으로 등록된 파일 디스크립터에 변화가 발생하면
변화가 발생한 파일 디스크립터의 수를 반환해.

그리고 여기서 중요한게,
변화가 감지된 파일 디스크립터를 어떻게 전달하냐인데,
이거는 입력받은 `readset` / `writeset` / `exceptset`을 재사용을 해서,
해당 구조체들에 기록하는 식으로 반환해.

(리눅스 기준 설명)
변화가 감지된 파일 디스크립터는 각 비트에 기록돼.
`FD_ISSET()`을 호출해서 특정 파일 디스크립터에 변화가 발생했는지를 파악할 수 있어

(윈도우 기준 설명)
변화가 감지된 소켓 핸들만 소켓 핸들의 배열에 남아있게 돼.
이미 변화가 발생한 소켓 핸들만 `fd_set`에 남아있기 때문에,
그냥 바로 배열을 순회하면 돼.

근데 이게 이렇게 갱신되기 때문에,
`select()`를 호출할 때 마다 계속 `fd_set`을 만들어줘야해.
(이게 `select()`의 핵심 불편한 점..)

### 2-2. `select()`의 단점

`select()`는 I/O 멀티플렉싱을 수행해주는 가장 기본적인 함수지만,
문제가 여러 개 있어.

- `select()` 호출 시마다 `fd_set`들이 덮어씌워져서 매번 `fd_set`을 따로 준비해야함
  - 그래서 `fd_set` 복사 비용이 큼..
- 소켓 래퍼와 함께 쓰기 어려움
  - `fd_set`은 원시 소켓 핸들(파일 디스크립터)만 받음
- 송신을 할 경우 구현이 어려움
  - `select()`의 write 변화 감지 조건이 **쓸 수 있는 상태이면 감지**라,
  송신 버퍼가 비어있기만 해도 `select()`가 반환됨..
  - 그래서 `SendQueue`같은걸 두고 `SendQueue`에 `Push()`되었을 때만
  `select()`를 호출하게 하려 해도, 그걸 전달하기가 어려움..
- `fd_set`에 등록 가능한 최대 소켓 개수가 있음.
  - 윈도우 기준기본값이 64개.
    - 물론 늘릴 수야 있지만,
    일일히 소켓 핸들을 저장해놓기 때문에
    `fd_set`이 커지면 복사 / 순회 비용이 폭발함.
  - 리눅스 기준 1024비트.
    - 어쨌든 1024개의 소켓 이상은 `fd_set`에 넣을 수가 없음.
- `select()`는 오로지 상태 감지만 해줄 뿐,
실제 읽기 / 쓰기는 별도로 수행해야함
- (윈도우 기준) 상태 변화 소켓을 찾을 때는 일일히 소켓 배열을 순회해서 찾아야함(병목)

그리고 나중에 볼 IOCP(I/O Completion Port) / epoll은 이런 문제들을 많이 해결해줘.
그래서 요즘은 죄다 IOCP만 쓰지..

## 3. 요약

1. I/O 멀티플렉싱은 하나의 채널(스레드)로 여러 개의 입/출력을 감시 / 관리하는 것이다.
    - 멀티플렉싱의 관점에서 요약하려고 저렇게 됐는데,
    어쨌든 적은 수의 스레드로 여러 파일 디스크립터의 입/출력을 감시 / 관리하는 것이다.
2. I/O 멀티플렉싱을 위한 파일 디스크립터 감시 함수로 `select()`가 있다.
    - 감시할 파일 디스크립터 개수, 감시할 파일 디스크립터 목록, 타임아웃을 설정한다.
    - 반환값으로는 
    에러인 경우 -1, 타임아웃인 경우 0, 성공한 경우 변화가 감지된 파일 디스크립터의 수를 반환한다.
      - 감지된 파일의 경우 인자로 받은 파일 디스크립터 목록에 정리해놓는다.
3. `select()` 함수는 다양한 단점 때문에 요즘에는 IOCP / epoll을 주로 쓴다.
